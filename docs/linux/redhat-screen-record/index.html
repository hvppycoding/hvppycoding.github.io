    Red Hat 화면 녹화 방법

    2025-08-11

    redhat 8.x os에서 간단히 화면 녹화(*.gif)로 하는 법

    Red Hat Enterprise Linux 8.x에서 간단히 화면을 GIF로 녹화하려면 아래 방법이 가장 간단합니다.
    (별도의 무거운 영상 편집 툴 없이 빠르게 GIF 결과를 얻는 방식입니다.)

    1. peek 사용 (GUI 기반)

    peek은 간단한 화면 녹화 도구로, 바로 GIF로 저장할 수 있습니다.

    설치

    sudo dnf install peek

    사용

    1. 터미널에서 peek 실행

    2. 원하는 영역 크기 조정

    3. Record as GIF 버튼 클릭

    4. 녹화 후 저장

    장점: 마우스로 영역 조절, 바로 GIF 저장
    단점: Wayland 환경에서는 X11로 전환 필요할 수 있음 (GDM에서 Xorg 세션 선택)

    2. byzanz-record 사용 (CLI 기반)

    터미널 환경에서 바로 GIF 녹화를 원할 때 유용합니다.

    설치

    sudo dnf install byzanz

    예시 명령

    byzanz-record --duration=10 --x=0 --y=0 --width=1280 --height=720 output.gif

    • --duration=10 : 녹화 시간(초)

    • --x, --y : 시작 좌표

    • --width, --height : 녹화 영역 크기

    • output.gif : 저장할 파일명

    장점: 간단, GUI 없이 서버/CLI 환경에서도 가능
    단점: 화면 영역 수치 직접 입력해야 함

    3. ffmpeg로 GIF 만들기

    먼저 mp4 등으로 녹화 후 GIF로 변환하는 방법입니다.
    이 방식은 화질 제어와 후처리가 편합니다.

    설치

    sudo dnf install ffmpeg

    녹화

    ffmpeg -video_size 1280x720 -framerate 25 -f x11grab -i :0.0 output.mp4

    GIF 변환

    ffmpeg -i output.mp4 -vf "fps=10,scale=800:-1:flags=lanczos" output.gif

    장점: 화질, 프레임, 크기 세밀하게 조정 가능
    단점: 두 번 작업해야 함 (녹화 → 변환)

    💡 추천 조합

    • 간단 & 빠름 → peek

    • 서버나 터미널 환경 → byzanz

    • 고품질 GIF → ffmpeg (녹화 후 변환)

    원하시면 제가 RHEL 8.x Wayland 환경에서 peek가 안 될 경우 우회 방법 도 같이 정리해 드릴 수 있습니다.
    그걸 포함하면 설치 후 바로 잘 쓸 수 있습니다.

    peek flatpak을 그냥 윈도우에서 다운 받을 순 없나?

    peek은 리눅스 전용 앱이라서 Windows에서 바로 실행할 수 있는 네이티브 버전 은 없습니다.
    Flatpak 패키지도 리눅스용 포맷이기 때문에 Windows에 그대로 다운로드해도 실행이 안 돼요.

    왜 안 되나?

    • Flatpak : 리눅스 앱 배포용 패키지 포맷

    • Windows : Flatpak 런타임 자체를 지원하지 않음

    • 즉, Windows에서 peek.flatpak 파일을 받아도 해석할 수 있는 런타임이 없어서 실행 불가

    대안 3가지

    1. WSL2(Windows Subsystem for Linux) + GUI

      • Windows 10/11에서 Ubuntu 같은 리눅스를 설치 후 peek을 실행

      • WSLg(Windows 11) 환경이면 GUI 앱도 바로 뜹니다.

      • 설치 예:

        sudo apt install peek
peek

    2. 가상 머신(VM) 사용

      • VirtualBox/VMware에 Fedora, Ubuntu 등 리눅스를 설치 → peek 설치

      • Windows에서도 VM 화면을 녹화 가능

    3. Windows 네이티브 대체 프로그램 사용

      • ScreenToGif → Windows에서 peek과 거의 비슷한 UX

      • 설치 후 바로 영역 지정 → GIF 저장 가능

      • Portable 버전도 있어 설치 없이 사용 가능

    만약 목적이 "윈도우에서 peek처럼 단순 GIF 녹화"라면
    ScreenToGif가 제일 비슷하고, 실행도 간편합니다.

    원하시면 제가 peek vs ScreenToGif 비교표 만들어서 어떤 게 더 적합한지 바로 보여드릴 수도 있습니다.

    윈도우에서 실행하려는 건 아니고 redhat os에서는 인터넷도 없고 sudo 권한도 없어서 다운만 받으려고

    아~ 그러면 상황이 이렇게군요.

    • 실행은 Red Hat 8.x 에서 할 거고

    • 그 환경은 인터넷 없음 + sudo 불가

    • 그래서 Windows에서 미리 peek Flatpak 파일을 받아서 옮기고 싶은 거군요.

    그 경우라면 가능합니다. 👍
    Windows에서 peek Flatpak 파일을 미리 받아서 USB나 다른 방법으로 RHEL 환경에 복사하면 돼요.

    1. Windows에서 peek Flatpak 파일 다운로드

    Flatpak 앱은 Flathub 에서 받을 수 있습니다.

    peek Flathub 페이지
    https://flathub.org/apps/com.uploadedlobster.peek

    여기서 직접 다운로드하려면:

    1. 페이지 하단의 Download Flatpak Bundle 버튼 클릭

    2. com.uploadedlobster.peek.flatpak 파일 저장

    2. RHEL 환경으로 옮기기

    • USB, 네트워크 공유, SCP 등 가능한 방법으로 RHEL로 복사

    3. RHEL에서 설치 (sudo 없이)

    만약 RHEL에 이미 Flatpak 런타임이 있고, 사용자 로컬 설치 가 가능하다면:

    flatpak install --user com.uploadedlobster.peek.flatpak
    • --user 옵션 → 관리자 권한 없이 현재 계정에만 설치

    4. 런타임 의존성 주의

    Peek Flatpak은 GNOME/GTK 런타임에 의존합니다.
    만약 해당 런타임이 RHEL 환경에 없으면, 그 런타임 .flatpak 파일도 같이 받아서 옮겨야 합니다.

    런타임 예:

    • org.gnome.Platform

    • org.freedesktop.Platform

    이것들도 Flathub에서 다운로드 가능
    예: https://flathub.org/apps/org.gnome.Platform

    📌 정리

    • Windows에서 com.uploadedlobster.peek.flatpak + 필요한 런타임 .flatpak 파일 미리 다운로드

    • RHEL로 옮겨서 flatpak install --user로 설치

    • sudo 없이 가능하지만, Flatpak 런타임이 기본 설치되어 있어야 함

    원하시면 제가 peek 실행에 필요한 모든 flatpak 파일 목록 + 다운로드 링크 를 정리해서 드릴 수 있습니다.

    flatpak도 없어

    아, 그러면 상황이 더 제한적이네요.
    정리하면 Red Hat 8.x에서

    • 인터넷 없음

    • sudo 권한 없음

    • flatpak도 없음

    즉, 시스템에 추가 패키지 설치 권한이 전혀 없는 상태군요.

    이 경우에는 peek 같은 패키지 기반 앱은 사실상 불가능 하고, 대신 단일 실행 파일(Portable Binary) 또는 스크립트 방식 으로 해결해야 합니다.

    1. Portable 실행 파일 방식

    • 리눅스에서 인터넷/설치 권한이 없는 경우, 정적 빌드(static build) 된 실행 파일을 Windows에서 미리 받아서 옮기면 실행 가능

    • 예: byzanz 또는 ffmpeg의 static binary

    • 장점: 설치 불필요, 복사 후 바로 실행 가능

    • 단점: peek처럼 GUI가 예쁘진 않음

    예) ffmpeg static build 다운로드 (Windows에서)

    • https://johnvansickle.com/ffmpeg/

    • ffmpeg-git-amd64-static.tar.xz 받아서 압축 풀고 RHEL로 복사

    • RHEL에서:

      ./ffmpeg -f x11grab -video_size 1280x720 -i :0.0 out.mp4
./ffmpeg -i out.mp4 out.gif

    2. 파이썬 기반 GIF 캡처

    • RHEL에 Python이 있다면, pyautogui, imageio 같은 라이브러리를 wheel 파일로 Windows에서 받아서 옮긴 후 pip로 로컬 설치 가능

    • GUI가 간단하고, 설치 권한 없이 --user 옵션으로 Python 패키지 설치 가능

    • 다만, Python 버전과 환경에 맞춰 wheel 파일을 준비해야 함

    3. 완전 무설치 방법

    • X11 환경이라면 xwd(X Window Dump) 같은 기본 툴이 이미 있을 수 있음

    • 일정 주기로 스크린샷을 찍고 imageio 같은 툴로 GIF로 합치는 방법 가능

    • 단점: 실시간 녹화처럼 부드럽진 않음

    💡 결론

    • 현재 환경에서는 peek처럼 Flatpak 앱을 그대로 옮겨 실행하는 건 불가능

    • 대신 ffmpeg static binary 가 제일 실용적

    • USB나 공유폴더로 파일 옮겨서 바로 실행 가능

    • GIF도 변환까지 한 번에 처리 가능

    특정 영역만 녹화할 수 있어?

    네, 가능합니다.
    ffmpeg static binary를 쓰면 RHEL 8.x에서도 인터넷·sudo 없이 특정 영역만 녹화 할 수 있습니다.

    1. 사전 준비 (Windows에서)

    1. ffmpeg static build 다운로드:
      https://johnvansickle.com/ffmpeg/
      → ffmpeg-release-amd64-static.tar.xz 받기

    2. 압축 풀기

    3. ffmpeg 실행 파일을 USB 등으로 RHEL로 옮기기

    2. RHEL에서 특정 영역 녹화

    예를 들어 좌표 (X=100, Y=200)에서 가로 800px × 세로 600px 영역을 10초 동안 녹화하려면:

    ./ffmpeg -f x11grab -video_size 800x600 -framerate 25 -i :0.0+100,200 -t 10 output.mp4

    • -video_size 800x600 → 캡처 영역 크기

    • :0.0+100,200 → X=100, Y=200 시작 좌표

    • -t 10 → 10초 녹화

    • -framerate 25 → 초당 25프레임

    3. GIF로 변환

    녹화가 끝나면 mp4 → gif 변환:

    ./ffmpeg -i output.mp4 -vf "fps=10,scale=800:-1:flags=lanczos" output.gif

    • fps=10 → 초당 10프레임 (GIF 파일 크기 줄임)

    • scale=800:-1 → 가로 크기 800, 세로는 비율 유지

    4. 좌표 찾기 팁

    좌표(X,Y)를 모를 경우:

    xdotool getmouselocation

    이 명령어로 마우스 위치를 알 수 있음
    (단, xdotool이 없으면 설치가 필요하지만, 설치 불가 환경이면 기본 X11 좌표는 감으로 맞춰야 함)

    💡 이 방식은 인터넷·sudo 없이 가능하고, peek처럼 GUI는 없지만
    원하는 영역만 깔끔하게 녹화할 수 있습니다.

    원하시면 제가 ffmpeg static binary로 "화면 영역 선택 → 녹화 → GIF 변환"을 한 줄 명령어로 끝내는 버전도 만들어 드릴 수 있습니다.
    그러면 한 번에 바로 GIF가 나옵니다.
    그걸 만들어 드릴까요?

    그냥 파이썬 패키지로 된 간단한 툴 있나 조사해줘

    파이썬 기반으로 특정 영역을 GIF로 녹화할 수 있는 간단한 도구 에 대해 찾아봤습니다. sudo 없이 사용자 계정만으로도 로컬에 설치할 수 있는 옵션 위주로 정리해드릴게요.

    Python 도구 추천

    1. pyautogui + imageio (스크립트 방식)

    가장 직접적이고 가벼운 방법입니다. 특정 영역을 반복 캡처해 GIF로 저장하는 단순한 스크립트로, 사용자가 녹화 영역 좌표를 지정해야 합니다.

    import time, numpy as np, pyautogui, imageio
t0 = time.time()
with imageio.get_writer('test.gif', mode='I', duration=0.1) as writer:
    while True:
        t1 = time.time()
        img = pyautogui.screenshot(region=(100,200,800,600))
        writer.append_data(np.array(img))
        if t1 - t0 > 5:  # 예: 5초 녹화
            break

    즉, 특정 영역(region)으로 녹화가 가능합니다. 다만, 용량은 다소 클 수 있어요. Stack Overflow

    2. mss 모듈 사용

    mss는 pyautogui보다 속도가 빠르고 효율적인 캡처를 지원합니다. 동일한 방식으로 region 캡처가 가능합니다. Stack Overflow

    3. PyPeek (Python GUI 도구)

    GUI 기반이며 Peek처럼 특정 영역을 마우스로 지정해 녹화할 수 있습니다. GIF 또는 MP4 형식으로 저장 가능하며 주석(annotation)도 가능하다는 장점이 있습니다.

    • 설치법: 
      pip install --user pypeek

    • 주요 특징:

      • 마우스로 영역 지정 가능

      • GIF, MP4 둘 다 지원

      • 간단한 주석 삽입 가능 (화살표, 텍스트 등) github.com+1

    요약 비교

    도구 유형 영역 지정 장점 제약사항
    pyautogui + imageio 스크립트 코드로 지정 간단, 설치가 쉽고 오프라인 환경에 적합 파일 크기 큼, 수동 스크립팅 필요
    mss 스크립트 코드로 지정 속도 향상, 효율적인 캡처 GUI 없음, 스크립트 작업 필요
    PyPeek GUI 도구 마우스로 지정 GUI 편의성, 주석 기능, GIF/MP4 지원 PySide6 필요, 설치된 의존성 확인 필요

    제안

    • 환경이 인터넷 및 sudo 권한 없이 Python만 있다면 :

      • pyautogui + imageio 방식은 단순하고 빠르게 적용 가능.

      • 조금 더 편한 GUI 기반이 필요하다면 Windows에서 pip download pypeek로 미리 패키지를 받아서 RHEL로 옮겨 설치하는 방법도 있습니다.

    원하시면 pyautogui + imageio 스크립트를 사용하는 완전 오프라인 가이드나, PyPeek 설치를 위한 패키지 준비 단계도 도와드릴 수 있어요. 어떻게 해 드릴까요?

    ffmpeg가 없다는데 내가 말한 redhat에 ffmpeg 설치하는 가장 쉬운 방법 알려줘

    지금 환경이

    • RHEL 8.x

    • 인터넷 없음

    • sudo 없음

    이라면, yum/dnf 같은 표준 설치 방식은 불가능하니, 결국 Windows에서 ffmpeg 실행 파일(정적 빌드)을 미리 받아서 RHEL로 옮기는 방법이 제일 쉽습니다.

    아래 순서대로 하면 됩니다.

    1. Windows에서 ffmpeg 정적 빌드 다운로드

    1. 브라우저로 https://johnvansickle.com/ffmpeg/ 접속

    2. "Static Linux 64-bit build" 링크 클릭
      예: ffmpeg-release-amd64-static.tar.xz

    3. 다운로드 완료 후 압축을 풉니다.

      • 압축 해제 시 ffmpeg, ffprobe 실행 파일이 들어있는 폴더가 나옴

    2. RHEL로 파일 옮기기

    • USB, 외장하드, 또는 네트워크 전송(SCP, SFTP 등)으로 ffmpeg 실행 파일이 들어있는 폴더를 그대로 RHEL 홈 디렉토리로 복사

    3. RHEL에서 실행 준비

    cd ~/ffmpeg-git-YYYYMMDD-amd64-static   # 옮겨온 폴더로 이동
chmod +x ffmpeg

    4. ffmpeg 사용

    폴더 안에서 직접 실행:

    ./ffmpeg -version

    예: 화면 녹화 (특정 영역)

    ./ffmpeg -f x11grab -video_size 800x600 -i :0.0+100,200 -t 5 out.mp4

    5. (선택) 경로 추가

    매번 경로를 입력하지 않으려면 홈 디렉토리에 bin 폴더 를 만들어서 넣고 PATH에 추가:

    mkdir -p ~/bin
cp ffmpeg ~/bin
echo 'export PATH=$HOME/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

    이제 터미널 어디서든 ffmpeg 명령 가능.

    📌 이 방법의 장점:

    • sudo 불필요

    • 인터넷 불필요

    • 옮기기만 하면 바로 실행 가능

    pypeek에서 만든 영상을 일정 배속으로 바꾸고 싶으면 어떻게 해야할까?

    pypeek은 내부적으로 PySide6 기반 GUI로 화면을 캡처하지만, 결과물은 결국 MP4 나 GIF 같은 일반 영상 파일이라서,
    배속 조정은 ffmpeg 로 처리하는 게 가장 간단하고 품질 저하도 최소입니다.

    1. MP4 영상의 재생 속도 변경

    예를 들어 2배속으로 바꾸려면:

    ffmpeg -i input.mp4 -filter:v "setpts=0.5*PTS" output.mp4

    • 0.5*PTS → 2배속 (시간 절반)

    • 0.25 → 4배속, 2.0 → 0.5배속(느리게)

    2. GIF의 재생 속도 변경

    GIF는 -filter_complex를 쓰면 됩니다.

    2배속 예시

    ffmpeg -i input.gif -filter_complex "[0:v]setpts=0.5*PTS[v]" -map "[v]" output.gif

    다만 GIF는 프레임 딜레이 값을 직접 바꾸는 게 더 정확할 때가 있어요:

    ffmpeg -i input.gif -filter_complex "fps=10,setpts=0.5*PTS" output.gif
    • fps=10은 기존 프레임 속도 유지 또는 변경 가능

    3. 배속과 동시에 GIF 변환

    만약 pypeek 결과물이 MP4이고, 바로 빠르게 GIF로 만들고 싶으면:

    ffmpeg -i input.mp4 -filter_complex "setpts=0.5*PTS,fps=10,scale=800:-1:flags=lanczos" output.gif

    • setpts=0.5*PTS → 2배속

    • fps=10 → GIF 프레임 수 제한 (파일 크기 감소)

    • scale=800:-1 → 가로 800px, 세로는 비율 유지

    📌 정리

    • MP4라면 → setpts로 속도 조절

    • GIF라면 → setpts + fps로 조절

    • 속도 변경 후 화질/프레임 크기도 같이 조절 가능

    원하시면 제가 "pypeek → 속도 변경 → GIF 변환"을 한 줄로 끝내는 명령어를 만들어 드릴 수 있습니다.
    그렇게 하면 배속 조정과 변환을 한 번에 할 수 있어요.
    그 버전 만들어 드릴까요?

    PTS가 뭐야?

    PTS는 Presentation TimeStamp(표시 시간 스탬프)의 약자입니다.

    영상에서 각 프레임은 "언제 화면에 보여줄지"라는 시간이 붙어 있는데, 그게 PTS입니다.

    • setpts 필터는 이 값을 조정해서 재생 속도를 바꾸는 원리입니다.

    예시로 이해

    영상의 프레임들이 원래 이렇게 있다고 해봅시다:

    프레임 번호 원래 PTS(초)
    1 0.00
    2 0.04
    3 0.08
    4 0.12

    • setpts=PTS → 그대로 재생 (속도 변화 없음)

    • setpts=0.5*PTS → PTS를 절반으로 줄임 → 시간 간격이 절반 → 2배속

    • setpts=2.0*PTS → PTS를 2배로 늘림 → 시간 간격이 두 배 → 0.5배속 (느리게)

    왜 FPS 말고 PTS를 조정하나?

    • FPS(Frame Per Second)는 "초당 몇 장"을 의미하고, PTS는 "그 장을 언제 보여줄지"를 의미합니다.

    • 단순히 FPS만 바꾸면 프레임 수는 변하지만 재생 시간은 변하지 않습니다.

    • 속도 자체를 바꾸려면 PTS를 수정해야 합니다.

    💡 정리:

    • PTS = 각 프레임의 "표시 시간"

    • setpts 필터 = 표시 시간을 수식으로 바꿔서 속도를 조절하는 도구

    • 0.5*PTS → 빠르게, 2.0*PTS → 느리게

    원하시면 제가 PTS 조정이 어떻게 실제 영상 시간에 반영되는지 시각화된 그림을 하나 그려서 보여드릴 수도 있습니다.

    <!doctype html>

<head>
  <meta charset="utf-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />

    .box { max-width: 480px; }
    img { width: 100%; height: auto; display: block; }

    • width/height 속성 을 넣으면 CLS(레이아웃 흔들림) 방지.

    • loading="lazy"는 아래쪽 이미지에만 권장(첫 뷰포트라면 빼기).

    • 체크무늬 배경으로 투명 경계/프린지 있는지 한눈에 확인 가능.

    3) 메타데이터·재생정보 점검 (ffprobe)

    이미 ffmpeg를 쓰고 있으니, ffprobe 로 길이/프레임 등을 수치로 확인하세요.

    # 기본 정보
./ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,avg_frame_rate,width,height \
  -show_entries format=duration,size -of json output.gif

# 평균 프레임레이트만 보고 싶다면
./ffprobe -v error -select_streams v:0 -show_entries stream=avg_frame_rate -of default=nk=1:nw=1 output.gif
    • 예상 FPS·해상도·길이(초)·파일 크기가 의도와 맞는지 체크.

    4) 웹 퍼포먼스 관점 최소 체크리스트

    • 파일 크기 : 가능하면 2–3 MB 이내(짧을수록 좋음).

    • 해상도 : 실제 표시 크기보다 과도하게 크지 않게.

    • FPS : 8–12 fps면 대부분의 UI 데모에 충분.

    • 팔레트 최적화 : ffmpeg의 palettegen/paletteuse를 사용하면 색 품질/용량 균형이 좋아집니다.

    # 고품질 GIF 최적화 파이프라인(권장)
./ffmpeg -i input.mp4 -vf "fps=10,scale=800:-1:flags=lanczos,palettegen=stats_mode=single" -y palette.png
./ffmpeg -i input.mp4 -i palette.png -lavfi "fps=10,scale=800:-1:flags=lanczos,paletteuse=dither=bayer:bayer_scale=5" -y output.gif

    5) 대안 포맷 고려(필요 시)

    • WebP 애니메이션 또는 MP4/WebM 가 GIF보다 훨씬 가볍고 부드럽습니다.

    • 최종이 반드시 GIF가 아니라면:

      • <video autoplay muted loop playsinline>로 MP4/WebM 삽입 + GIF 폴백

      • 또는 <picture>로 WebP 먼저, GIF 폴백 제공

    <video autoplay muted loop playsinline width="480" height="270" poster="poster.jpg">

    pypeek -> MP4 + ffmpeg 변환 시 속도 조절 스텝은 어떻게 어디에 넣는게 좋아?

    pypeek → MP4 → ffmpeg 변환할 때 속도 조절 은 변환 단계에서 한 번에 넣는 게 제일 깔끔합니다.
    이유는:

    • pypeek 은 녹화 속도를 그대로 저장하므로, 속도 변경을 미리 하지 않아도 원본 품질 보존

    • ffmpeg 에서 setpts 필터로 영상 속도 변경과 동시에 WebP/GIF 변환, 크기 조절, 프레임 수 조절 을 한 번에 가능

    • 중간 단계 없이 처리하면 재인코딩 횟수가 줄어 화질 손상 최소화

    변환 + 속도 조절을 한 번에

    예: pypeek이 만든 record.mp4를 2배속 WebP로 변환

    ffmpeg -i record.mp4 -filter_complex "setpts=0.5*PTS,fps=12,scale=800:-1:flags=lanczos" output.webp

    • setpts=0.5*PTS → 2배속 (0.5는 시간 절반)

    • fps=12 → 초당 12프레임 (용량 줄이기)

    • scale=800:-1 → 가로 800px, 세로 자동 비율

    • flags=lanczos → 고품질 리사이즈

    GIF 변환도 동일

    ffmpeg -i record.mp4 -filter_complex "setpts=0.5*PTS,fps=12,scale=800:-1:flags=lanczos" output.gif

      • 해상도 조정 (scale)

      • 프레임 수 조절 (fps)

    그럼 pypeek → MP4 → WebP + GIF 변환을
    속도 변경, 크기 조정, 프레임 수 제한 까지 한 번에 처리하는 명령 세트를 드릴게요.

    한 번에 WebP + GIF 변환 (2배속 예시)

    # 변환 설정
SPEED=0.5         # setpts 배속 계수 (0.5 = 2배속, 2.0 = 0.5배속)
FPS=12            # 출력 프레임 수
WIDTH=800         # 출력 가로 크기

# 원본 MP4 → WebP
ffmpeg -i record.mp4 \
  -filter_complex "setpts=${SPEED}*PTS,fps=${FPS},scale=${WIDTH}:-1:flags=lanczos" \
  -loop 0 output.webp

# 원본 MP4 → GIF (팔레트 최적화 포함, 고품질)
ffmpeg -i record.mp4 \
  -filter_complex "setpts=${SPEED}*PTS,fps=${FPS},scale=${WIDTH}:-1:flags=lanczos,palettegen" \
  -y palette.png

ffmpeg -i record.mp4 -i palette.png \
  -filter_complex "setpts=${SPEED}*PTS,fps=${FPS},scale=${WIDTH}:-1:flags=lanczos,paletteuse=dither=bayer:bayer_scale=5" \
  -y output.gif

    설명

    • SPEED

      • 0.5 → 2배속 (시간 절반)

      • 1.0 → 원속도

      • 2.0 → 0.5배속 (느리게)

    • FPS

      • 보통 8~15fps면 용량과 부드러움 균형 좋음

    • WIDTH

      • 가로 픽셀 수 (세로는 비율 자동 맞춤)

    • -loop 0 → WebP 무한 반복

    💡 이 스크립트를 .sh 파일로 저장해두면
    ./convert.sh record.mp4 처럼 한 번에 WebP랑 GIF를 다 뽑을 수 있습니다.

    원하면 제가 여기에 출력 파일 크기를 자동으로 체크해서 FPS나 WIDTH를 조정해주는 버전 도 만들어 드릴 수 있습니다.
    그러면 최종 GIF/WebP 용량이 예를 들어 2MB 이하로 자동 맞춰집니다.

    pypeek 실행 시, Falling back to using scrrens root_visual. 이라는 메시지가 뜨는데 이건 뭘까?

    그 메시지는 pypeek 내부에서 화면 캡처를 위해 Qt/PySide6 의 X11 관련 API를 호출할 때,
    사용하려던 비주얼(visual)을 못 찾고 기본 root_visual로 대체한다 는 뜻입니다.

    원인

    • Visual : X11에서 "픽셀 포맷"이나 "컬러 표현 방식"을 정의하는 구조체

    • 보통은 화면과 같은 visual을 사용하지만, 드라이버나 창 관리자 설정에 따라 원하는 visual을 얻지 못하면 Qt가 fallback 처리

    • pypeek에서 쓰는 PySide6 → QtGui → Xlib 경로에서 "root_visual"로 바꾼 것

    즉,

    "원래 의도한 visual 포맷을 못 찾았으니, 루트 윈도우의 visual을 대신 쓸게요"
    라는 의미고, 기능적으로 큰 문제는 없지만 일부 색상 정확도나 투명 처리에서 미세한 차이가 날 수 있습니다.

    주로 나타나는 상황

    • 원격 X11 세션 (ssh -X / VNC / Xpra 등)

    • 가상머신의 가속 미지원 X 서버

    • Wayland 에서 XWayland로 동작할 때

    • 비표준 컬러 깊이(8-bit, 30-bit 등) 사용 시

    해결 방법 (가능할 때)

    1. 로컬 X11 세션 에서 실행

      • GDM 로그인 시 "GNOME on Xorg" 선택

    2. 컬러 깊이 표준화

      • Xorg 설정에서 24-bit(8bit/channel)로 변경

    3. Qt 환경변수 설정
      실행 전:

      export QT_X11_NO_MITSHM=1
export QT_GRAPHICSSYSTEM=native

    첫 번째는 공유 메모리 관련 문제 방지, 두 번째는 기본 native 렌더러 사용

    1. PySide6 / Qt 버전 업데이트

      • pypeek이 사용하는 Qt 버전이 오래되면 visual 처리 버그가 있을 수 있음

    💡 중요

    • 메시지는 경고 수준 이며, 대부분의 경우 녹화 품질에 치명적인 문제는 없음

    • 단, 색상이 이상하거나 투명 배경이 깨지면 root_visual fallback이 원인일 가능성이 높음

    원하시면 제가 pypeek 실행 시 이 경고 메시지를 없애는 방법 과
    투명/컬러 품질 검증 체크리스트 까지 같이 드릴 수 있습니다.
    그걸 정리해 드릴까요?

    width는 별로 안건드리고 싶은걸

    좋아요, 그러면 pypeek → MP4 → WebP/GIF 변환에서 width는 원본 해상도 유지 로 두면 됩니다.

    ffmpeg에서는 scale=-1:-1처럼 둘 다 -1 로 설정하면 크기 변경을 전혀 안 합니다.
    다만 WebP나 GIF 최적화를 위해 짝수 픽셀 이 아닌 경우 ffmpeg가 자동으로 맞춰 줄 수 있습니다.

    변환 예시 (원본 해상도 유지 + 속도 변경)

    # 배속 계수 (0.5 = 2배속, 2.0 = 0.5배속)
SPEED=0.5
FPS=12

# WebP
ffmpeg -i record.mp4 \
  -filter_complex "setpts=${SPEED}*PTS,fps=${FPS},scale=-1:-1:flags=lanczos" \
  -loop 0 output.webp

# GIF (팔레트 최적화 포함)
ffmpeg -i record.mp4 \
  -filter_complex "setpts=${SPEED}*PTS,fps=${FPS},scale=-1:-1:flags=lanczos,palettegen" \
  -y palette.png

ffmpeg -i record.mp4 -i palette.png \
  -filter_complex "setpts=${SPEED}*PTS,fps=${FPS},scale=-1:-1:flags=lanczos,paletteuse=dither=bayer:bayer_scale=5" \
  -y output.gif

    포인트

    • scale=-1:-1 → 해상도 변경 없이 처리

    • FPS만 조정해도 파일 크기와 부드러움 균형 조절 가능

    • SPEED에서 원하는 재생 속도를 직접 지정

    원하시면 제가 여기에 원본 해상도를 유지하되, FPS만 조정해 목표 파일 크기(MB) 이하로 자동 맞춰주는 버전 도 만들어 드릴 수 있습니다.
    그렇게 하면 width는 안 건드리면서도 용량 관리를 할 수 있습니다.
    그 버전으로 만들어 드릴까요?

    PTS를 조정하면 fps도 바뀌어?

    아니요, setpts로 PTS(프레임 표시 시간)만 조정하면 FPS(초당 프레임 수)는 변하지 않습니다.

    왜 그런가?

    • PTS 는 "각 프레임을 언제 보여줄지"를 정하는 시간 정보 입니다.

    • FPS 는 "재생 중 초당 몇 장을 보여줄지"라는 빈도 정보 입니다.

    • setpts는 프레임의 개수나 간격은 바꾸지 않고, 시간 축만 늘리거나 줄입니다.

    예시

    원본 영상:

    • FPS: 30

    • 길이: 10초 → 총 프레임 300장

    setpts=0.5*PTS 적용 시:

    • 프레임 수: 그대로 300장

    • 길이: 5초로 줄어듦

    • FPS: 300장 ÷ 5초 = 60fps (즉, 실질 재생 프레임 빈도 증가)

    그래서 실무에서는…

    • setpts로 배속 조정 → FPS가 변한 듯 보이지만, 실제로는 시간이 줄어서 FPS 계산값이 바뀌는 것

    • GIF나 WebP 변환 시 fps= 필터로 원하는 프레임 속도를 별도로 지정하는 게 안전

    • 예: 2배속 + 12fps로 변환

    ffmpeg -i input.mp4 -filter_complex "setpts=0.5*PTS,fps=12" output.gif

    💡 요약

    • setpts는 시간 축만 변경

    • fps는 실제 프레임 수를 줄이거나 늘려 재생 빈도 조절

    • 배속 조정과 FPS 조정은 별개 작업 이라 두 필터를 함께 쓰는 게 가장 깔끔

    원하시면 제가 배속 + FPS 최적화 를 한 줄로 깔끔하게 처리하는 ffmpeg 변환 패턴을 만들어 드릴 수 있습니다.
    그러면 배속과 파일 크기 제어를 동시에 할 수 있습니다.
    그렇게 해 드릴까요?

    무슨 말인지 모르겠어. 60fps가 된걸 다시 리샘플링해서 12fps로 바꾼다는 뜻?

    네, 맞아요. 👍
    제가 쉽게 단계별로 풀어 설명해 드릴게요.

    1. setpts만 쓰면 생기는 일

    원본 예시:

    • FPS: 30

    • 길이: 10초

    • 총 프레임 수: 300장

    setpts=0.5*PTS (2배속) 적용하면:

    • 프레임 수: 300장 그대로

    • 길이: 5초

    • 계산된 FPS: 300장 ÷ 5초 = 60fps

    즉, ffmpeg 입장에서는 "이 영상은 초당 60장을 보여주는 영상"이 되어버립니다.

    2. 그대로 GIF나 WebP 변환하면?

    GIF나 WebP는 초당 60장을 유지하려 하니까:

    • 파일 용량이 커지고

    • 사람이 보기엔 거의 차이가 없는 프레임이 많아짐

    3. 그래서 fps 필터로 리샘플링

    여기서 fps=12를 같이 쓰면:

    • 초당 60장짜리 영상을 → 초당 12장만 남기고 나머지 프레임은 버림

    • 결과: 용량 감소 + 변환 속도 빨라짐

    ffmpeg -i input.mp4 \
  -filter_complex "setpts=0.5*PTS,fps=12,scale=800:-1:flags=lanczos" \
  output.gif

    ✅ 정리

    • setpts → 시간 조절 (배속/느리게)

    • fps → 프레임 수 조절 (용량·부드러움 제어)

    • 둘을 같이 쓰면:
      setpts로 먼저 60fps처럼 된 걸 → fps로 필요한 만큼만 남김 (예: 12fps)

    원하면 제가 이 과정이 어떻게 변하는지 프레임 타임라인 그림으로 보여드릴 수 있어요.
    그림 보면 바로 감이 올 거예요.
    그걸 그려 드릴까요?

    최종적으로 10 fps 영상을 만들거야. 근데 0.75를 적용해서 1.5배속으로 보여줄거야. 처음에 몇 fps로 영상을 찍는게 좋을까

    좋아요, 그럼 계산을 차근차근 해볼게요.

    1. 목표 조건

    • 최종 영상: 10 fps

    • 최종 속도: 1.5배속 (setpts=0.75*PTS)

    2. 배속이 FPS에 주는 영향

    원본 FPS = 원본 프레임 수 ÷ 원본 길이

    setpts=0.75*PTS 적용 시:

    • 프레임 수는 변하지 않음

    • 길이는 0.75배로 짧아짐

    • 계산된 FPS는 원본의 1 ÷ 0.75 = 1.333... 배로 증가

    즉, 원본 FPS × 1.333… = 배속 적용 후 FPS

    3. 리샘플링(fps 필터)으로 최종 10fps를 맞출 것

    • 최종 10fps이므로, 배속 적용 후 FPS가 10보다 크면 다운샘플링 가능

    • 원본 FPS가 너무 낮으면, 배속 적용 후 최종 10fps 만들 때 부드러움 손실이 큼

    4. 추천 원본 FPS 계산

    조건:

    원본_FPS × 1.333... ≥ 10

    즉,

    원본_FPS ≥ 10 × 0.75
원본_FPS ≥ 7.5

    하지만 실무에서는 안전 여유 를 줘야 하므로:

    • 최소 2배 여유 → 원본 FPS 20 정도 추천

    • 그래야 배속·리샘플링 후에도 모션 부드럽고, 중간 프레임 손실 적음

    5. 예시 시뮬레이션

    • 원본 촬영: 20 fps

    • 배속 적용: 20 × 1.333... ≈ 26.6 fps

    • 리샘플링: fps=10으로 다운 → 부드러움 유지 + 용량 절감

    💡 최종 답

    원본은 최소 15fps , 가능하면 20fps 이상 으로 촬영 후, 배속과 fps=10 리샘플링을 적용하는 게 가장 자연스럽습니다.

    원하시면 제가 이걸 한 번에 처리하는 ffmpeg 명령(배속 + 최종 fps=10 + 용량 최적화) 만들어 드릴게요.
    그럼 pypeek 출력만 넣으면 바로 끝납니다.
    그걸 만들어 드릴까요?
