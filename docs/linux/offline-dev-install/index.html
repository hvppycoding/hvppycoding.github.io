    오프라인 환경 개발 세팅

    2025-08-27

    redhat 8.x os에 개발 환경 세팅하고자 해. - sudo 권한 없음 - 오프라인 환경(파일 받아서 옮기는 것은 가능) - 쉘: tcsh 1. gcc 빌드(이 후 빌드에서 이 gcc 설치) 2. 최신 sqlite3 빌드 3. python 3.11 빌드(2에서 설치한 sqlite3에 대한 빌드) 설치 디렉토리: $RELEASE 라고 가정 설치용 소스코드 위치: ${RELEASE}/installers 에 저장할 것 설치위치 예시: ${RELEASE}/toolchains/gcc/13.4.0

    좋아요. 조건(무 sudo, 오프라인, tcsh, 설치 경로 규칙)에 맞춰 “한 번에 복붙 가능한” 단계별 빌드 절차를 정리했어요.
    아래 순서대로 진행하면 됩니다.

    • 설치 루트: $RELEASE (사용자 지정 경로)

    • 소스 보관: ${RELEASE}/installers

    • 예시 설치 경로: GCC → ${RELEASE}/toolchains/gcc/13.4.0 (요청하신 예시 그대로)

    • 셸: tcsh

    0) 준비: 디렉터리와 기본 환경

    tcsh

# 원하는 경로로 바꾸세요
setenv RELEASE /path/to/release

# 필수 디렉터리
mkdir -p ${RELEASE}/installers
mkdir -p ${RELEASE}/build
mkdir -p ${RELEASE}/toolchains

# (선택) 병렬 빌드 스레드 수
set njobs=`/usr/bin/nproc >& /dev/null ; if ($? != 0) echo 2`
if ("$njobs" == "") set njobs=2

    tcsh는 새 바이너리를 PATH에 추가한 뒤 rehash를 해야 명령어를 인식합니다.

    1) 오프라인으로 가져올 소스 목록(파일명/버전/무결성)

    다음 파일들을 외부에서 받아 ${RELEASE}/installers 에 옮깁니다.

    A. GCC 13.4.0 (공식 릴리스)

    • gcc-13.4.0.tar.xz (또는 .tar.gz)

    • 동일 디렉토리의 sha512.sum 파일도 함께 받으면 sha512sum -c로 검증 가능. gcc.gnu.orgftp.tsukuba.wide.ad.jp

    GCC 필수 서브모듈(소스 트리 내 포함 빌드 방식 사용)

    • GMP 6.3.0 — 원본: gmp-6.3.0.tar.xz (SHA256: bd2966e6d277f79328e894a5a9f3ba3fbf2ed2be81def5f48623e30c23fb1572) ftp.gnu.orgLaunchpad

    • MPFR 4.2.1 — mpfr-4.2.1.tar.xz (SHA256: 277807353a6726978996945af13e52829e3abd7a9a5b7fb2793894e18f1fcbb2) gmplib.org

    • MPC 1.3.1 — mpc-1.3.1.tar.gz (SHA256: ab642492f5cf882b74aa0cb730cd410a81edcdbec895183ce930e706c1c759b8) fossies.org
      (ISL은 선택 사항입니다. 없으면 Graphite 최적화만 비활성화됩니다. 필요 시isl_0.26.orig.tar.xz/SHA256: a0b5cb06d24f9fa9e77b55fabbe9a3c94a336190345c2555f9915bb38e976504) Launchpad

    B. 최신 SQLite3 (2025-07-30 현재 최신: 3.50.4)

    • sqlite-autoconf-3500400.tar.gz

      • 공식 다운로드 페이지(파일명·SHA3-256 해시 제공) SQLite

      • 3.50.4 릴리스 노트/버전 타임라인 확인용 참조 SQLite+1

    SHA3 검증 이 권장됩니다. RHEL 8의 openssl로도 가능: openssl dgst -sha3-256 FILENAME.

    C. Python 3.11 (최신 보안 릴리스: 3.11.13, 2025-06-03)

    • Python-3.11.13.tgz 또는 Python-3.11.13.tar.xz (소스만 배포) Python.org

    2) GCC 13.4.0 빌드(무 sudo, in-tree prerequisites)

    설치 경로: ${RELEASE}/toolchains/gcc/13.4.0

    tcsh

# 2-1) 압축 해제
cd ${RELEASE}/installers
tar -xf gcc-13.4.0.tar.xz

# (선택) 무결성 확인: sha512.sum 파일이 같은 디렉터리에 있을 때
# sha512sum -c sha512.sum |& grep gcc-13.4.0

# 2-2) GCC 소스 트리 아래에 필수 라이브러리 풀기
tar -xf gmp-6.3.0.tar.xz
tar -xf mpfr-4.2.1.tar.xz
tar -xf mpc-1.3.1.tar.gz
# (선택) tar -xf isl_0.26.orig.tar.xz

# 이름을 gcc 소스 내부의 디렉터리로 맞춰 배치
mv gmp-6.3.0   gcc-13.4.0/gmp
mv mpfr-4.2.1  gcc-13.4.0/mpfr
mv mpc-1.3.1   gcc-13.4.0/mpc
# (선택) mv isl-0.26 gcc-13.4.0/isl

# 2-3) out-of-source 빌드 디렉터리
mkdir -p ${RELEASE}/build/gcc-13.4.0
cd ${RELEASE}/build/gcc-13.4.0

# 2-4) configure
${RELEASE}/installers/gcc-13.4.0/configure \
  --prefix=${RELEASE}/toolchains/gcc/13.4.0 \
  --disable-multilib \
  --enable-languages=c,c++ \
  --enable-bootstrap

# 2-5) 컴파일 및 설치
make -j${njobs}
make install

# 2-6) 새 GCC 우선 사용
setenv GCC_PREFIX ${RELEASE}/toolchains/gcc/13.4.0
setenv PATH ${GCC_PREFIX}/bin:${PATH}
setenv LD_LIBRARY_PATH ${GCC_PREFIX}/lib64:${GCC_PREFIX}/lib:${LD_LIBRARY_PATH}
rehash

# 확인
gcc --version

    위 방식은 GMP/MPFR/MPC를 GCC가 함께 빌드 하도록 하는 공식적인 쉬운 경로입니다(별도 설치/링크 불필요). gcc.gnu.org

    3) 최신 SQLite3 빌드

    설치 경로(예시): ${RELEASE}/packages/sqlite/3.50.4

    tcsh

setenv SQLITE_VER 3.50.4
setenv SQLITE_SRC sqlite-autoconf-3500400
setenv SQLITE_PREFIX ${RELEASE}/packages/sqlite/${SQLITE_VER}

cd ${RELEASE}/installers
tar -xf ${SQLITE_SRC}.tar.gz
cd ${RELEASE}/build
mkdir -p sqlite-${SQLITE_VER} && cd sqlite-${SQLITE_VER}

# SQLite는 C만 필요. 새 gcc 사용.
setenv CC gcc

# rpath를 심어놓으면 나중에 LD_LIBRARY_PATH 없어도 찾기 쉬움
setenv CFLAGS "-O2 -fPIC"
setenv LDFLAGS "-Wl,-rpath,${SQLITE_PREFIX}/lib"

${RELEASE}/installers/${SQLITE_SRC}/configure \
  --prefix=${SQLITE_PREFIX} \
  --enable-shared

make -j${njobs}
make install
rehash

# 확인
${SQLITE_PREFIX}/bin/sqlite3 -version

    최신 버전 및 해당 tarball 이름은 공식 다운로드/릴리스 페이지에서 확인했습니다. (3.50.4, 2025-07-30) SQLite+2

    4) Python 3.11 빌드(새 SQLite 사용)

    설치 경로(예시): ${RELEASE}/packages/python/3.11.13

    포인트

    • _sqlite3 모듈을 켜려면 컴파일 시점에 SQLite의 headers/libs가 보여야 합니다.

    • 오프라인이라도 ensurepip로 기본 pip는 포함됩니다(네트워크 액세스는 별개).

    • OpenSSL, zlib 등의 추가 라이브러리가 시스템에 없으면 해당 모듈이 비활성화될 수 있습니다. 이번 요구사항은 SQLite 연동이므로 필수는 아닙니다.

    tcsh

setenv PY_VER 3.11.13
setenv PY_PREFIX ${RELEASE}/packages/python/${PY_VER}

cd ${RELEASE}/installers
tar -xf Python-3.11.13.tar.xz

cd ${RELEASE}/build
mkdir -p python-${PY_VER} && cd python-${PY_VER}

# 새 GCC와 새 SQLite를 가리키도록 플래그 지정
setenv CC gcc
setenv CXX g++
setenv CPPFLAGS "-I${SQLITE_PREFIX}/include"
# Python 실행 시에도 libsqlite3을 찾도록 rpath 포함
setenv LDFLAGS "-L${SQLITE_PREFIX}/lib -Wl,-rpath,${SQLITE_PREFIX}/lib"

${RELEASE}/installers/Python-3.11.13/configure \
  --prefix=${PY_PREFIX} \
  --enable-shared \
  --with-ensurepip=install

make -j${njobs}
make install
rehash

# 확인: Python과 sqlite3 모듈이 새 SQLite에 링크되었는지
${PY_PREFIX}/bin/python3.11 -c 'import sys,sqlite3; print(sys.version); print("sqlite:", sqlite3.sqlite_version)'

    3.11 계열의 최신 보안 릴리스는 3.11.13 (2025-06-03) 입니다(3.11은 현재 보안 수정만, 소스 배포만 제공). Python.orgPython Developer's Guide

    5) 매번 쓰기 편하도록 env 스크립트(csh) 만들기

    tcsh

setenv ENVHOME ${RELEASE}/env
mkdir -p ${ENVHOME}

cat > ${ENVHOME}/activate.csh << 'EOF'
# source /path/to/release/env/activate.csh
if ( $?RELEASE == 0 ) then
  echo "Please setenv RELEASE first."
  exit 1
endif

setenv GCC_PREFIX      ${RELEASE}/toolchains/gcc/13.4.0
setenv SQLITE_PREFIX   ${RELEASE}/packages/sqlite/3.50.4
setenv PY_PREFIX       ${RELEASE}/packages/python/3.11.13

setenv PATH            ${PY_PREFIX}/bin:${SQLITE_PREFIX}/bin:${GCC_PREFIX}/bin:${PATH}
setenv LD_LIBRARY_PATH ${PY_PREFIX}/lib:${SQLITE_PREFIX}/lib:${GCC_PREFIX}/lib64:${GCC_PREFIX}/lib:${LD_LIBRARY_PATH}
setenv PKG_CONFIG_PATH ${SQLITE_PREFIX}/lib/pkgconfig:${PKG_CONFIG_PATH}

rehash
echo "[env] GCC:      `gcc --version | head -1`"
echo "[env] SQLite3:  `sqlite3 -version | head -1`"
echo "[env] Python:   `python3.11 --version`"
EOF

# 사용법
# setenv RELEASE /path/to/release
# source ${RELEASE}/env/activate.csh

    트러블슈팅(필요 시)

    • make 도중 texinfo 경고/문서 생성 실패: 무시해도 GCC 자체 빌드는 진행됩니다.

    • 링커가 libstdc++/libgcc_s를 못 찾음 : LD_LIBRARY_PATH에 ${GCC_PREFIX}/lib64:${GCC_PREFIX}/lib가 포함돼야 합니다. 위 env 스크립트로 해결.

    • Python에서_sqlite3가 import 안 됨:

      1. configure 때 CPPFLAGS/LDFLAGS가 빠졌거나,

      2. 런타임에 새 libsqlite3.so를 못 찾는 경우입니다.
        python3.11 -c 'import sys; import ctypes; print(ctypes.util.find_library("sqlite3"))'로 점검하고, rpath/LD_LIBRARY_PATH를 확인하세요.

    • openssl/zlib 등 모듈이 빠짐 : 요구사항에는 포함되어 있지 않지만, 필요하면 OpenSSL/zlib/readline 등을 소스 빌드 후 Python을 재구성하면 됩니다(동일한 --prefix로 재빌드).

    필요하시면 위 절차를 “완전 자동화 스크립트(tcsh)”로도 만들어 드릴게요. (버전만 바꿔 넣으면 재사용 가능)

    openssl 현재 버젼이 openssl 1.1.1k인데 충분할까?

    짧게 답하면 네, “기술적으로는 충분합니다.”
    Python 3.11의 ssl 모듈은 OpenSSL 1.1.1 이상 을 요구하므로, 1.1.1k면 버전 요건을 충족합니다. Python documentationPython Enhancement Proposals (PEPs)

    다만, 단계별로 생각해보면:

    1. 보안·유지보수 관점

      • OpenSSL 1.1.1 계열은 2023-09-11에 EOL 이라 공개 보안 패치가 더 이상 나오지 않습니다. (RHEL은 백포팅을 하기도 하지만, 사용자 환경에서 sudo가 없어 시스템 패키지를 갱신하기 어렵죠.) 가능하면 LTS인 OpenSSL 3.0 계열 로 옮기는 게 안전합니다. openssl-corporation.orgopenssl-library.org

    2. 빌드 관점(중요 포인트)

      • Python이 ssl 모듈을 만들려면 헤더/라이브러리(보통openssl-devel) 가 필요합니다. 시스템에 개발 헤더가 없다면, 1.1.1k가 있어도 ssl 모듈이 비활성화됩니다. 이 경우엔 사용자 영역에 OpenSSL을 소스 빌드 해서 Python에 경로를 넘기는 게 확실합니다. (Python 3.11은 OpenSSL 1.1.1과 3.0 모두 지원) Python documentationDiscussions on Python.org

    3. 실무 권장안

      • 최소요건만 본다면 지금 상태(1.1.1k)로도 Python 3.11 빌드는 가능합니다.

      • 하지만 장기 유지/보안 을 생각하면, 오프라인으로 openssl-3.0.x 소스 타볼(예: openssl-3.0.17.tar.gz)을 받아 ${RELEASE}/installers에 두고, 아래처럼 로컬 설치 후 Python을 그걸로 링크 하는 걸 권합니다. (3.0은 현재 LTS이며 2026-09까지 보안 지원) openssl-library.org+1 ``` tcsh

요지는 이거예요:

  * **GCC만큼은 “소스 디렉터리 안(in-source)”에서 빌드하면 안 됩니다.** GCC 공식 문서가 **소스 트리 밖(out-of-source)** 빌드를 강력 권장하고, _objdir == srcdir_ (소스 디렉터리에서 곧장 빌드)은 **미지원(unsupported)** 이라고 못박아요. 다만 _srcdir의 하위에 별도 빌드 디렉터리(objdir)_ 를 두는 건 “동작하긴 한다(should work)”고 되어 있어요. [gcc.gnu.org](https://gcc.gnu.org/install/configure.html)

  * **SQLite, Python은** (일반적인 Autoconf 프로젝트처럼) **out-of-source 빌드가 잘 됩니다.** 관례적으로 VPATH(자동메이크의 out-of-tree) 빌드가 지원돼요. 소스 트리를 더럽히지 않으니 유지보수에 유리합니다. [GNU](https://www.gnu.org/s/automake/manual/html_node/VPATH-Builds.html?utm_source=chatgpt.com)

  * 결론적으로, **`${RELEASE}/installers` 안에 빌드 디렉터리를 만들어도 됩니다.** 핵심은 _소스 디렉터리와는 다른 디렉터리_ 에서 `configure`/`make`를 돌리는 거예요. (예: `${RELEASE}/installers/build/gcc-13.4.0` → 소스는 `${RELEASE}/installers/gcc-13.4.0`)

    * Python도 out-of-tree가 가능하고 실제로 그렇게들 씁니다(관련 이슈·논의도 있어요). [GitHub](https://github.com/python/cpython/issues/54069?utm_source=chatgpt.com)

아래처럼 하면 깔끔합니다.

# 디렉터리 배치(예)
```bash
${RELEASE}/installers/
  gcc-13.4.0/           # [소스]
  sqlite-autoconf-3500400/   # [소스]
  Python-3.11.13/       # [소스]
  build/                # [빌드 산출물 전용 루트]
    gcc-13.4.0/         # [GCC 빌드 디렉터리]
    sqlite-3.50.4/      # [SQLite 빌드 디렉터리]
    python-3.11.13/     # [Python 빌드 디렉터리]

    어떻게 치면 되나 (step-by-step)

    1) GCC (반드시 out-of-source)

    tcsh

# 소스: ${RELEASE}/installers/gcc-13.4.0
# 빌드: ${RELEASE}/installers/build/gcc-13.4.0  ← 소스 바깥이면 installers 안이어도 OK
mkdir -p ${RELEASE}/installers/build/gcc-13.4.0
cd ${RELEASE}/installers/build/gcc-13.4.0

# configure는 "소스 경로/configure"를 실행
${RELEASE}/installers/gcc-13.4.0/configure \
  --prefix=${RELEASE}/toolchains/gcc/13.4.0 \
  --disable-multilib --enable-languages=c,c++ --enable-bootstrap

make -j${njobs}
make install
rehash

    근거: GCC는 소스 디렉터리 안에서의 빌드를 미지원(objdir == srcdir unsupported). srcdir 하위의 별도 objdir은 “동작하긴 함”. 그래서 위처럼 소스 옆의 별도 빌드 디렉터리 를 잡는 게 정석입니다. gcc.gnu.org

    2) SQLite (in-source도 되지만, out-of-source 권장)

    tcsh

mkdir -p ${RELEASE}/installers/build/sqlite-3.50.4
cd ${RELEASE}/installers/build/sqlite-3.50.4

setenv CC gcc
${RELEASE}/installers/sqlite-autoconf-3500400/configure \
  --prefix=${RELEASE}/packages/sqlite/3.50.4 \
  --enable-shared
make -j${njobs}
make install
rehash

    Autoconf/Automake의 VPATH(out-of-tree) 빌드 가 표준적으로 지원됩니다. 소스 폴더를 깔끔히 유지하려면 이 방식이 좋아요. GNU

    3) Python 3.11 (in-source 가능, out-of-source 권장)

    tcsh

mkdir -p ${RELEASE}/installers/build/python-3.11.13
cd ${RELEASE}/installers/build/python-3.11.13

setenv CC gcc
setenv CXX g++
# (SQLite와 링크하려면 include/lib 경로 지정)
setenv CPPFLAGS "-I${RELEASE}/packages/sqlite/3.50.4/include"
setenv LDFLAGS  "-L${RELEASE}/packages/sqlite/3.50.4/lib -Wl,-rpath,${RELEASE}/packages/sqlite/3.50.4/lib"

${RELEASE}/installers/Python-3.11.13/configure \
  --prefix=${RELEASE}/packages/python/3.11.13 \
  --enable-shared --with-ensurepip=install
make -j${njobs}
make install
rehash

    Python은 전통적으로 소스 디렉터리에서 바로 빌드하는 예시 가 문서에 많지만, Autoconf 기반이라 out-of-tree도 가능 합니다(옛 이슈에서도 out-of-tree 전제를 두고 논의). 유지보수 측면에서 out-of-tree가 유리합니다. Python documentationGitHub

    요약

    • 가능 : ${RELEASE}/installers 안에 별도 build 하위 폴더 를 만들어 그 안에서 빌드하기.

    • 주의 : GCC는 소스 디렉터리 자체에서 빌드 금지(unsupported). 소스 옆의 build/gcc-...처럼 분리 디렉터리 를 쓰세요. gcc.gnu.org

    • 왜 권장? 소스/산출물 분리 → 청소·재빌드·멀티 설정(디버그/릴리즈) 관리가 쉬워집니다. Autoconf/Automake가 이를 정식 지원(VPATH). GNU

    원하시면, 위 구조(installers 안의 build/*)로 맞춘 tcsh 자동화 스크립트 를 바로 만들어 드릴게요.

    그러면 installer/build/gcc-…/ 에서 빌드할게. 다시 다 작성해줘. 그리고 빌드 커맨드를 나중에 참고하기 위해 저장해두고 싶은데 어디에 하는게 좋을까?

    좋아—installers/build/... 안에서 빌드하도록 전 과정을 다시 정리했고,
    “나중에 참고할 빌드 커맨드/로그”를 표준 위치에 자동 저장 하도록 구성했어.
    (셸은 tcsh, sudo 불가/오프라인 가정)

    0) 공통 레이아웃 & 환경 변수 (한 번만)

    tcsh

# 0-1) 설치 루트 지정
setenv RELEASE /path/to/release

# 0-2) 표준 디렉터리
mkdir -p ${RELEASE}/installers/build
mkdir -p ${RELEASE}/toolchains
mkdir -p ${RELEASE}/packages
mkdir -p ${RELEASE}/env
# 빌드 커맨드 보관/로그 보관 위치
mkdir -p ${RELEASE}/recipes ${RELEASE}/logs

# 0-3) 병렬 빌드 스레드 수
if ( -x /usr/bin/nproc ) then
  set njobs=`/usr/bin/nproc`
else
  set njobs=2
endif

    소스 아카이브(오프라인으로 준비해서 ${RELEASE}/installers에 두기)

    • GCC 13.4.0: gcc-13.4.0.tar.xz

      • (함께) gmp-6.3.0.tar.xz, mpfr-4.2.1.tar.xz, mpc-1.3.1.tar.gz

    • SQLite 3.50.4: sqlite-autoconf-3500400.tar.gz

    • Python 3.11.13: Python-3.11.13.tar.xz

    구조(예):

    bash

${RELEASE}/installers/
  gcc-13.4.0/                  # [압축 해제 후 소스]
  sqlite-autoconf-3500400/
  Python-3.11.13/
  build/
    gcc-13.4.0/                # [빌드 디렉터리]
    sqlite-3.50.4/
    python-3.11.13/

    1) GCC 13.4.0 빌드 (objdir = ${RELEASE}/installers/build/gcc-13.4.0)

    tcsh

# 1-0) 소스/부속 라이브러리 배치
cd ${RELEASE}/installers
tar -xf gcc-13.4.0.tar.xz
tar -xf gmp-6.3.0.tar.xz
tar -xf mpfr-4.2.1.tar.xz
tar -xf mpc-1.3.1.tar.gz

mv gmp-6.3.0  gcc-13.4.0/gmp
mv mpfr-4.2.1 gcc-13.4.0/mpfr
mv mpc-1.3.1  gcc-13.4.0/mpc

# 1-1) 빌드 디렉터리
mkdir -p ${RELEASE}/installers/build/gcc-13.4.0
cd       ${RELEASE}/installers/build/gcc-13.4.0

# 1-2) prefix 등 공통 경로
setenv GCC_PREFIX ${RELEASE}/toolchains/gcc/13.4.0
mkdir -p ${GCC_PREFIX}

# 1-3) "빌드 커맨드/로그 보관" 준비
mkdir -p ${RELEASE}/recipes/gcc-13.4.0
mkdir -p ${RELEASE}/logs/gcc-13.4.0

# 1-4) configure (커맨드 저장+로그 저장)
set cfg="${RELEASE}/installers/gcc-13.4.0/configure \
  --prefix=${GCC_PREFIX} \
  --disable-multilib \
  --enable-languages=c,c++ \
  --enable-bootstrap"
echo $cfg > ${RELEASE}/recipes/gcc-13.4.0/configure.cmd
eval $cfg |& tee ${RELEASE}/logs/gcc-13.4.0/configure.log

# 1-5) 빌드/설치 (커맨드+로그 저장)
set mk="make -j${njobs}"
echo $mk > ${RELEASE}/recipes/gcc-13.4.0/make.cmd
eval $mk |& tee ${RELEASE}/logs/gcc-13.4.0/make.log

set inst="make install"
echo $inst > ${RELEASE}/recipes/gcc-13.4.0/install.cmd
eval $inst |& tee ${RELEASE}/logs/gcc-13.4.0/install.log

# 1-6) 신규 gcc 사용
setenv PATH ${GCC_PREFIX}/bin:${PATH}
setenv LD_LIBRARY_PATH ${GCC_PREFIX}/lib64:${GCC_PREFIX}/lib:${LD_LIBRARY_PATH}
rehash
gcc --version

    중요 : GCC는 반드시 소스 밖(out-of-source) 빌드. 위처럼 installers/build/gcc-13.4.0을 objdir로 사용하면 안전해.

    2) SQLite 3.50.4 빌드 (objdir = installers/build/sqlite-3.50.4)

    tcsh

cd ${RELEASE}/installers
tar -xf sqlite-autoconf-3500400.tar.gz

mkdir -p ${RELEASE}/installers/build/sqlite-3.50.4
cd       ${RELEASE}/installers/build/sqlite-3.50.4

setenv SQLITE_PREFIX ${RELEASE}/packages/sqlite/3.50.4
mkdir -p ${SQLITE_PREFIX}
mkdir -p ${RELEASE}/recipes/sqlite-3.50.4
mkdir -p ${RELEASE}/logs/sqlite-3.50.4

setenv CC gcc
setenv CFLAGS "-O2 -fPIC"
# rpath를 심어두면 런타임에 LD_LIBRARY_PATH가 없어도 찾기 쉬움
setenv LDFLAGS "-Wl,-rpath,${SQLITE_PREFIX}/lib"

set cfg="${RELEASE}/installers/sqlite-autoconf-3500400/configure \
  --prefix=${SQLITE_PREFIX} \
  --enable-shared"
echo $cfg > ${RELEASE}/recipes/sqlite-3.50.4/configure.cmd
eval $cfg |& tee ${RELEASE}/logs/sqlite-3.50.4/configure.log

set mk="make -j${njobs}"
echo $mk > ${RELEASE}/recipes/sqlite-3.50.4/make.cmd
eval $mk |& tee ${RELEASE}/logs/sqlite-3.50.4/make.log

set inst="make install"
echo $inst > ${RELEASE}/recipes/sqlite-3.50.4/install.cmd
eval $inst |& tee ${RELEASE}/logs/sqlite-3.50.4/install.log

rehash
${SQLITE_PREFIX}/bin/sqlite3 -version

    3) Python 3.11.13 빌드 (objdir = installers/build/python-3.11.13)

    tcsh

cd ${RELEASE}/installers
tar -xf Python-3.11.13.tar.xz

mkdir -p ${RELEASE}/installers/build/python-3.11.13
cd       ${RELEASE}/installers/build/python-3.11.13

setenv PY_PREFIX ${RELEASE}/packages/python/3.11.13
mkdir -p ${PY_PREFIX}
mkdir -p ${RELEASE}/recipes/python-3.11.13
mkdir -p ${RELEASE}/logs/python-3.11.13

# 새 gcc 및 sqlite에 링크
setenv CC gcc
setenv CXX g++
setenv CPPFLAGS "-I${SQLITE_PREFIX}/include"
setenv LDFLAGS  "-L${SQLITE_PREFIX}/lib -Wl,-rpath,${SQLITE_PREFIX}/lib"

set cfg="${RELEASE}/installers/Python-3.11.13/configure \
  --prefix=${PY_PREFIX} \
  --enable-shared \
  --with-ensurepip=install"
echo $cfg > ${RELEASE}/recipes/python-3.11.13/configure.cmd
eval $cfg |& tee ${RELEASE}/logs/python-3.11.13/configure.log

set mk="make -j${njobs}"
echo $mk > ${RELEASE}/recipes/python-3.11.13/make.cmd
eval $mk |& tee ${RELEASE}/logs/python-3.11.13/make.log

set inst="make install"
echo $inst > ${RELEASE}/recipes/python-3.11.13/install.cmd
eval $inst |& tee ${RELEASE}/logs/python-3.11.13/install.log

rehash
${PY_PREFIX}/bin/python3.11 -c 'import sys,sqlite3; print(sys.version); print("sqlite:", sqlite3.sqlite_version)'

    4) 매번 쓰기 편한 활성화 스크립트(env/activate.csh)

    tcsh

cat > ${RELEASE}/env/activate.csh << 'EOF'
# 사용법:
#   setenv RELEASE /path/to/release
#   source ${RELEASE}/env/activate.csh

setenv GCC_PREFIX    ${RELEASE}/toolchains/gcc/13.4.0
setenv SQLITE_PREFIX ${RELEASE}/packages/sqlite/3.50.4
setenv PY_PREFIX     ${RELEASE}/packages/python/3.11.13

setenv PATH            ${PY_PREFIX}/bin:${SQLITE_PREFIX}/bin:${GCC_PREFIX}/bin:${PATH}
setenv LD_LIBRARY_PATH ${PY_PREFIX}/lib:${SQLITE_PREFIX}/lib:${GCC_PREFIX}/lib64:${GCC_PREFIX}/lib:${LD_LIBRARY_PATH}
setenv PKG_CONFIG_PATH ${SQLITE_PREFIX}/lib/pkgconfig:${PKG_CONFIG_PATH}

rehash
echo "[env] GCC:     `gcc --version | head -1`"
echo "[env] SQLite:  `sqlite3 -version | head -1`"
echo "[env] Python:  `python3.11 --version`"
EOF

    빌드 커맨드를 “나중에 보기 좋게” 저장하려면 어디가 좋을까?

    • 정답:${RELEASE}/recipes/<패키지>/

      • 예) recipes/gcc-13.4.0/{configure.cmd,make.cmd,install.cmd}

      • 예) recipes/python-3.11.13/configure.cmd

    • 빌드/설치 로그는${RELEASE}/logs/<패키지>/

      • 예) logs/sqlite-3.50.4/configure.log, make.log, install.log

    • 위 절차는 이미 각 단계에서 echo … > recipes/...와 |& tee logs/...로 자동 저장 하고 있어.

    • 추가로 버전/경로 메타데이터를 한 파일에 모으고 싶다면:

    tcsh

cat > ${RELEASE}/recipes/MANIFEST.txt << EOF
GCC:    13.4.0 -> ${RELEASE}/toolchains/gcc/13.4.0
SQLite: 3.50.4 -> ${RELEASE}/packages/sqlite/3.50.4
Python: 3.11.13 -> ${RELEASE}/packages/python/3.11.13
EOF

    트러블슈팅(요약)

    • gcc 런타임 라이브러리 못 찾음 → LD_LIBRARY_PATH에 ${GCC_PREFIX}/lib64:${GCC_PREFIX}/lib.

    • Python에서 _sqlite3 미로딩 → CPPFLAGS/LDFLAGS 누락 또는 런타임에 libsqlite3.so 탐색 실패(rpath/LD_LIBRARY_PATH 확인).

    • 문서(Info) 생성 실패 경고 → GCC 빌드 자체엔 영향 거의 없음.

    필요하면 OpenSSL(예: 3.0 LTS)도 같은 패턴으로 recipes/logs에 커맨드와 로그를 남기면서 사용자 경로에 빌드하도록 추가해줄게.
