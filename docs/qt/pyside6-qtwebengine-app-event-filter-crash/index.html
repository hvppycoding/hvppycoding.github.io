    PySide6: 앱 이벤트 필터 하나로 QWebEngineView가 segfault하는 이유 (PYSIDE-3409)

    PySide6 앱에 QWebEngineView를 붙였더니 웹 뷰가 화면에 뜨는 순간 프로세스가 SIGSEGV로 죽었다. 원인을 좁혀 보니 웹 엔진 쪽 코드는 아무 상관이 없었다. Python으로 만든 application-level event filter가 하나라도 설치돼 있으면 죽는다. 그 필터가 아무 일도 하지 않고 False만 돌려줘도 마찬가지다.

    최소 재현

    """PYSIDE-3409 minimal repro: a Python application event filter + QWebEngineView = SIGSEGV.

    python repro.py              # crashes (exit -11 / SIGSEGV) on PySide6 <= 6.11.2
    python repro.py --no-filter  # same page, no app filter: renders and exits 0
"""

import sys

from PySide6.QtCore import QObject, QTimer
from PySide6.QtWebEngineCore import QWebEnginePage, QWebEngineProfile
from PySide6.QtWebEngineWidgets import QWebEngineView
from PySide6.QtWidgets import QApplication


class PassThrough(QObject):
    def eventFilter(self, watched, event):  # noqa: N802 - Qt override
        return False  # does nothing; just being installed is enough


app = QApplication(sys.argv)
if "--no-filter" not in sys.argv:
    keep = PassThrough()
    app.installEventFilter(keep)

view = QWebEngineView()
page = QWebEnginePage(QWebEngineProfile(app), view)
view.setPage(page)
page.setHtml("<h1>hello</h1>")
view.show()

QTimer.singleShot(3000, app.quit)
app.exec()
print("survived")

    실행 결과 (macOS arm64, Python 3.13, PySide6 6.9.3 / Qt WebEngine = Chromium 130):

    $ python repro.py --no-filter
survived                      # exit 0
$ python repro.py
                              # exit -11 (SIGSEGV)

    마우스를 움직일 필요도 없다. 웹 뷰가 처음 뜰 때 Qt가 내부적으로 보내는 posted event만으로 충분하다.

    네이티브 스택

    lldb로 잡은 스택은 이렇다.

    PySide::typeName(QObject const*) + 36          <- EXC_BAD_ACCESS address=0x8
PySide::getWrapperForQObject(QObject*, _typeobject*)
QObjectWrapper::sbk_o_eventFilter(...)
QCoreApplicationPrivate::sendThroughApplicationEventFilters(...)
...
QObject::doSetProperty(...)
PySide::getWrapperForQObject(...)
QObjectWrapper::sbk_o_eventFilter(...)

    죽는 순간 넘어온 객체의 vtable은 QtWebEngineCore::RenderWidgetHostViewQtDelegateItem이었다.

    왜 죽나

    1. 앱 이벤트 필터는 앱의 모든 QObject가 받는 이벤트를 먼저 본다. 사용자가 만든 위젯뿐 아니라 Qt가 내부에서 만든 객체도 예외가 아니다.
    2. 필터가 Python이면, PySide는 이벤트마다 대상 C++ 객체를 Python 객체로 바꿔 넘겨야 한다. eventFilter(self, watched, event)의 watched가 그것이다. 처음 보는 객체라면 wrapper를 새로 만든다.
    3. wrapper를 만들 때 PySide 6.9.3의 typeName()은 C++ RTTI(typeid(*obj).name())로 "실제 클래스가 무엇인지"를 먼저 묻는다. 메타오브젝트(QMetaObject) 조회는 그다음이다.
    4. 웹 뷰가 처음 화면에 뜰 때 Qt WebEngine은 내부 표면 객체 RenderWidgetHostViewQtDelegateItem을 만든다. 이것도 이벤트를 받으므로 앱 필터로 넘어온다.
    5. 그런데 QtWebEngineCore는 -fno-rtti로 빌드돼 있다. Chromium이 RTTI 없이 빌드되기 때문이다. 그래서 이 클래스의 vtable에서 type_info 슬롯이 null이다.
    6. typeid()가 null + 8을 읽고 죽는다. 주소 0x8이 바로 그 흔적이다.

    중요한 점은 이 crash가 Python 필터 코드에 들어가기 전에, 바인딩이 인자를 변환하는 단계에서 난다는 것이다. 필터 안에서 isinstance 검사를 하든 try/except로 감싸든 막을 방법이 없다.

    우회 시도와 결과

    시도 결과
    QtQuick 모듈을 먼저 import 여전히 crash
    QQuickWidget.rootObject() wrapper를 미리 만들어 붙잡아 둠 crash. 죽는 건 나중에 생기는 delegate item이고, 그걸 Python으로 꺼내는 경로(childItems() 등)도 같은 typeName()을 지난다
    필터 코드에서 피하기 불가능. 필터 코드가 실행되기 전에 죽는다
    앱 필터 대신 위젯 단위 installEventFilter crash는 피한다. 웹 엔진 내부 객체의 이벤트가 그 필터를 거치지 않기 때문이다. 단, 앱 필터로만 할 수 있던 일(자식이 먼저 소비하는 키 이벤트 가로채기 등)은 못 한다

    결국 실질적인 회피책은 "웹 뷰가 있는 프로세스에는 Python 앱 이벤트 필터를 두지 않는다"뿐이다. 테마 전환, 전역 단축키, IME 처리처럼 앱 필터를 쓰는 라이브러리 코드가 하나라도 섞여 있으면 걸린다.

    업스트림 상태

    업스트림 이슈는 PYSIDE-3409이고, 수정 커밋은 b8452b5824ae(2026-08-12)다.

    Fix a crash retrieving the wrapper for QtWebEngineCore::ResourceRequestBody

    The class is built without RTTI on Linux, calling typeid() on it crashes. Flip the lookup order in typeName(QObject*), do QMetaObject lookup first.

    수정 내용은 typeName()에서 RTTI보다 QMetaObject를 먼저 보게 한 것이다. 커밋은 Linux와 ResourceRequestBody를 언급하지만, macOS에서도 RenderWidgetHostViewQtDelegateItem으로 똑같이 재현된다.

    2026-10-01에 공개 저장소를 확인해 보니 이 수정은 dev 브랜치에만 있다. 6.8, 6.9, 6.10, 6.11 브랜치와 v6.10.0–6.10.3, v6.11.0–6.11.2 태그에는 없고, 커밋에 backport 대상(Pick-to:)도 지정돼 있지 않다. 그러니 다음 마이너 릴리스가 나오기 전까지는 앱 필터와 QWebEngineView를 한 프로세스에 둘 수 없다.
