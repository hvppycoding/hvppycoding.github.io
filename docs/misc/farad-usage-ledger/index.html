    Farad에 토큰 사용량 원장과 Greeting 대시보드 카드 붙이기

    데스크톱 AI 에이전트 앱 Farad에 "내가 토큰을 얼마나 썼는지"를 보여주는 기능을 넣었다. 빈 세션(Greeting) 화면에 GitHub 잔디 같은 활동 히트맵과 사용량 타일을 띄우는 대시보드 카드가 목표였고, 그걸 떠받칠 토큰 사용량 원장(ledger) 을 데이터 기반부터 새로 만들었다. 작업을 4개 단계로 나눠서 진행했다.

    Greeting 화면에 붙은 사용량 카드 — 레인지 토글, 토큰 + 핵심 활동 타일, 일별 토큰 히트맵.

    왜 "원장"이 따로 필요했나

    Farad에는 이미 컨텍스트 사용량(context_usage)이 있었다. 하지만 이건 지금/다음 호출에 보낼 컨텍스트 창이 얼마나 찼는지(footer의 Context: 18.2k / 128k)를 보여주는 값이지, 누적 사용량이 아니다. 두 개념은 절대 섞으면 안 된다.

    • context_usage — 컨텍스트 창 점유율. 호출 1회 시점의 스냅샷.
    • token usage ledger — 매 LLM 호출의 input/output/reasoning/cache 토큰을 call 단위로 누적한 원장. 세션별·일·월·년·전체·모델별 사용량의 source of truth. 이번에 새로 만든 것.

    다행히 좋은 소식이 있었다. 토큰 사용량은 이미 transcript(JSONL)에 정확값으로 영속화되어 있었다. char/4 추정이 아니라 provider가 반환한 실제 usage다. 그래서 "기존 대화에서 복원"은 추정이 아니라 정확 집계가 된다.

    설계에서 갈린 지점들

    저장 방식 — JSON 롤업 vs SQLite 원장. 레포의 기존 state는 전부 JSON이었지만, 이번 원장은 per-event 식별·중복 제거(provider 값이 추정값을 덮어쓰기)·범위 질의(day/month/year/ model)·streak/peak-hour 집계가 전부 필요했다. 전형적인 원장의 모양이라 SQLite(파이썬 표준 라이브러리)를 선택했다. 단, 주 타깃이 NFS 공유 HPC라서 락 풋건을 피하려고 journal_mode=DELETE(WAL 금지)·busy_timeout·단일 writer·짧은 트랜잭션으로 못박고, UI는 SQL을 모르게 UsageService 파사드 뒤에 숨겼다.

    이중계산을 어떻게 막나. 라이브 기록과 과거 백필이 같은 호출을 두 번 셀 수 있다. 해결책은 단일 소스 + 안정적 event_id다. assistant transcript 항목의 metadata.provider_usage 딱 하나만 파싱하고, event_id = llm_call_id(없으면 session_id:message_id)로 upsert한다. 그러면 라이브로 기록하든 나중에 백필로 다시 읽든 같은 행에 합쳐져서 절대 두 번 안 세진다. provider 값이 들어오면 추정값을 자동으로 승격(교체)하되, 추정값이 provider 값을 덮진 못하게 했다.

    4단계 구현

    Phase 1 — 데이터 기반. 신규 farad/usage/ 패키지(models / store(SQLite) / service / formatting). completion_usage_meta()에 reasoning 토큰 추출을 추가했고(그동안 필드만 있고 안 채워지던 값), AsyncSession의 이벤트 디스패치에서 assistant 항목이 디스크에 저장될 때 원장에 기록하도록 훅을 걸었다. AppServices에 usage_service를 배선.

    Phase 2 — 백필. 기존 transcript를 훑어 과거 사용량을 채운다. 디렉터리를 직접 열거해서 일반 세션·서브에이전트·스케줄 실행·그 서브에이전트까지 모두 포함했다(기존 세션 목록 API가 스케줄 top-level run을 빠뜨리는 함정이 있었다). transcript 서명(청크 파일 크기/mtime)으로 바뀐 세션만 다시 스캔하는 증분 방식이라, 매 실행마다 전체 스캔하지 않는다. provider 메타가 있으면 정확값, 없는 옛 항목만 output-only로 추정하고 "추정"으로 표시한다. 앱 시작 시 백그라운드 스레드로 1회 돈다.

    Phase 3 — 컨텍스트 툴팁. footer에 보이는 텍스트는 그대로 두고(컨텍스트 창 점유율), 툴팁에만 "이 세션 누적"(입력/출력/추론/캐시) 블록과 출처(provider/추정) 라벨을 더했다. UI는 DB를 직접 읽지 않고 미리 계산된 값을 받는다.

    Phase 4 — Greeting 카드. 이번 작업의 얼굴. 단일 paintEvent로 그리는 활동 히트맵 위젯(셀 수백 개를 개별 위젯으로 두면 저사양에서 무겁다 — 데이터-viz 캔버스로 게이트 예외를 문서에 명시)과, 헤더 레인지(All/30d/7d)·Overview/Models 토글·토큰 + 핵심 활동 타일 8개· 히트맵·추정 푸터를 담은 사용량 카드. 빈 세션 화면에 인사말 → 카드 순으로 얹고, 프롬프트 입력창은 다른 세션처럼 맨 아래에 둔다. 데이터가 없거나 화면이 짧으면 카드를 숨겨서 미니멀한 인사말은 그대로 유지한다.

    색은 전부 팔레트 토큰으로만 칠해서 라이트/다크가 자동으로 따라온다. 히트맵 셀은 accent_solid 한 토큰에서 alpha 0.30 / 0.55 / 0.78 / 1.0 램프로 강도를 표현한다.

    도중에 만난 함정

    • Greeting 오버레이의 높이 = 타임라인 뷰포트, 윈도우 높이가 아니다. 프롬프트 입력창은 그 아래 별도 영역이다. 처음엔 카드를 위에, 인사말을 프롬프트 바로 위에 붙이는 구조로 짰는데, 새 세션 화면이 프롬프트를 화면 가운데로 띄우는 탓에 인사말이 사는 오버레이가 980px 창에서도 ~409px밖에 안 됐다(그래서 카드가 끼지 못하고 숨겨졌다). 결국 레이아웃 자체를 정리했다 — 인사말을 맨 위, 그 아래 사용량 카드, 프롬프트는 다른 세션처럼 맨 아래로. 새 세션의 프롬프트 가운데-띄우기를 걷어내니 타임라인이 풀-높이가 되면서 카드가 넉넉히 들어갔다.
    • 스트리밍 usage는 누적 스냅샷이지 델타가 아니다 — 청크를 더하면 안 된다.
    • cache/reasoning 토큰은 입력/출력의 세부값이라 total에 다시 더하면 안 된다.

    결과와 한계

    신규 테스트 30여 개 + 기존 영향분 갱신으로 통과한다. 라이트/다크 모두 카드가 깔끔하게 렌더된다(시드 데이터 기준: 668K 전체 토큰, 입력/출력 분해, 세션·활동일·연속·피크 시간·주 사용 모델 타일, 그리고 잔디 히트맵). 카드는 전체 폭 대신 컴팩트하게(타일 4열×2행, 캡쳐처럼 가로로 넓고 낮게) 잡고, 히트맵은 카드 폭을 채우도록 폭-반응형으로 그린다. 창이 좁아지면 가로 스크롤 없이 타일이 2열로 자동 reflow되고, 아주 좁으면 카드만 숨긴다. 잔디 셀에 마우스를 올리면 그날 토큰 수가 툴팁으로 뜬다("6월 21일 · 1.2K 토큰").

    다크 모드 — 색은 전부 팔레트 토큰이라 라이트에서 따로 손대지 않아도 자동으로 따라온다.

    남은 것:

    • 추정 백필은 output-only다(입력은 추정 생략). 정확값은 provider 메타뿐이고, 추정분은 UI에 "추정 포함"으로 표기한다.
    • 히트맵은 레인지와 무관하게 최근 26주 고정(레인지 토글은 타일/모델에만 적용).
    • 비용($) 표시는 스코프 밖 — 모델 단가 데이터가 앱에 아직 없어서 토큰만 다룬다. 나중에 단가만 붙이면 환산되도록 자리는 비워뒀다.

    데이터 기반(원장 + 백필 + 서비스)을 제대로 깔아둔 덕에, Greeting 카드 말고도 컨텍스트 툴팁, 나중에 만들 전용 사용량 패널까지 같은 UsageService 하나로 붙일 수 있게 됐다.
