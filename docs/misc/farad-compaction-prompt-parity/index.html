    Claude Code의 대화 압축 프롬프트를 Farad에 그대로 이식하기

    데스크톱 AI 에이전트 앱 Farad의 대화 압축(compaction) 프롬프트를 Claude Code(CC)의 압축 프롬프트와 거의 동일하게 다시 썼다. 덤으로 "주 사용 언어" 섹션 하나를 추가하고, 압축 도중 돌던 메모리 저장 로직은 전부 걷어냈다. 이 글은 그래서 얼마나 충실하게 이식됐나를 두 프롬프트를 나란히 놓고 검증한 기록이다.

    배경 — Farad의 압축은 3단계

    Farad는 컨텍스트가 차오를 때 3단계로 대응한다.

    • microcompact — 도구 결과만 잘라내고 메시지는 전부 유지.
    • full compaction — LLM에게 대화 전체 요약을 받아 히스토리를 그 요약으로 치환.
    • snip — 비상시 강제 드롭.

    이 중 full compaction이 LLM에 보내는 "요약을 만들어줘" 프롬프트가 이번 작업의 대상이다. 기존 Farad는 자체 압축 프롬프트 + 압축 시점에 메모리를 추출/저장하는 별도 경로를 갖고 있었는데, 메모리보다 압축 품질이 우선이라고 판단해서 방향을 틀었다:

    1. 압축 프롬프트를 검증된 CC 프롬프트와 통일한다.
    2. 압축 중 메모리 저장/파싱 후처리는 제거한다.
    3. 단, 한/영 혼용 환경을 위해 주 사용 언어 섹션만 추가한다.

    무엇을 바꿨나

    • Compactor._build_summary_prompt()를 CC getCompactPrompt()와 동일 구조로 재작성. 조립 규칙은 NO_TOOLS_PREAMBLE + BASE_COMPACT_PROMPT + (Additional Instructions) + NO_TOOLS_TRAILER로 CC와 같다.
    • 9개 섹션(Primary Request, Key Technical Concepts, … Optional Next Step)과 <analysis>/<summary> 출력 계약을 CC와 동일하게 유지.
    • Section 10. Primary Language 추가 — 유저의 주 사용 언어와 어시스턴트가 응답해온 언어(예: 한국어)를 추출하고, 다른 요청이 없는 한 압축 이후에도 그 언어를 유지하라는 지시.
    • 압축 응답에서 메모리를 파싱해 성공/실패 후처리하던 코드 제거.
    • 더 이상 호출되지 않는 죽은 메모리-flush 서브시스템(FlushRunner, flush_memory_before_compact, AppendOnlyWriteTool)을 통째로 삭제.

    충실도 검증 — 손으로 옮기지 않는다

    비교의 신뢰도를 위해 두 프롬프트를 구현된 상태 그대로 추출했다. 전사 오류를 0으로 만들기 위해 사람이 다시 타이핑하지 않는다.

    • CC: 원본 TypeScript(services/compact/prompt.ts)에서 NO_TOOLS_PREAMBLE, BASE_COMPACT_PROMPT, DETAILED_ANALYSIS_INSTRUCTION_BASE 템플릿 리터럴을 정규식으로 추출 → ${...} 보간 치환 → NO_TOOLS_TRAILER 결합. getCompactPrompt()의 조립을 그대로 재현.
    • Farad: 실제 구현 함수 Compactor._build_summary_prompt()를 그냥 호출한 반환값.
