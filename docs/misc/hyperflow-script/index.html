    HyperFlow - script

    2025-09-16

    아래는 내 발표 대본이야. 근데 문제는 영어로 해야해. 이걸 영어로 바꿔줘. 어려운 용어나 수식어 쓰지말고 최대한 간단하고 엔지니어 용어로 써줘. Page 0> 안녕하세요. 제 이름은 양자영입니다. 저는 ai가 추가된 workflow framework를 개발하고 사내에 배포하는 것을 기획하고 있습니다. 임시로 이름은 hyperflow라고 지었습니다. 이는 며칠 전부터 시작해서 매우 초기 단계입니다. 저의 목표는 우리 회사 엔지니어들이 쉽게 ai가 포함된 workflow를 잘 활용할 수 있게 하는 것입니다. 다른 좋은 아이디어가 있으면 공유해주시면 감사하겠습니다. Page 1> 오픈소스 프레임워크인 ComfyUI를 우리의 설계 환경에 맞게 커스터마이즈하여 툴을 배포하고자 합니다. (툴 시작 데모) ComfyUI를 각자의 머신에서 띄우기 위한 간단한 Manager 앱을 만들었고, Chrome으로 접속할 수 있습니다. 제가 생각하는 이 방식의 유저 사이드 장점은 크게 5가지입니다. 1. AI의 힘을 워크플로우에 사용하는 것 그 자체. 다른 ai agent와 이 부분은 같다. 현재는 대부분의 사용자들이 chat gpt 와 같은 chat-based로 단편적인 질문 위주로 활용 중이다. 이 프레임워크를 통해 chat을 통해 묻고 자신이 직접 실행하는 것을 벗어날 수 있다. 그리고 더 많은 것을 AI에게 위임할 수 있다. 2. 안정성. 미래에는 어떨지 모르겠지만 현재의 AI의 능력으로는 자동으로 복잡한 업무를 모두 할 수는 없다. 또한 프롬프팅에 따라 영향을 많이 받는다.Workflow 그래프를 만들어두고 AI가 잘 할 수 있는 단위로 나누어시키면 안정성을 높일 수 있다. 예를 들어 "doc 폴더에 있는 모든 *.md 파일을 한국어로 번역해서 doc_kr에 넣어줘." 라는 작업을 단일 agent에게 맡긴다면 잘 하지 못할 수 있다.하지만 ai는 하나의 파일을 번역하는 것은 잘한다. 그래서 각 파일을 나누어서 번역하는 워크플로우를 만들면 안정성을 높일수 있을 것 같다. 3. 재사용성 각 워크플로우를 export하여 json형태로 저장할 수 있다. 이를 다른 사람이 load 하여 쉽게 사용할 수 있다. 간단하지만 강력한 기능이라고 생각한다. 왜냐하면 대부분의 사용자들은 잘 만들어진 워크플로우를 불러와서 입력만 수정해서 런을 할 것이기 때문이다. 4. 커스터마이저블 코딩을 잘 모르는 사람도 노드 기반으로 쉽게 워크플로우를 수정할 수 있다. 이 또한 매우 중요한 기능이라고 생각한다. 특히, 우리는 설계 현업에서의 디테일한 업무까지는 잘 알지 못한다. 이 프레임워크를 통해 그들이 우리가 제공한 다양한 Node 들을 활용해 자신들에게 맞는 워크플로우를 스스로 만들고 서로 공유하는 것을 기대한다. 5. 모니터 현재 있는 솔루션들은 AI Agent가 일을 할 때 진행 사항을 모니터링하기가 쉽지 않다. 해당 AI Agent를 개발한 사람은 ai가 잘하고 있는지, 잘못하고 있는지 로그파일이나 생성되는 파일 위치를 보고 알 수 있으나, 모르는 사람이 보면 엄청난 텍스트 밖에 보이지 않는다. Workflow화했을 때 장점은 처음 보는 사람도 지금 워크플로우 상에서 어떤 단계를 진행하고, 어떤 단계에서 실패했는지 알기 쉽다. 지금까지는 유저와 활용 입장에서의 장점들에 대해서 얘기했다. 이제는 프레임워크를 관리하는 개발자의 입장에서 얘기하겠다. 개발자가 무한히 많은 개발자가 있는 것이 아니기 때문에 효율적인 개발이 중요하다. 1. 파이썬이다. 각각의 노드는 파이썬으로 되어 있으며, 객체 간의 데이터 전달도 파이썬 객체이다. 파이썬은 현재 가장 인기있는 프로그래밍 언어이며, 최신 AI 기술 패키지를 손쉽게 설치하고 활용할 수 있다. 2. 활발한 개발 + 풍부한 Custom Node ComfyUI는 인기 있는 이미지 생성 프레임워크이기 때문에 활발히 개선되고 있는 중이다. 예를 들어, subgraph 기능과 parallel api 기능이 1달전에 릴리즈 되었다. 또한, 이미지 처리 관련 노드가 대다수이긴 하지만, 사람들이 만들어둔 많은 노드 패키지를 활용할 수 있다. 3. 확장이 쉽다. custom node를 추가하여 기능 확장이 쉽다. 파이썬 코드를 추가하여 원하는 기능을 구현하고 여러 워크플로우에서 재사용할 수 있다. ComfyUI는 인기 있는 툴이고, ChatGPT도 이에 대해 잘 알고 있기 때문에 개발할 때 도움을 받을 수 있다. 또한, 소스 자체도 오픈소스이기 때문에 최악의 경우엔 소스를 고칠 수도 있다. 단점 지금까지는 제가 생각하는 장점들에 대해 주로 이야기 했는데요, 이제 단점에 대해 얘기해 보겠습니다. 1. 안정성 개인 사용자를 대상으로 개발된 오픈소스이기 때문에 안정성이 떨어질 수 있다. 2. Parallel Processing parallel api가 최근 추가되긴 했지만 Parallelism이 많이 요구되니는 Workflow 처리 가능성은 아직 의문인 상태이다.

    좋아요! 아래에 어렵지 않은 엔지니어 톤으로 깔끔하게 영어로 바꿔 썼어요. 페이지별로 바로 읽으시면 됩니다.

    Page 0

    Hello. My name is Ja-young Yang.
    I’m planning and building a workflow framework with AI and rolling it out inside our company.
    The temporary name is Hyperflow. We started a few days ago, so this is very early.

    My goal is simple: help our engineers use AI-powered workflows easily.
    If you have better ideas, please share them.

    Page 1

    We will customize the open-source framework ComfyUI for our engineering environment and ship it as our tool.
    (Start tool demo)

    I made a small Manager app so each person can run ComfyUI on their own machine and access it in Chrome.

    Here are five user-side benefits of this approach:

    1. Use AI inside the workflow
      Most people use chat tools like ChatGPT for one-off questions. With this framework, you can move beyond “ask in chat, then run it yourself.” You can hand more steps to AI inside a defined workflow.

    2. Reliability
      Today’s AI can’t do long, complex tasks end-to-end, and results vary with prompts. If we build a workflow graph and split work into steps that AI is good at, reliability goes up.
      Example: “Translate all *.md files in the doc folder to Korean and put them in doc_kr.” A single agent may fail. But AI is good at one file at a time. So a per-file translation workflow is more stable.

    3. Reusability
      You can export any workflow to JSON and share it. Others can load it, tweak inputs, and run. Simple but powerful.

    4. Customizable
      Non-coders can edit workflows with node-based editing. We don’t know every detail of field work. With our nodes, teams can build what they need and share with others.

    5. Monitoring
      Agent tools are hard to monitor. Developers read logs, but most users just see walls of text. A workflow view makes it clear which step is running and where it failed.

    So far I covered user benefits. Now from the framework maintainer’s view: we must build efficiently.

    1. Python
      Each node is Python. Data between nodes are Python objects. Python is popular and has rich AI packages.

    2. Active dev + many custom nodes
      ComfyUI is popular for image generation and improves fast. For example, subgraph and Parallel API shipped about a month ago. There are many community node packs (mostly image-related) we can reuse.

    3. Easy to extend
      We can add custom nodes to extend features. Write Python once and reuse across workflows. ComfyUI is well known, and ChatGPT can help during development. It’s open source, so in the worst case we can patch the code.

    Drawbacks

    1. Stability
      It’s open source aimed at individual users, so stability may be lower.

    2. Parallel processing
      Parallel API is new. It’s still unclear if it can handle high parallelism for heavy workflow processing.
