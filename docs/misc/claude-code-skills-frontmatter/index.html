    Claude Code Skills 완전 정리 — SKILL.md와 모든 프론트매터 필드

    Claude Code의 Skill(스킬) 은 "반복해서 붙여넣던 지시·체크리스트·다단계 절차"를 파일 하나로 묶어 에이전트의 도구상자에 추가하는 기능이다. SKILL.md 파일을 만들어 두면 Claude가 필요할 때 알아서 불러오거나, /skill-name 으로 직접 실행할 수 있다.

    이 글은 스킬의 개념과 구조를 정리하되, 특히 SKILL.md의 YAML 프론트매터 필드를 빠짐없이 다룬다. 내용은 공식 문서(Claude Code Skills, Agent Skills 개요) 기준이다(2026년 6월).

    1. Skill이란? 언제 만드나

    스킬을 만들 타이밍은 단순하다.

    • 같은 지시/체크리스트/절차를 채팅에 자꾸 다시 붙여넣고 있을 때
    • CLAUDE.md의 한 섹션이 "사실(fact)"이 아니라 "절차(procedure)"로 자라났을 때

    CLAUDE.md 내용과 달리 스킬의 본문은 실제로 쓰일 때만 로드된다. 그래서 긴 레퍼런스 자료를 넣어둬도 호출 전까지는 토큰 비용이 거의 0이다. 이게 스킬의 핵심 가치다.

    다른 확장과의 차이

    커스텀 커맨드는 스킬로 통합됐다. .claude/commands/deploy.md 와 .claude/skills/deploy/SKILL.md 는 둘 다 /deploy 를 만들고 동일하게 동작한다. 기존 .claude/commands/ 파일은 계속 작동하며, 스킬은 그 위에 지원 파일 디렉터리, 호출 주체 제어 프론트매터, 자동 로딩 같은 기능을 더한다.

    Claude Code 스킬은 여러 AI 도구에서 통용되는 Agent Skills 오픈 표준을 따르고, 거기에 호출 제어·서브에이전트 실행·동적 컨텍스트 주입 같은 Claude Code 고유 확장을 얹은 형태다.

    2. Progressive Disclosure — 3단계 로딩

    스킬이 "많이 깔아도 가볍다"는 이유는 점진적 공개(progressive disclosure) 구조 덕분이다. 내용이 필요한 시점에만 컨텍스트로 들어온다.

    레벨 로드 시점 토큰 비용 내용
    L1: 메타데이터 항상 (시작 시) 스킬당 ~100토큰 프론트매터의 name + description
    L2: 본문 지시 스킬이 트리거될 때 5k 토큰 미만 권장 SKILL.md 본문(워크플로·가이드)
    L3: 리소스/코드 필요할 때만 사실상 무제한 번들된 파일·스크립트(실행만, 코드는 컨텍스트에 안 들어옴)

    즉 시작 시점엔 "이 스킬이 존재하고 언제 쓰는지"만 알고, 실제 매칭되는 요청이 오면 그제야 SKILL.md 본문을 읽고, 거기서 참조하는 REFERENCE.md 같은 파일은 그게 필요한 작업일 때만 추가로 읽는다. 스크립트는 실행해서 출력만 받으므로 코드 자체는 토큰을 쓰지 않는다.

    3. 파일/폴더 구조와 위치

    스킬은 디렉터리 하나가 단위이고, 진입점은 항상 SKILL.md 다.

    my-skill/
├── SKILL.md           # 메인 지시 (필수)
├── template.md        # Claude가 채워 넣을 템플릿
├── examples/
│   └── sample.md      # 기대 출력 형식 예시
└── scripts/
    └── validate.sh    # Claude가 실행할 스크립트

    SKILL.md만 필수다. 나머지(템플릿·예시·스크립트·상세 레퍼런스)는 선택이며, SKILL.md에서 해당 파일을 참조해 둬야 Claude가 "무엇이 들었고 언제 읽어야 하는지" 안다.

    어디에 두느냐가 곧 권한 범위

    위치 경로 적용 범위
    Enterprise managed settings 참고 조직 전체
    Personal ~/.claude/skills/<skill-name>/SKILL.md 내 모든 프로젝트
    Project .claude/skills/<skill-name>/SKILL.md 해당 프로젝트
    Plugin <plugin>/skills/<skill-name>/SKILL.md 플러그인이 켜진 곳

    같은 이름이 여러 레벨에 있으면 enterprise > personal > project 순으로 덮어쓴다. 어느 레벨이든 동명의 번들 스킬도 override 한다(예: 프로젝트에 code-review 스킬을 두면 번들 /code-review 를 대체). 플러그인 스킬은 plugin-name:skill-name 네임스페이스라 충돌하지 않는다.

    또한 작업 디렉터리 하위의 중첩 .claude/skills/ 도 로드된다. 모노레포에서 패키지가 자기 스킬을 들고 있다가, 그 패키지 파일을 만질 때만 활성화되는 식이다. 이름이 겹치면 중첩본은 apps/web:deploy 처럼 디렉터리 한정 이름으로 노출된다.

    Live change detection: Claude Code는 스킬 디렉터리의 파일 변화를 감시한다. ~/.claude/skills/·프로젝트 .claude/skills/ 안의 SKILL.md 를 추가/수정/삭제하면 재시작 없이 현재 세션에 반영된다. 단, 세션 시작 시 없던 최상위 스킬 디렉터리를 새로 만들면 재시작이 필요하다.

    4. SKILL.md 작성 기본

    SKILL.md 는 (1) --- 로 감싼 YAML 프론트매터와 (2) 그 아래 마크다운 본문, 두 부분이다. 가장 작은 예:

    ---
description: Summarizes uncommitted changes and flags anything risky. Use when the user asks what changed, wants a commit message, or asks to review their diff.
---

## Current changes

!`git diff HEAD`

## Instructions

Summarize the changes above in two or three bullet points, then list any risks
you notice such as missing error handling, hardcoded values, or tests that need
updating. If the diff is empty, say there are no uncommitted changes.

    본문은 짧게. 스킬이 한 번 로드되면 그 내용은 세션 내내 컨텍스트에 남는다(아래 라이프사이클 참고). 줄마다 반복 토큰 비용이 든다는 뜻이다. "왜/어떻게"를 서술하기보다 무엇을 하라를 명령형으로 적고, SKILL.md 본문은 500줄 이하로 유지하자. 길어지는 레퍼런스는 별도 파일로 빼서 점진적 공개를 살린다.

    5. 프론트매터 전체 레퍼런스 ⭐

    여기가 이 글의 핵심이다. 모든 필드는 선택이며, Claude가 언제 쓸지 알도록 description 만 권장된다. 아래는 Claude Code가 인식하는 프론트매터 필드 전부다.

    5.1 한눈에 보는 표

    필드 필수 타입 기본값 역할
    name No string 디렉터리 이름 스킬 목록에 표시되는 display name
    description 권장 string 본문 첫 문단 무엇을·언제 쓰는지. 자동 호출 판단의 핵심
    when_to_use No string — 트리거 문구·예시 요청 등 추가 컨텍스트. description 뒤에 붙음
    argument-hint No string — 자동완성에 뜨는 인자 힌트. 예: [issue-number]
    arguments No string | list — $name 치환용 named positional 인자
    disable-model-invocation No bool false true 면 Claude 자동 로드 차단 (수동 /name 만)
    user-invocable No bool true false 면 / 메뉴에서 숨김 (Claude 자동 호출은 가능)
    allowed-tools No string | list — 스킬 활성 동안 승인 없이 쓸 도구(사전승인)
    disallowed-tools No string | list — 활성 동안 도구 풀에서 제거
    model No string 세션 모델 활성 동안 모델 오버라이드(턴 한정)
    effort No enum 세션 effort 추론 강도: low/medium/high/xhigh/max
    context No string — fork 면 분리된 서브에이전트 컨텍스트에서 실행
    agent No string general-purpose context: fork 시 사용할 서브에이전트 타입
    hooks No map — 이 스킬 라이프사이클에 스코프된 훅
    paths No string | list — 자동 활성화를 제한하는 glob 패턴
    shell No enum bash 인라인 셸 실행기: bash 또는 powershell

    5.2 필드별 상세

    name — 표시 이름(호출 이름이 아님) 스킬 목록에 보이는 라벨이다. 생략하면 디렉터리 이름을 쓴다. 주의할 점: / 뒤에 입력하는 호출 커맨드 이름은 name이 아니라 디렉터리에서 온다. .claude/skills/deploy-staging/SKILL.md → /deploy-staging. 유일한 예외는 플러그인 루트 SKILL.md 로, 디렉터리가 없으니 이때만 name 이 호출 이름이 된다.

    오픈 표준/API 차원의 name 제약(여러 surface에서 통용되게 하려면 지키는 게 안전):

    • 최대 64자
    • 소문자·숫자·하이픈만
    • XML 태그 불가
    • 예약어 anthropic, claude 불가

    description — 가장 중요한 한 줄 스킬이 무엇을 하고 언제 써야 하는지를 적는다. Claude는 이 텍스트로 자동 호출 여부를 판단하므로, 사용자가 자연스럽게 말할 키워드를 담아야 한다. 생략하면 본문 첫 문단이 쓰인다.

    길이에 두 가지 기준이 있어 헷갈리기 쉽다:

    • 오픈 표준/Claude API: description 단일 최대 1,024자, 비어 있으면 안 되고 XML 태그 불가.
    • Claude Code 목록 표시: description + when_to_use 합산 1,536자에서 잘림(컨텍스트 절약용). 핵심 use case를 앞에 둘 것. 이 cap은 maxSkillDescriptionChars 로 조정 가능.

    when_to_use — 트리거 보강 "이런 문구가 나오면 발동" 같은 추가 신호를 적는다. description 뒤에 이어 붙고 위의 1,536자 cap에 함께 포함된다.

    argument-hint / arguments — 인자 argument-hint 는 자동완성 UX용 힌트일 뿐 동작에 영향이 없다([filename] [format]). arguments 는 본문에서 $name 으로 꺼내 쓸 named positional 인자를 선언한다(공백 구분 문자열 또는 YAML 리스트, 순서대로 위치에 매핑). 한마디로 위치 인자($0, $1)에 의미 있는 별칭을 다는 기능이다.

    ---
name: fix-issue
description: Fix a GitHub issue on a branch
arguments: [issue, branch]
---

Fix GitHub issue $issue on the $branch branch.

    arguments: [issue, branch] → 첫 인자 = $issue, 둘째 = $branch. /fix-issue 123 hotfix 호출 시 $issue=123, $branch=hotfix 로 치환된다. $0/$1 보다 본문이 훨씬 읽기 쉬워진다. 자세한 미스매치 동작은 §7.1 참고.

    disable-model-invocation vs user-invocable — 호출 주체 제어 이 둘이 자주 헷갈린다. 기본은 "Claude도, 사용자도" 모두 호출 가능이다.

    프론트매터 사용자 호출 Claude 호출 컨텍스트 로드
    (기본) ✅ ✅ description 상시 + 호출 시 전체
    disable-model-invocation: true ✅ ❌ description 미포함, 내가 호출할 때만 전체
    user-invocable: false ❌ ✅ description 상시 + 호출 시 전체
    • disable-model-invocation: true → 부수효과 있는 작업(/commit, /deploy, /send-slack-message 등)에. "코드가 준비된 것 같다"고 Claude가 멋대로 배포하면 곤란하니까. 서브에이전트 preload도 막는다.
    • user-invocable: false → 사용자가 직접 부를 일은 없지만 Claude는 알아야 하는 배경 지식(예: 레거시 시스템 설명)에.

    allowed-tools — 제한이 아니라 사전승인 헷갈리기 쉬운데, 이건 도구를 제한하는 게 아니다. 스킬이 활성인 동안 나열된 도구를 승인 프롬프트 없이 쓰게 해줄 뿐, 나머지 도구도 여전히 호출 가능하고 평소 권한 설정이 적용된다. 공백/쉼표 구분 문자열 또는 YAML 리스트.

    allowed-tools: Bash(git add *) Bash(git commit *) Bash(git status *)

    프로젝트 .claude/skills/ 에 체크인된 스킬은 워크스페이스 신뢰 다이얼로그를 수락한 뒤에 적용된다. 스킬이 스스로 광범위한 도구 접근을 부여할 수 있으니 신뢰 전에 검토하자.

    disallowed-tools — 풀에서 제거 반대로 활성 동안 특정 도구를 아예 빼버린다. 백그라운드 루프 스킬이 AskUserQuestion 같은 걸 절대 못 부르게 할 때 유용. 다음 메시지를 보내면 해제된다.

    model / effort — 모델·추론 강도 오버라이드

    • model: 스킬 활성 동안 모델을 바꾼다. 현재 턴 한정이고 설정에 저장되지 않으며, 다음 프롬프트엔 세션 모델로 복귀. /model 과 같은 값 또는 inherit.
    • effort: low/medium/high/xhigh/max. 세션 effort를 덮어쓴다. 모델별로 가용 레벨이 다르다.

    context: fork / agent — 서브에이전트로 격리 실행 context: fork 를 주면 스킬이 분리된 컨텍스트의 서브에이전트에서 돈다. SKILL.md 본문이 그 서브에이전트의 프롬프트가 되며, 대화 히스토리에 접근하지 않는다. 그래서 fork는 "가이드라인"만 든 스킬엔 의미가 없고, 실행할 작업이 명시된 스킬에만 맞는다. agent 로 실행 환경(모델·도구·권한)을 정한다. 빌트인 Explore/Plan/general-purpose 또는 .claude/agents/ 의 커스텀 에이전트. 생략 시 general-purpose. (참고: Explore/Plan 은 CLAUDE.md·git status를 건너뛰어 컨텍스트를 작게 유지한다.)

    hooks — 스킬 스코프 훅 이 스킬의 라이프사이클에 묶이는 훅을 정의한다(설정 형식은 Hooks 문서 참조).

    paths — 활성화 범위 제한 glob 패턴을 주면, 그 패턴에 매칭되는 파일을 다룰 때만 스킬이 자동 로드된다(쉼표 구분 문자열 또는 YAML 리스트). path-specific 규칙과 같은 형식.

    shell — 인라인 셸 실행기 본문의 !`command` 와 ` ```! ` 블록을 어떤 셸로 실행할지. bash(기본) 또는 powershell. PowerShell은 Windows에서 CLAUDE_CODE_USE_POWERSHELL_TOOL=1 가 필요하다.

    6. 호출 방식과 권한

    • 자동(모델 주도): 요청이 description 과 맞으면 Claude가 알아서 로드.
    • 수동(사용자 주도): /skill-name. user-invocable: false 가 아니면 항상 가능.
    • 서브에이전트: context: fork 시 격리 컨텍스트에서 실행 후 결과만 본 대화로 회수.

    권한 쪽에서 Claude가 부를 수 있는 스킬을 통제하는 방법은 세 가지다.

    # 모든 스킬 끄기 — deny 규칙에 추가
Skill

# 특정 스킬만 허용/거부
Skill(commit)
Skill(review-pr *)
Skill(deploy *)   # deny

    Skill(name) 은 정확 매칭, Skill(name *) 은 인자 포함 prefix 매칭. 개별 스킬을 Claude 컨텍스트에서 완전히 빼려면 disable-model-invocation: true. (user-invocable 은 메뉴 가시성만 다루지 Skill 도구 접근을 막지 않는다는 점 주의.)

    7. 동적 컨텍스트 주입과 문자열 치환

    스킬 본문은 정적 텍스트만이 아니다.

    !`<command>` — 셸 출력 인라인 주입. 스킬 내용이 Claude에게 가기 전에 명령을 실행해 출력으로 치환한다. Claude는 명령이 아니라 결과(실데이터)를 본다. 전처리이지 Claude가 실행하는 게 아니다. 줄 맨 앞이나 공백 뒤의 ! 만 인식한다. 여러 줄은 ` ```! ` 펜스 블록을 쓴다.

    ---
name: pr-summary
description: Summarize changes in a pull request
context: fork
agent: Explore
allowed-tools: Bash(gh *)
---

## Pull request context
- PR diff: !`gh pr diff`
- PR comments: !`gh pr view --comments`
- Changed files: !`gh pr diff --name-only`

## Your task
Summarize this pull request...

    문자열 치환 변수:

    변수 의미
    $ARGUMENTS 호출 시 넘긴 인자 전체
    $ARGUMENTS[N] / $N 0-기반 인덱스로 개별 인자 ($0, $1 …)
    $name arguments 로 선언한 named 인자
    ${CLAUDE_SESSION_ID} 현재 세션 ID(로깅·세션별 파일에)
    ${CLAUDE_EFFORT} 현재 effort 레벨
    ${CLAUDE_SKILL_DIR} 이 SKILL.md 가 있는 디렉터리(번들 스크립트 경로에)

    7.1 인자 미스매치는 "막히지 않는다"

    가장 중요한 멘탈 모델: 인자는 검증·강제되지 않는다. 스킬 호출은 함수 호출(타입·개수 체크)이 아니라 프롬프트 텍스트 치환이다. 그래서 선언한 인자를 안 맞춰도 호출이 거부되거나 에러로 끊기지 않고, 있는 값으로 치환한 뒤 나머지는 Claude(모델)가 읽고 판단한다.

    상황 결과
    인자를 아예 안 넘김 $issue·$ARGUMENTS 등이 빈 자리로 치환됨. 막히지 않고 그대로 실행 → 모델이 되묻거나 추정
    인자는 넘겼는데 본문에 placeholder 없음 Claude Code가 내용 끝에 ARGUMENTS: <입력> 을 자동으로 덧붙여 모델이 어쨌든 보게 함(입력이 사라지지 않음)
    선언보다 적게 넘김 매핑 안 된 이름은 채울 값이 없어 빈 자리. 부족분의 정확한 치환 동작은 공식 문서에 명시되어 있지 않다
    선언보다 많이 넘김 남는 인자는 이름엔 매핑 안 되지만 $ARGUMENTS(원문 전체)에는 그대로 포함됨

    실무 함정 — 공백/따옴표. $0, $1 같은 위치 인자는 셸 스타일 따옴표를 쓴다. /migrate-component hello world React 처럼 띄어쓰면 $0=hello, $1=world 로 갈라져 "한 개 의도였는데 두 개로 잡히는" 미스매치가 난다. 여러 단어를 한 인자로 넘기려면 "hello world" 로 묶어야 한다. 반면 $ARGUMENTS 는 항상 입력 원문 전체로 확장된다.

    그래서 권장 패턴 — 누락을 본문 지시문으로 방어한다. 검증이 없으니, 인자가 없을 때의 행동을 직접 적어 두는 게 정석이다.

    ---
name: fix-issue
description: Fix a GitHub issue
arguments: [issue]
---

Fix GitHub issue $issue.
If no issue number was provided, ask the user which issue to fix before proceeding.

    이러면 인자를 안 맞춰도 모델이 막무가내로 진행하지 않고 되묻는다(§4의 summarize-changes 예시 "If the diff is empty, say there are no uncommitted changes" 도 같은 방어 패턴이다). 정리하면 인자 미스매치는 "차단"이 아니라 "빈 값 / 원문 fallback"으로 흐르고, 최종 안전망은 본문 지시문이다.

    8. 라이프사이클 — 한 번 로드되면 계속 남는다

    스킬을 호출하면 렌더된 SKILL.md 내용이 대화에 메시지 하나로 들어가 세션 내내 유지된다. Claude Code는 이후 턴에서 파일을 다시 읽지 않는다. 그래서 "작업 내내 적용돼야 할 지침"은 일회성 단계가 아니라 상시 지시문으로 써야 한다.

    자동 compaction이 일어나면 호출했던 스킬을 토큰 예산 안에서 다시 붙인다(각 스킬 최근 호출분의 첫 5,000토큰, 합산 25,000토큰 예산, 최근 호출 우선). 한 세션에서 여러 스킬을 부르면 오래된 건 compaction 후 떨어질 수 있다 — 필요하면 다시 호출하자.

    9. 실전 예제

    (A) 레퍼런스형 — 인라인 지식 (자동 호출 환영)

When writing API endpoints:
- Use RESTful naming conventions
- Return consistent error formats
- Include request validation

    10. 작성 팁 & 흔한 함정

    • description 에 사용자가 진짜 말할 키워드를 넣어라. 트리거 정확도가 여기서 갈린다. 너무 자주 발동하면 더 구체적으로, 안 발동하면 키워드 보강.
    • 본문은 짧게, 긴 자료는 별도 파일로. 점진적 공개를 살리는 핵심.
    • 부수효과 있는 작업엔 disable-model-invocation: true.
    • /doctor 로 description이 잘리거나 드롭됐는지 확인 가능. 스킬이 많아 예산이 넘치면 안 쓰는 스킬부터 잘린다(skillOverrides 로 "name-only" 처리해 예산 확보).
    • 신뢰 가능한 출처의 스킬만. 스킬은 지시+코드로 Claude에 새 능력을 주므로, 악성 스킬은 데이터 유출·무단 접근으로 이어질 수 있다. 외부 스킬은 SKILL.md·스크립트·리소스를 전부 감사한 뒤 쓰자.
