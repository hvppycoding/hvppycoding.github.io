    HyperRun(hrun) 관리자 가이드 — 글로벌 툴 추가

    사용자 가이드가 "내 데이터 디렉터리에서 도구를 쓰는" 관점이라면, 이 글은 시스템 관리자가 네트워크 루트에 글로벌 툴을 추가·배포하는 관점이다.

    큰 그림

    관리자가 만지는 곳은 셋이다.

    1. 툴킷(toolkit)     toolkits/<tool>/        ← 래퍼·env·desc·docs (대부분 여기)
2. 네트워크 루트     $HYPERRUN_ROOT          ← 버전별 배포 + current 심볼릭
3. 시스템 커맨드     $HYPERRUN_ROOT/commands ← 사용자에게 노출되는 이름 등록

    C++ 라우터(hrun)는 네트워크 A/B 경로가 바뀔 때만 다시 빌드한다. 도구 추가에는 보통 안 건드린다.

    1. 툴킷 구조

    toolkits/<tool>/
  VERSION
  commands/<command>          # 실행 가능한 래퍼 (chmod 755)
  desc/<command>.desc         # 한 줄 설명 (list에 표시)
  env/<tool>.env              # 사이트 기본 환경값
  docs/commands/<command>.md  # 커맨드 문서
  docs/README.md
  docs/env.md

    mycli-template/을 복사해 시작하는 게 가장 빠르다.

    2. 래퍼 작성법

    래퍼는 core가 호출하며, lib 함수를 source 해서 도구 컨텍스트를 잡고 실제 실행 파일로 exec 한다.

    #!/bin/sh
set -eu

if [ -z "${HYPERRUN_CORE:-}" ]; then
    echo "mytool wrapper must be invoked by HyperRun core" >&2
    exit 2
fi

. "$HYPERRUN_CORE/lib/common.sh"
. "$HYPERRUN_CORE/lib/env.sh"
. "$HYPERRUN_CORE/lib/platform.sh"
. "$HYPERRUN_CORE/lib/tool.sh"

# 툴 진입: HYPERRUN_TOOL_ID / HYPERRUN_TOOL_HOME 설정 + 홈 lazy 생성
hrun_enter_tool mytool mytool

# 사이트 기본 env → 사용자 override 순으로 로딩
hrun_load_env_file "$HYPERRUN_ROOT/toolkits/mytool/current/env/mytool.env"
hrun_load_env_file "$HYPERRUN_DATA_DIR/env/tools/mytool.env"
hrun_detect_platform

MYTOOL_EXE=${HYPERRUN_MYTOOL_EXE:-}

# 내장 진단 연동 (which/env/docs/list가 이 분기를 호출)
case "${HYPERRUN_INSPECT:-}" in
    which)    printf '%s\n' "${MYTOOL_EXE:-not configured}"; exit 0 ;;
    env)      printf 'HYPERRUN_TOOL_HOME=%s\n' "$HYPERRUN_TOOL_HOME"; exit 0 ;;
    describe) echo "My internal tool"; exit 0 ;;
    docs)     printf '%s\n' "$HYPERRUN_ROOT/toolkits/mytool/current/docs/commands/mytool.md"; exit 0 ;;
esac

[ -n "$MYTOOL_EXE" ] || hrun_die 127 "HYPERRUN_MYTOOL_EXE not set; configure env/tools/mytool.env"
hrun_ensure_executable "$MYTOOL_EXE"
exec "$MYTOOL_EXE" "$@"

    체크리스트:

    • hrun_enter_tool <tool_id> [command_name]를 먼저 호출 (이게 HYPERRUN_TOOL_HOME을 만든다).
    • 도구 고유 HOME 변수는 env/<tool>.env에서 MYTOOL_HOME=${HYPERRUN_TOOL_HOME}처럼 매핑.
    • HYPERRUN_INSPECT 4분기(which/env/describe/docs)를 처리하면 hrun which/env/docs/list와 매끄럽게 연동.
    • 인자는 항상 "$@"로 보존.

    3. 한 도구에 여러 커맨드

    python/pip처럼 한 도구가 여러 진입점을 가지면 같은 tool_id를 줘서 tool home을 공유한다.

    hrun_enter_tool python pip   # tool_id=python, command_name=pip → tools/python 공유

    4. desc / docs / env 규칙

    • desc: desc/<command>.desc의 첫 줄이 hrun list 설명. 순서 사용자 → 시스템 → 래퍼 describe → "-".
    • docs: hrun docs <command>로 출력. 순서 사용자 → 시스템 → 래퍼 docs.
    • env: 안전 파서. KEY=value, ${VAR}, ${VAR:-default}, 따옴표만 허용. $(...)·백틱·$VAR 거부.

    5. 배포: 버전 디렉터리 + current 심볼릭

    sh packaging/install-network.sh \
  --runner-path /user/aegis/RELEASE/bin/run_hrun \
  --root        /user/aegis/RELEASE/apps/hrun \
  --version     v0.2.0

    하는 일:

    • scripts/run_hrun를 --runner-path에 설치 (= HYPERRUN_RUNNER; 얇은 패스스루)
    • core를 core/releases/<version>에 복사하고 core/current 심볼릭 갱신
    • python 툴킷을 toolkits/python/releases/<version>에 복사하고 current 갱신
    • 시스템 env 파일 보장 + sync-system-commands.sh로 시스템 커맨드 링크

    배포는 버전 보관 + 심볼릭 전환이라 롤백이 심볼릭 변경 한 번이다.

    $HYPERRUN_ROOT/core/current            -> releases/v0.2.0
$HYPERRUN_ROOT/toolkits/python/current -> releases/v0.2.0

    주의: 기본 install-network.sh는 python 툴킷만 복사한다. 새 툴킷(mytool)은 같은 패턴(releases 복사 + current 심볼릭)을 스크립트에 더해 배포해야 한다.

    6. 시스템 커맨드 등록

    툴킷을 배포해도, 사용자에게 노출되려면 $HYPERRUN_ROOT/commands/<name> 링크가 있어야 한다.

    sh packaging/sync-system-commands.sh --root "$HYPERRUN_ROOT" --manifest commands.tsv

    manifest는 TAB 구분 4열이다.

    command<TAB>command-target<TAB>desc-target<TAB>docs-target

    예 (mytool 등록, 경로는 $HYPERRUN_ROOT/commands 기준 상대 심볼릭):

    mytool	../toolkits/mytool/current/commands/mytool	../toolkits/mytool/current/desc/mytool.desc	../../toolkits/mytool/current/docs/commands/mytool.md

    manifest를 안 주면 python/pip 기본 링크만 만든다. 기존 비-심볼릭 파일은 덮어쓰지 않는다(안전장치).

    7. C++ 라우터 빌드 (네트워크 경로가 바뀔 때만)

    A/B 경로·API 기본값·공유 데이터 루트는 컴파일 상수다.

    make build \
  HYPERRUN_RUNNER_A=/user/aegis/RELEASE/bin/run_hrun \
  HYPERRUN_ROOT_A=/user/aegis/RELEASE/apps/hrun \
  HYPERRUN_API_KEY_A=... \
  HYPERRUN_BASE_URL_A=https://api-a.example/v1 \
  HYPERRUN_SHARED_DATA_ROOT_A=/user/aegis/RELEASE/userdata \
  HYPERRUN_RUNNER_B=/user/llmsol00/RELEASE/bin/run_hrun \
  HYPERRUN_ROOT_B=/user/llmsol00/RELEASE/apps/hrun

sudo make install-hrun      # /appl/bin/hrun 에 설치

    RHEL7 배포는 STATIC_LIBS=1로 -static-libstdc++ -static-libgcc를 붙일 수 있다. A/B 경로 하드코딩은 오직 이 C++ 빌드 상수에서만 한다. 바이너리는 실행 전용 권한으로 두면 사용자가 컴파일된 API_KEY를 읽지 못한다.

    컴파일된 HYPERRUN_API_KEY_A/B·HYPERRUN_BASE_URL_A/B는 선택된 네트워크에 따라 런타임에 HYPERRUN_API_KEY / HYPERRUN_BASE_URL 로 환경에 주입되어, 래퍼·도구가 별도 설정 없이 그대로 읽을 수 있다(값이 비어 있으면 주입 안 함).

    공유 데이터 루트 (선택)

    HYPERRUN_SHARED_DATA_ROOT_A/B를 컴파일하면, 그 네트워크 사용자 데이터가 ~/.hrun 대신 공유 트리 아래 사용자별로 모이고, ~/.hrun은 거기로 링크된다.

    HYPERRUN_SHARED_DATA_ROOT_A=/user/aegis/RELEASE/userdata
  -> HYPERRUN_DATA_DIR = .../userdata/<user>/.hrun   (실폴더)
  -> ~/.hrun           -> .../userdata/<user>/.hrun   (심볼릭)
    • 사용자명은 id -un(euid 기반, $USER 변조 무관), 홈(~)은 getent passwd(없으면 $HOME). 심볼릭은 릴리스 run_hrun이 만들고(폴더 생성 + 링크 + stat 확인 + sync), hrun-core는 그냥 항상 ~/.hrun을 쓴다.
    • 실폴더는 공유 경로이고 ~/.hrun은 거기로 best-effort 심볼릭(실패해도 동작, 기존 실디렉터리 ~/.hrun은 절대 덮어쓰지 않고 경고).
    • 비워 두면(기본값) ~/.hrun 자체가 데이터 폴더(심볼릭 없음). 사용자가 HYPERRUN_DATA_DIR을 직접 주면 항상 그게 우선.
    • 권한은 기본 umask(강제 모드 없음).

    8. 검증

    make test
sh packaging/smoke.sh

# 배포 후
hrun doctor
hrun list
hrun which mytool
hrun env mytool
hrun docs mytool
hrun mytool --help

    보안 규칙 요약

    • A/B 경로는 C++ 빌드 상수 밖에서 하드코딩하지 않는다.
    • 데이터 루트용 별도 사용자 config 파일을 만들지 않는다($HOME/.hrun 또는 공유 루트 사용).
    • eval, system(...), popen, 셸 문자열 실행 금지.
    • 사용자 env 파일을 source 하지 않는다(안전 파서만).
    • 인자는 "$@"로 보존하고 command/profile/tool 이름을 검증한다.
    • 도구 쓰기 상태는 HYPERRUN_TOOL_HOME만 사용한다.
