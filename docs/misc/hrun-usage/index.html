    HyperRun(hrun) 사용법

    hrun은 폐쇄망(내부망)에서 도구·런타임·환경을 라우팅해주는 작은 런처다. 사용자는 네트워크(A/B)나 설치 경로를 신경 쓰지 않고 hrun <command> 한 줄로 내부 도구를 실행한다.

    hrun python -V
hrun pip list
hrun mycli a b c

    hrun은 보이는 네트워크 러너를 고르고, 공통 디스패치 레이어를 거쳐, 요청한 도구의 래퍼를 실행한다.

    기본 사용

    hrun <command> [args...]
    • <command> 는 등록된 내부 도구 이름(python, pip, mycli 등).
    • 뒤에 오는 인자는 그대로 실제 도구로 전달된다.

    명령 탐색 순서는 사용자 우선이다.

    1. $HYPERRUN_DATA_DIR/commands/<command>   (사용자)
2. $HYPERRUN_ROOT/commands/<command>       (시스템)

    즉 같은 이름이면 사용자 커맨드가 시스템 커맨드를 덮어쓴다.

    내장 커맨드

    hrun help                 # 사용법
hrun version              # core 버전
hrun doctor               # 진단 정보(네트워크/경로/플랫폼)
hrun config               # 데이터 디렉터리 경로와 존재 여부
hrun list                 # 사용 가능한 커맨드 목록
hrun which <command>      # 실제 실행 파일 경로
hrun env <command>        # 그 커맨드의 환경 컨텍스트
hrun docs [--path] <command>   # 커맨드 문서 출력(또는 경로만)

    list 출력 예

    COMMAND   SOURCE   DESCRIPTION
python    system   Company Python runtime
pip       system   ...
mycli     user     ...

    doctor

    네트워크 선택 결과와 경로, 플랫폼을 보여준다. 환경이 꼬였을 때 가장 먼저 확인할 것.

    hrun doctor

    config

    데이터 디렉터리 후보와 존재 여부만 출력하며, 디렉터리를 만들지는 않는다. 실제 생성은 일반 커맨드를 실행할 때 일어난다.

    $ hrun config
data_dir=/home/me/.hrun
data_dir_exists=yes

    프로파일

    기본 프로파일은 user다. 다른 프로파일로 실행하려면:

    hrun --profile agent python job.py

    프로파일은 환경변수 파일 로딩에 영향을 준다. 로드 순서:

    $HYPERRUN_ROOT/env/global.env
$HYPERRUN_DATA_DIR/env/global.env
$HYPERRUN_ROOT/env/profiles/<profile>.env
$HYPERRUN_DATA_DIR/env/profiles/<profile>.env

    환경변수 파일

    env 파일은 셸이 source 하지 않고 HyperRun이 직접 안전하게 파싱한다. 지원 형식:

    KEY=value
KEY="value with space"
KEY='literal value'        # 작은따옴표는 확장 안 함
export KEY=value
KEY=${OTHER}/suffix
KEY=${OTHER:-default}
# 주석

    $VAR, $(cmd), 백틱, 산술 확장 등은 거부된다. :-default 없는 미정의 ${VAR}도 에러라, 오타를 일찍 잡아준다.

    데이터 디렉터리와 툴 홈

    사용자 데이터 루트(HYPERRUN_DATA_DIR)는 다음 순서로 결정된다.

    1. 절대경로로 지정된 HYPERRUN_DATA_DIR
2. HYPERRUN_DEFAULT_DATA_DIR
3. HYPERRUN_SHARED_DATA_ROOT/<user>/.hrun   (관리자가 컴파일로 켰을 때만)
4. $HOME/.hrun

    관리자가 공유 데이터 루트(HYPERRUN_SHARED_DATA_ROOT)를 켜 둔 사이트라면, 데이터가 공유 트리 아래 사용자별로 <root>/<user>/.hrun에 모이고, ~/.hrun은 거기를 가리키는 편의 심볼릭 링크로 만들어진다(기존 실디렉터리는 건드리지 않음). 명시적으로 HYPERRUN_DATA_DIR을 주면 항상 그게 우선이라 언제든 빠져나올 수 있다.

    도구가 쓰기 가능한 공간이 필요하면 툴 홈을 쓴다.

    HYPERRUN_TOOL_HOME = $HYPERRUN_DATA_DIR/tools/<tool_id>
    • 래퍼가 도구로 진입할 때 lazy 생성된다(미리 만들지 않음).
    • pip과 python처럼 한 툴에 속한 커맨드는 같은 tool_id를 공유한다 → tools/python 하나를 같이 쓴다.

    도구 자체가 쓰는 HOME 환경변수가 있다면, 그 도구의 env 파일에서 매핑해주면 된다.

    # $HYPERRUN_DATA_DIR/env/tools/<tool>.env
FOO_HOME=${HYPERRUN_TOOL_HOME}
# 하위 경로가 필요하면
AWS_CONFIG_FILE=${HYPERRUN_TOOL_HOME}/config

    주의: ${HYPERRUN_TOOL_HOME} 는 툴 env 파일(env/tools/<tool>.env)에서만 쓸 수 있다. global.env/프로파일 env는 툴 진입 전에 로딩돼서 그 시점엔 값이 없다.

    진단 / 트러블슈팅

    hrun doctor
hrun which <command>
hrun env <command>
HYPERRUN_TRACE=1 hrun <command>   # 선택된 네트워크/러너를 stderr로 출력

    종료 코드 메모:

    • 126 — 러너/실행 파일이 있지만 실행 권한 없음
    • 127 — 러너/커맨드를 찾지 못함
    • 2 — 잘못된 인자·이름, 또는 env 문법 오류
