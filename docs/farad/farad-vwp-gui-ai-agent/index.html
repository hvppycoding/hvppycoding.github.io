    Farad: VWP에서 바로 쓰는 GUI AI Agent 애플리케이션

    Farad 입문 영상에 사용할 최종 내레이션 대본이다. 화면에서는 Farad, 음성에서는 패럿으로 읽는다. 특정 직무에 한정하지 않고 파일 조사, 커맨드 실행, 데이터 분석, 결과 검증처럼 VWP에서 반복되는 일반적인 업무를 기준으로 설명한다.

    실행

    VWP 터미널에서 화면처럼 명령어를 입력하면, 바로 이런 창이 뜹니다.

    이게 Farad, 패럿입니다.

    한 줄로 소개하면, VWP에서 바로 쓰는 GUI AI Agent 애플리케이션입니다.

    겉으로는 채팅창처럼 보이지만, 답변만 주고 끝나는 채팅과는 조금 다릅니다. 현재 업무 폴더의 파일을 직접 확인하고, 필요한 커맨드를 실행하고, 그 결과를 다시 보면서 작업을 이어갈 수 있습니다.

    먼저 왜 이런 형태로 만들었는지부터 짧게 설명하겠습니다.

    개발 배경

    패럿은 여러 코딩 에이전트를 사용해 본 경험에서 시작했습니다.

    제가 터미널 기반 코딩 에이전트를 사용해 보니, 파일을 찾고 코드를 수정하고 테스트를 실행하는 능력은 상당히 좋았습니다. 그런데 작업이 여러 개로 늘어나면 이전 세션을 찾거나, 긴 실행 결과를 다시 읽거나, 중단한 작업을 이어가는 부분은 데스크톱 앱이 확실히 편했고요.

    Codex Desktop이나 Claude Cowork 같은 도구를 보면서, 이 두 가지를 VWP 환경에서도 함께 사용할 수 있으면 좋겠다고 생각했습니다.

    처음부터 저 혼자 쓰려고 만든 건 아닙니다. 다른 분들이 VWP에서 쉽게 쓸 수 있어야 했고, 동시에 만든 저도 실제 업무에서 계속 사용할 수 있어야 했습니다. 직접 사용하지 않으면 작은 불편을 계속 놓치게 되니까요.

    그래서 기능을 정할 때도 설명할 때만 그럴듯한 것보다는, 실제로 자주 꺼내 쓸 기능을 우선했습니다.

    VWP는 여러 사용자가 노드를 공유하고, 사양이 항상 넉넉한 환경도 아닙니다. 그래서 화려하게 움직이는 화면보다 세션을 열고, 긴 대화를 읽고, 결과를 스크롤하는 기본 동작이 가볍게 느껴지도록 신경을 썼습니다.

    일반 채팅과 Agent의 차이

    그럼 일반적인 AI 채팅과 Agent는 무엇이 다를까요.

    예를 들어, 내 컴퓨터에 설치된 Python 버전을 알려달라고 해보겠습니다.

    기존 채팅에서는 Python 버전 확인 커맨드를 알려주고, 사용자에게 직접 실행해 보라고 답할 수 있습니다. 그러면 사람이 터미널로 이동해서 커맨드를 실행하고, 결과를 복사해서 다시 채팅에 넣어야 합니다.

    그런데 저 중간 과정을 꼭 사람이 해야 할까요. 여기서 Agent가 시작됩니다.

    같은 질문을 패럿에 입력하면, LLM이 Python 버전을 확인하기 위한 Bash 실행을 요청합니다. 패럿은 실제 VWP에서 커맨드를 실행하고, 나온 결과를 다시 LLM에게 전달합니다. 그러면 LLM이 실제 결과를 보고 설치된 버전을 답합니다.

    커맨드 하나에서는 작은 차이지만, 여러 파일과 실행 결과를 오가는 작업에서는 이 차이가 꽤 커집니다.

    LLM과 Agent Harness

    여기서 한 가지는 정확히 구분해 두는 게 좋습니다.

    LLM이 직접 파일을 열거나 터미널을 조작하는 것은 아닙니다. LLM은 사용자의 요청과 현재 작업 정보를 보고, 다음에 무엇을 할지 판단합니다.

    파일을 읽어야겠다고 판단하면 읽기 도구를 요청하고, 커맨드가 필요하면 Bash 도구를 요청합니다. 이건 어디까지나 실행 요청입니다.

    실제 실행 주체는 패럿의 Agent Harness입니다. 패럿이 사용할 수 있는 도구와 현재 Working Folder를 관리하고, 실행 전에 권한을 확인한 뒤 도구를 동작시킵니다. 그리고 파일 내용이나 커맨드 출력 같은 실제 결과를 다시 LLM에게 전달합니다.

    LLM은 그 결과를 보고 답변할 수도 있고, 다음 파일을 확인하거나 다른 커맨드를 요청할 수도 있습니다.

    그래서 LLM과 Agent 애플리케이션은 같은 말이 아닙니다. 같은 LLM을 사용하더라도 어떤 도구를 제공하고, 권한을 어떻게 확인하고, 세션 정보를 어떻게 관리하느냐에 따라 실제 사용 경험은 달라집니다.

    정리하면, LLM은 다음 행동을 판단하고, 패럿은 그 행동을 실제 VWP 작업으로 연결합니다. 이 흐름이 필요한 만큼 반복되는 것이 Agent의 기본 동작 방식입니다.

    통계 데이터로 작업해 보기

    이제 준비된 예제 데이터로 실제 흐름을 보겠습니다.

    먼저 /cd로 Working Folder를 지정합니다. Working Folder는 현재 세션에서 패럿이 파일을 찾고 커맨드를 실행할 기준 위치입니다. 작업이 바뀌면 이 위치부터 바꿔주면 됩니다.

    이번 예제는 두 가지 실행 방식의 시간과 메모리 사용량을 기록한 교육용 합성 데이터입니다. 실제 시스템의 성능 수치는 아닙니다.

    처음부터 분석 결론을 달라고 하지 않고, 데이터 상태부터 확인해 보겠습니다. 전체 행 수와 컬럼의 의미, 결측치, 중복, 이상치가 있는지 살펴보되 아직 파일은 수정하지 말라고 요청했습니다.

    패럿은 전체 100건을 확인하고, 메모리 값이 비어 있는 행 1건과 실행 시간이 유난히 긴 이상치 후보 1건을 찾았습니다. 중복 데이터는 없고요.

    이렇게 조사 범위와 수정 여부를 함께 말해주면, 처음 보는 폴더에서도 비교적 안전하게 작업을 시작할 수 있습니다.

    이제 baseline과 optimized 방식을 비교해 보겠습니다.

    실행 시간은 평균만 보지 않고 중앙값과 표준편차를 함께 확인하고, 성공률과 평균 메모리 사용량도 비교하도록 요청했습니다. 평균은 이상치 하나에도 영향을 받을 수 있기 때문에, 분포가 얼마나 일정한지도 같이 보는 겁니다.

    분석을 위해 커맨드 실행이 필요하면 승인 화면이 나타납니다. 패럿이 실행하려는 커맨드와 작업 위치를 보여주기 때문에 내용을 확인한 다음, 이번 한 번만 허용하거나 비슷한 작업을 계속 허용할 수 있습니다.

    결과를 보면 optimized 방식은 실행 시간 중앙값이 약 11% 낮고, 실행 시간의 편차도 작습니다. 성공률은 두 방식이 같고요. 대신 평균 peak memory는 약 8% 더 사용합니다.

    더 빠르고 일정하지만, 메모리 비용은 조금 늘어난 셈입니다. 다만 이 데이터만으로 실행 방식 하나가 모든 차이의 원인이라고 단정할 수는 없습니다.

    이번에는 답변만 받고 끝내지 않고, 같은 분석을 다시 실행할 수 있도록 코드와 보고서로 남겨보겠습니다.

    패럿이 Python 분석 코드를 만들고 실제로 실행한 다음, Markdown 보고서와 비교 그래프를 생성합니다. 마지막에는 생성된 보고서의 숫자가 원본 데이터와 맞는지도 다시 확인합니다.

    코딩을 직접 하지 않더라도, 결과만 받아보는 데서 끝나지 않고 재현 가능한 분석 과정까지 남길 수 있습니다.

    SVG와 세션 관리

    분석 과정 전체를 한눈에 보고 싶다면, 답변 안에 SVG 다이어그램을 만들어 달라고 요청할 수도 있습니다.

    LLM이 원본 데이터, 품질 점검, 방식 비교, 최종 해석의 관계를 SVG 내용으로 만들고, 패럿이 이를 검증한 뒤 채팅 안에서 바로 렌더링합니다.

    여기서 SVG는 Bash처럼 시스템을 실행하는 도구가 아닙니다. LLM이 만든 답변을 패럿이 읽기 쉬운 벡터 그래픽으로 표현하는 기능입니다.

    그리고 패럿을 데스크톱 앱으로 만든 이유 중 하나가 세션 관리입니다.

    실제 업무에서는 분석, 로그 확인, 코드 수정처럼 여러 작업을 번갈아 진행하게 됩니다. 패럿에서는 작업마다 세션을 나눌 수 있고, 대화뿐 아니라 어떤 파일을 읽고 어떤 도구를 실행했는지도 같은 흐름에 남습니다.

    새 작업은 /new나 Ctrl+N으로 시작하고, Ctrl+K를 누르면 이전 세션을 검색해서 바로 이어갈 수 있습니다.

    처음 사용할 때 기억할 것

    /cd는 Working Folder를 바꾸고, 입력 중 @ 기호를 사용하면 특정 파일을 직접 지정할 수 있습니다. Ctrl+K는 세션 검색, Ctrl+N은 새 세션, Ctrl+L은 채팅 입력으로 이동입니다. 진행 중인 작업을 멈추려면 Esc를 누르면 되고, 모델을 바꾸고 싶다면 /model을 사용하면 됩니다.

    처음부터 전부 외울 필요는 없습니다. 사실 처음에는 세 가지만 기억하면 됩니다.

    VWP에서 패럿을 실행하고, /cd로 업무 폴더를 지정하고, 먼저 조사만 부탁해 보는 겁니다.

    이 폴더가 어떤 작업을 위한 곳인지 파악해줘. 아직 파일을 수정하거나 커맨드를 실행하지 말고, 근거가 된 파일과 함께 설명해줘.

    그 결과를 확인한 다음 필요한 커맨드를 실행하거나, 문제의 원인을 찾거나, 분석 결과를 파일로 남기는 작업까지 이어가면 됩니다.

    Agent는 질문에 답만 해주는 채팅이라기보다, 실제 작업 결과를 보고 다음 행동으로 이어주는 도구에 가깝습니다. 처음에는 작은 조사 하나부터 맡겨보면, 패럿이 일하는 방식도 금방 익숙해질 겁니다.
