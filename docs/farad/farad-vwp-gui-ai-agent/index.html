    Farad: VWP에서 바로 쓰는 GUI AI Agent 애플리케이션

    Farad 입문 영상에 사용할 내레이션 대본이다. 화면에서는 Farad, 음성에서는 패럿으로 읽는다. 특정 직무에 한정하지 않고 파일 조사, 커맨드 실행, 데이터 분석, 결과 검증처럼 VWP에서 반복되는 일반적인 업무를 기준으로 설명한다.

    실행

    VWP 터미널에서 화면처럼 명령어를 입력하면 이런 창이 뜹니다.

    이게 Farad, 패럿입니다.

    VWP에서 바로 사용할 수 있는 GUI 형태의 AI Agent 애플리케이션이고요.

    겉으로는 채팅창처럼 보이지만, 질문에 답만 하고 끝나는 채팅과는 조금 다릅니다. 현재 업무 폴더의 파일을 직접 확인하고, 필요한 커맨드를 실행하고, 실제로 나온 결과를 보면서 다음 작업까지 이어갈 수 있습니다.

    먼저 패럿을 왜 이런 형태로 만들었는지 짧게 말씀드리고, Agent가 어떤 방식으로 일하는지 예제와 함께 보여드리겠습니다.

    개발 배경

    패럿의 출발점은 터미널 기반 코딩 Agent였습니다.

    직접 사용해 보니 파일을 찾고, 코드를 수정하고, 테스트를 실행하는 능력은 상당히 좋았습니다. 다만 작업이 여러 개로 늘어나면 예전 세션을 다시 찾거나, 긴 실행 결과를 읽거나, 중단한 작업을 이어가는 부분은 데스크톱 앱이 훨씬 편했고요.

    Codex Desktop이나 Claude Cowork 같은 도구를 보면서, 이런 GUI 형태의 AI Agent가 VWP에도 있으면 좋겠다는 생각에서 개발을 시작했습니다.

    누구나 쉽게 쓸 수 있게 만들되, 저도 실제 업무에서 계속 사용해 보고 있고요. 쓰면서 발견한 불편한 부분은 하나씩 고쳐가고 있습니다.

    기본적인 코딩 작업은 물론이고, 꼭 코드를 다루지 않더라도 파일 조사나 로그 확인, 데이터 분석, 문서 정리 같은 일에도 사용할 수 있게 만들고 있습니다.

    VWP는 여러 사용자가 노드를 공유하고, 사양이 항상 넉넉한 환경도 아닙니다. 그래서 화려한 효과보다는 세션을 열고, 긴 대화를 읽고, 결과를 스크롤하는 기본 동작이 가볍게 느껴지는 쪽에 더 신경을 썼습니다.

    일반 채팅과 Agent의 차이

    Agent라는 말이 조금 생소할 수 있어서, 간단한 예를 하나 들어보겠습니다.

    AI에게 내 컴퓨터에 설치된 Python 버전을 알려달라고 해보겠습니다.

    일반적인 채팅이라면 Python 버전을 확인하는 커맨드를 알려주고, 직접 실행해 보라고 답할 수 있습니다. 그러면 사용자가 터미널로 이동해서 커맨드를 실행하고, 나온 결과를 다시 채팅에 전달해야 합니다.

    Agent는 이 중간 과정을 이어서 처리합니다.

    같은 질문을 패럿에 입력하면, LLM이 Python 버전을 확인하기 위한 Bash 실행을 요청합니다. 패럿은 실제 VWP 환경에서 커맨드를 실행하고, 나온 결과를 다시 LLM에게 전달합니다. 그러면 LLM은 실제 결과를 보고 설치된 버전을 알려줍니다.

    커맨드 하나에서는 큰 차이가 없어 보이지만, 여러 파일을 확인하고 실행 결과에 따라 다음 행동을 골라야 하는 작업에서는 이 차이가 꽤 커집니다.

    LLM과 Agent Harness

    여기서 많이 헷갈리는 부분이 하나 있습니다.

    LLM이 직접 파일을 열거나 터미널을 조작하는 것은 아닙니다. LLM은 사용자의 요청과 현재 작업 정보를 보고, 다음에 무엇을 해야 할지 판단합니다.

    파일 내용이 필요하면 읽기 도구를 요청하고, 커맨드를 실행해야 하면 Bash 도구를 요청합니다. 말 그대로 도구를 사용해 달라는 요청을 만드는 겁니다.

    그 요청을 실제 작업으로 바꾸는 프로그램이 패럿의 Agent Harness입니다. 패럿이 현재 Working Folder와 사용할 수 있는 도구를 관리하고, 필요한 경우 사용자에게 권한을 확인한 뒤 실제로 실행합니다. 그리고 파일 내용이나 커맨드 출력처럼 실행해서 얻은 결과를 다시 LLM에게 전달합니다.

    LLM은 그 결과를 보고 답변할 수도 있고, 다른 파일을 확인하거나 다음 커맨드를 요청할 수도 있습니다.

    그래서 LLM과 Agent 애플리케이션은 같은 개념이 아닙니다. 같은 LLM을 사용하더라도 어떤 도구를 연결하고, 권한을 어떻게 확인하고, 작업 정보를 어떻게 관리하느냐에 따라 실제 사용 방식은 달라집니다.

    간단히 말하면, LLM은 다음 행동을 판단하고 패럿은 그 판단을 실제 VWP 작업으로 연결합니다. 그리고 실행 결과가 다시 LLM에게 돌아가면서 이 과정이 필요한 만큼 반복됩니다.

    통계 데이터로 작업해 보기

    이제 준비된 예제 데이터로 실제 작업 흐름을 보겠습니다.

    입력창에서 /를 누르면 사용할 수 있는 명령 목록이 열립니다. 가장 자주 사용하는 /cd를 첫 번째에 두었기 때문에, 방향키로 선택하고 Enter만 눌러도 최근에 사용한 폴더를 고를 수 있습니다.

    이동할 경로를 알고 있다면 /cd를 직접 입력해도 됩니다. 경로를 입력하기 시작하면 폴더가 자동으로 완성되기 때문에 긴 경로를 전부 타이핑할 필요는 없습니다.

    여기서 지정한 Working Folder가 현재 세션에서 패럿이 파일을 찾고 커맨드를 실행할 기준 위치가 됩니다.

    이미 실행할 커맨드를 알고 있다면 입력 맨 앞에 !를 붙여서 바로 실행할 수도 있습니다. 예를 들어 !pwd를 입력하면 현재 작업 경로를 바로 확인할 수 있습니다. 이건 LLM에게 작업을 부탁하는 것이 아니라, 사용자가 커맨드를 직접 실행하는 빠른 방법입니다.

    이번 예제는 두 가지 실행 방식의 시간과 메모리 사용량을 기록한 교육용 합성 데이터입니다. 실제 시스템의 성능 수치는 아닙니다.

    분석할 파일은 @ 기호로 지정하겠습니다. @를 입력하고 파일 이름을 몇 글자 치면 Working Folder 안의 파일을 찾아주기 때문에, 여기서 CSV 파일을 선택하면 됩니다.

    처음부터 결론을 내달라고 하기보다는 데이터 상태부터 확인해 보겠습니다. 선택한 파일의 전체 행 수와 컬럼의 의미를 정리하고, 결측치나 중복, 눈에 띄는 이상치가 있는지 살펴봐 달라고 요청했습니다. 아직 파일은 만들거나 수정하지 말라는 조건도 같이 넣었고요.

    확인 결과 전체 100건 중에 메모리 값이 비어 있는 행이 1건 있었고, 실행 시간이 유난히 긴 이상치 후보도 1건 있었습니다. 중복 데이터는 없었습니다.

    이런 식으로 조사할 범위와 수정 여부를 같이 알려주면, 처음 보는 폴더에서도 부담 없이 시작할 수 있습니다.

    데이터 상태를 확인했으니, 이제 baseline과 optimized 방식을 비교해 보겠습니다.

    실행 시간은 평균만 보지 않고 중앙값과 표준편차도 함께 확인하고, 성공률과 평균 메모리 사용량까지 비교해 달라고 요청했습니다. 이상치가 하나 있기 때문에 평균만 보면 결과가 조금 다르게 보일 수 있거든요.

    분석 과정에서 커맨드 실행이 필요하면 승인 화면이 나타납니다. 패럿이 어떤 커맨드를 어느 폴더에서 실행하려는지 보여주기 때문에, 내용을 확인한 다음 이번 한 번만 허용하거나 비슷한 작업을 계속 허용할 수 있습니다.

    결과를 보면 optimized 방식은 실행 시간 중앙값이 약 11% 낮고, 실행 시간의 편차도 작았습니다. 성공률은 두 방식이 같았고요. 대신 평균 peak memory는 약 8% 더 사용했습니다.

    정리하면 더 빠르고 일정한 대신, 메모리는 조금 더 사용하는 결과입니다. 다만 이 데이터만으로 실행 방식 하나가 모든 차이를 만들었다고 단정할 수는 없습니다.

    이번에는 분석 결과를 답변으로만 받지 않고, 다른 사람도 다시 실행할 수 있는 형태로 남겨보겠습니다.

    패럿이 Python 분석 코드를 만들고 실제로 실행한 다음, Markdown 보고서와 비교 그래프를 생성합니다. 마지막에는 보고서에 적힌 숫자가 원본 데이터와 맞는지도 다시 확인하고요.

    사용자가 직접 분석 코드를 작성하지 않더라도, 결과만 받아보는 데서 끝나지 않고 재현 가능한 코드와 산출물을 함께 남길 수 있습니다.

    SVG와 세션 관리

    분석 과정과 결론을 한눈에 보고 싶다면, 답변 안에 SVG 다이어그램을 만들어 달라고 할 수도 있습니다.

    LLM이 원본 데이터, 품질 점검, 방식 비교, 최종 해석의 관계를 SVG로 만들고, 패럿이 내용을 검증한 뒤 채팅 안에서 바로 보여줍니다.

    여기서 SVG는 Bash처럼 시스템을 실행하는 도구는 아닙니다. LLM이 만든 답변을 패럿이 읽기 쉬운 벡터 그래픽으로 표현하는 기능이라고 보면 됩니다.

    패럿을 데스크톱 앱으로 만든 또 다른 이유는 세션 관리입니다.

    실제 업무에서는 분석, 로그 확인, 코드 수정처럼 여러 작업을 번갈아 진행하는 경우가 많습니다. 패럿에서는 작업마다 세션을 나눌 수 있고, 대화뿐 아니라 어떤 파일을 읽고 어떤 도구를 실행했는지도 같은 흐름에 남습니다.

    새 작업은 /new나 Ctrl+N으로 시작할 수 있고요. Ctrl+K를 누르면 예전 세션을 검색해서 중단했던 작업을 다시 이어갈 수 있습니다.

    처음 사용할 때 기억할 것

    앞에서 본 /, !, @ 외에 단축키 몇 개만 알아두면 편합니다. Ctrl+K는 세션 검색, Ctrl+N은 새 세션, Ctrl+L은 채팅 입력으로 이동하는 단축키입니다. 진행 중인 작업을 멈추려면 Esc를 누르면 되고요. 사용할 모델은 /model에서 바꿀 수 있습니다.

    그렇다고 처음부터 이걸 전부 외울 필요는 없습니다. 처음에는 세 가지만 기억해도 충분합니다.

    VWP에서 패럿을 실행하고, / 목록에서 /cd를 골라 업무 폴더를 지정한 다음, @로 확인할 파일을 붙여서 먼저 조사만 부탁해 보는 겁니다.

    이 폴더가 어떤 작업을 위한 곳인지 파악해줘. 아직 파일을 수정하거나 커맨드를 실행하지 말고, 근거가 된 파일과 함께 설명해줘.

    결과를 확인한 다음에 필요한 커맨드를 실행하거나, 문제의 원인을 더 찾아보거나, 분석 결과를 파일로 남기는 작업까지 이어가면 됩니다.

    Agent는 질문에 답만 해주는 채팅보다는, 실제 작업 결과를 보고 다음 행동으로 이어주는 도구에 가깝습니다. 처음에는 작은 조사 하나부터 맡겨보면 패럿이 어떤 방식으로 일하는지도 금방 익숙해질 겁니다.
