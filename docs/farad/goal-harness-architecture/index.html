Farad · Architecture Review

The Goal Harness & its interaction with the Query Loop

A long-lived, per-session objective that drives the agent across turns until it is proven complete, blocked, or the user stops it. Architecturally it is an outer ralph loop wrapped around the existing per-turn inner loop (query_loop) — adding turn-boundary hooks, never touching the inner cycle. This page is written for code review: every claim is anchored to a symbol.

0 TL;DR for the reviewer

What it is

  • One power axis: on / off. The lifecycle meaning lives in off_reason.
  • revision is the monotonic arbiter; the transcript {"type":"meta","kind":"goal"} marker is truth, session.meta.json is a cache.
  • Three no-permission model tools; everything else is runtime/UI.
  • Cadence is agent-driven: grind by default, SnoozeGoal to wait. The runtime never infers cadence from tool-call counts or background jobs.

The one invariant to hold in mind

Containment. Every Goal integration point is a strict no-op when config.goal_service is None. The turn loop is byte-for-byte unchanged when the harness is unwired (tests / headless). Review each seam by asking: does it early-return on None?
Heads up — these landed this session (read §10 first if reviewing the diff): the model/user-facing turn/token budget was removed (replaced by a silent HARD_TURN_CAP backstop); SnoozeGoal was added; and a runtime "defer while background work runs" heuristic was deliberately rejected — cadence is the agent's call, not the runtime's.

3 The two nested loops — the load-bearing idea

Farad already had a per-turn agent loop: query_loop cycles LLM → tools → LLM within one turn until the model stops, returning LoopTerminated. The Goal harness adds an outer loop that, at each turn boundary, decides whether to fire another turn — the "ralph loop". The inner loop is untouched.

D1 guard. The next trigger="goal" turn re-checks _goal_continuation_still_due() at the top of _run_turn: if the Goal turned off or its revision advanced (pause, edit, new user turn) since the snapshot, the scheduled/snoozed turn is dropped before spending any model call. This is what makes a stale snooze fire into a paused Goal safe.

6 SnoozeGoal — agent-controlled cadence

The agent, not the runtime, decides when to wait. Default after a productive turn is to continue immediately (grind). When the agent is only waiting on something — a background command it launched, a rate limit, an external event — it calls SnoozeGoal(minutes) instead of ending an idle turn that would just re-fire.

Mechanics

  • request_snooze records a transient per-session seconds value (GoalService._pending_snooze). No marker, no rev bump — the Goal stays on.
  • The runtime consumes it once (take_pending_snooze) at the scheduling point and arms a separate _goal_snooze_task (an asyncio.sleep), held apart from _current_turn_task so user input can still run a turn.
  • Any real turn cancels the snooze at the top of _run_turn → a background completion / user reply preempts the wait. A snoozing Goal fires no turn, so it does not spend HARD_TURN_CAP.
  • Any off-transition clears a stale snooze in _commit; request_abort while snoozed cancels the wake and pauses the Goal (Case F).

Why not auto-detect background jobs?

An earlier prototype deferred continuation whenever the session had a running background shell or subagent. It was removed on purpose: the runtime cannot know a background job's nature. You might launch a server in the background and keep interacting with it — "wait until it finishes" is wrong there.

So cadence is the agent's call (SnoozeGoal), and the runtime never inspects background state in the continuation path. A backstop (HARD_TURN_CAP = 50, resets on resume) catches a runaway loop without being a tunable feature.

7 Wire context & the truth source

What the model sees

On every on turn, _with_goal_context attaches a wire-only compact reminder (goals/prompt.py · build_compact_reminder): the objective (XML-escaped, treated as data), the anti-shrink rule, evidence discipline, and the SnoozeGoal hint. It is built once per TurnContext so reruns are identical.

A read-only "Goal prompt" audit card is appended once per on-turn (_append_goal_notice_if_due), rendered exactly like the compaction / background-task cards via SYSTEM_NOTE_ROLE + presentation_kind="goal_prompt".

What never reaches the provider

normalize_for_api drops every transcript envelope whose type ∉ {user, assistant, tool}. So the Goal meta markers and the goal_notice audit entries are structurally wire-excluded — the reminder is injected separately and intentionally; the markers/notices never double-send.

Truth vs cache. The {"type":"meta","kind":"goal"} transcript marker is the source of truth (survives crash); session.meta.json is a fast cache. reconcile() resolves them at session-open and the continuation guard.

9 Architect review checklist

  • Containment — every seam early-returns when goal_service is None; the unwired turn loop is unchanged.
  • Truth first — service appends the transcript marker before refreshing the cache or emitting a snapshot (_commit).
  • Wire exclusion — Goal markers and goal_notice never pass normalize_for_api; the reminder is the only thing that reaches the model.
  • Revision arbiter — every state change bumps revision; the D1 guard compares against the scheduling snapshot, not "is it still on".
  • Exactly-once continuation — turn spawns assign _current_turn_task synchronously on the single session loop (no await between done-check and create_task) → no double-fire / lost wake.
  • Snooze is free to wait — snoozing fires no turn, so it never advances auto_turn_count / HARD_TURN_CAP; the wake is preemptable and cancelled by abort/shutdown/real-turn.
  • Cadence is the agent's — the runtime never infers continuation timing from tool-call counts or background-job state.
  • Only-user lifecycle — model tools can complete/block but cannot pause/resume/cancel/redefine.
  • English-fixed wire — goals/prompt.py is never i18n; the strip's Goal label is a fixed product term.
