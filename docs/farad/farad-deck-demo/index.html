    Farad 아티팩트 덱 템플릿 — Confluence 페이지 안에서 바로 발표하는 HTML 슬라이드

    아래는 Farad의 farad-artifact 스킬에 새로 추가한 슬라이드 덱 템플릿을 그대로 붙여 넣은 것이다. 원래 목적지는 Confluence Data Center의 HTML 매크로지만, 호스트 CSS를 견디도록 만들어서 이 블로그에서도 똑같이 동작한다.

    보는 법:

    • 페이지에서는 슬라이드가 세로로 쌓인 스택으로 읽힌다.
    • 오른쪽 위 Present를 누르면 덱이 화면을 덮는다. ← → 로 넘기고, Esc 또는 우측 상단 ✕ 로 나온다. 브라우저 크롬까지 지우려면 그 옆 확대 아이콘을 한 번 더 누른다.
    • 창을 좁히면 680px 아래에서 16:9를 풀고 읽히는 카드로 바뀐다.

    Confluence 페이지 안에서 발표하기

    pptx를 첨부하는 대신, 슬라이드를 페이지에 그대로 붙이고 거기서 발표한다.

    에이전트는 pptx보다 HTML을 훨씬 잘 만든다

    • HTML은 렌더해서 스스로 확인하고 고칠 수 있다. pptx는 EMU 좌표를 눈 감고 찍는 작업이다
    • flex·grid는 내용이 늘어나면 알아서 밀린다. pptx는 한글 12pt가 몇 줄인지 폰트 메트릭으로 추정해야 한다
    • 학습 데이터의 양이 비교가 안 된다

    목적지가 형식을 정한다

    웹 덱

    컨플루언스에 올리거나 그냥 발표만 하면 된다. 링크 하나로 끝나고 항상 최신이다.

    PPTX

    받는 사람이 PowerPoint에서 직접 고쳐야 하거나, 사내 마스터 템플릿 심의를 타야 할 때.

    폭이 바뀌면 글자도 같이 바뀐다

    실패 모드가 다르다

    내용이 넘칠 때 PPTX 이 덱
    결과 조용히 잘림 슬라이드가 길어짐
    만든 사람이 아는가 열어보기 전엔 모름 한눈에 보임
    화면 크기 대응 고정 폭에 비례해 스케일

    비율은 슬라이드가 아니라 빈 칸이 담당한다

    • aspect-ratio를 슬라이드에 직접 주면 block 축 min-content가 비율에서 전이된 값이 된다 — 넘친 내용이 다음 슬라이드를 침범한다
    • 그래서 비율은 빈 그리드 아이템이 갖고, 내용과 같은 셀에 겹친다
    • 행 높이 = 둘 중 큰 쪽. 평소엔 16:9, 넘치면 길어진다

    발표 모드는 브라우저 전체화면에 기대지 않는다

    • Present를 누르면 덱이 화면을 그대로 덮는다. iPhone Safari처럼 requestFullscreen이 아예 없는 곳에서도 똑같이 동작한다
    • 브라우저 크롬까지 지우고 싶으면 우측 상단 확대 아이콘이 한 단계 더 올려 준다. 나가는 건 그 옆의 ✕ 또는 Esc
    • 스케일은 컨테이너 쿼리 단위라 CSS만으로 된다. 스크립트가 걸러져도 슬라이드 스택으로 읽힌다
    • 키보드는 document가 아니라 덱에만 바인딩한다 — 안 그러면 Confluence 단축키를 가로챈다

    설계 메모

    스케일은 JS가 아니라 CSS가 한다

    슬라이드 폭에 비례해 글자가 커지는 것은 컨테이너 쿼리 단위(cqw) 하나로 처리했다. JS로 transform: scale()을 계산하는 reveal.js 방식이 아니라, 스케일 자체가 CSS라서 스크립트가 없어도 레이아웃이 성립한다. 위 4번 슬라이드의 그래프가 그 차이다.

    컨테이너 타입은 size가 아니라 inline-size다. size는 블록 축까지 containment를 걸어 높이가 내용과 무관해지므로, 내용이 넘치면 조용히 잘린다 — 생성된 PowerPoint의 실패 모드가 그대로 돌아온다.

    비율을 슬라이드에 직접 주면 안 된다

    슬라이드에 aspect-ratio: 16 / 9를 직접 주면, 폭이 확정된 상자의 block 축 min-content 크기가 비율에서 전이된 값으로 결정된다. 그래서 min-height: min-content를 붙여도 상자가 자라지 않고, 넘친 내용이 박스 밖으로 흘러 다음 슬라이드를 덮어썼다. 비율을 빈 그리드 아이템에 옮기고 내용과 같은 셀에 겹치니 행 높이가 둘 중 큰 쪽이 되어, 평소에는 16:9이고 내용이 넘치면 슬라이드가 길어진다.

    발표 모드는 Fullscreen API에 기대지 않는다

    처음엔 requestFullscreen()을 기본 경로로 두고, 거부당했을 때만 position: fixed로 덮는 폴백을 뒀다. 그런데 iPhone Safari에는 Element.requestFullscreen이 아예 없어서 폰에서는 항상 폴백이 돌고, 그 폴백은 :fullscreen과 한 셀렉터 목록으로 묶여 있었다. CSS 셀렉터 목록은 하나라도 파싱되지 않으면 규칙 전체가 버려지므로, :fullscreen을 모르는 브라우저에서는 배경도 슬라이드 숨김도 없이 위치만 고정되는 최악의 조합이 된다.

    지금은 순서를 뒤집었다. Present는 언제나 덱을 뷰포트에 고정하고, 진짜 전체화면은 그 안에서 한 번 더 누르는 선택지다. 덕분에 CSS에서 :fullscreen 셀렉터가 완전히 사라졌고, 상태는 data-farad-presenting 속성 하나가 전부다.

    차트는 인라인 SVG다

    매크로 안에서는 차트 라이브러리를 불러올 수 없고, 차트를 이미지로 굽으면 발표 모드에서 확대되는 순간 뭉갠다. viewBox 안의 길이는 사용자 단위라 슬라이드와 함께 스케일되고, 색은 덱의 토큰을 그대로 쓰므로 다크 모드도 따라온다. viewBox는 슬라이드보다 납작하게 잡는다 — width: 100%인 SVG는 높이를 그 비율에서 가져오므로, 세로로 긴 viewBox는 슬라이드를 16:9 밖으로 밀어낸다.
