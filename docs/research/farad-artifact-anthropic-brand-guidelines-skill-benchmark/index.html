    Anthropic brand-guidelines Skill 벤치마크

    조사일: 2026-07-14
    대상: anthropics/skills의 brand-guidelines

    한 줄 결론

    이 스킬은 완성물 생성기와 분리된, 작고 권위 있는 브랜드 토큰 공급원의 좋은 예다. 다만 색·폰트만 정하고 생성·검증 방법은 거의 주지 않으므로, Farad에서는 이를 그대로 복제하기보다 farad-artifact 안의 짧은 브랜드 기준으로 삼고, 매체별 레이아웃과 렌더 QA를 별도로 설계해야 한다.

    실제 구성과 작동 범위

    디렉터리에는 SKILL.md와 LICENSE.txt만 있다. 즉 스크립트, 템플릿, 이미지, 샘플 산출물은 없다. Agent Skills 표준상 이런 작은 패키지는 필요한 지침만 본문에 두고, 큰 리소스는 references/, assets/, scripts/로 지연 로드할 수 있다. 이 사례는 의도적으로 그 최소형만 취한다.

    YAML frontmatter는 name, 발동 용도까지 적은 description, 라이선스 참조로 구성된다. 본문은 다음 다섯 묶음이다.

    1. 발동 어휘 — branding, corporate identity, typography, visual formatting 등으로 브랜드나 시각 형식 요청에 넓게 반응한다.
    2. 색 토큰 — dark #141413, light #faf9f5, mid gray #b0aea5, light gray #e8e6dc를 기본 계층으로, orange #d97757, blue #6a9bcc, green #788c5d를 accent으로 지정한다.
    3. 타이포그래피 — 제목은 Poppins(없으면 Arial), 본문은 Lora(없으면 Georgia)로 고정한다.
    4. 적용 규칙 — 24pt 이상 제목에 제목 글꼴을 쓰고, 배경에 맞춰 텍스트색을 고르며, 도형에는 accent를 순환 적용해 시각적 변화를 준다고 지시한다.
    5. 구현 힌트 — 시스템 글꼴 fallback과 python-pptx의 RGBColor 사용을 설명한다.

    따라서 이것은 "Anthropic처럼 보이는 artifact를 만들 때 참조할 값과 가벼운 적용 규칙"이지, PPTX/HTML을 실제 생성·렌더·검수하는 워크플로 스킬은 아니다. 공식 저장소도 skill을 반복 가능한 전문 작업을 위한 instructions, scripts, resources의 폴더로 설명하며, 이 스킬은 그중 instructions 중심의 예시임을 명시한다. 저장소 README

    좋은 설계 포인트

    1. 브랜드 권위를 artifact 생성과 분리

    PPTX, HTML, 문서 스킬마다 색을 재서술하지 않고 하나의 브랜드 기준을 호출하게 할 수 있다. 브랜드 변경도 한 파일에서 관리한다. Farad도 콘텐츠 형식(HTML/PPTX/Confluence)과 제품의 시각 언어를 분리해야 한다는 점이 가장 큰 교훈이다.

    2. 토큰에 역할을 붙인다

    단순 hex 목록이 아니라 primary text/dark background, subtle background, accent라는 역할을 함께 준다. 생성 모델은 임의 팔레트보다 역할 기반 토큰에서 일관되게 선택한다. Farad 역시 page, surface, text-primary, text-secondary, rule, accent처럼 의미 토큰을 주고, 매체별 값은 그 아래로 내려야 한다.

    3. 환경 차이를 미리 흡수한다

    사용 가능 여부가 불확실한 글꼴에 fallback을 명시한다. artifact가 다른 PC나 PPTX 뷰어에서 무너지지 않게 하는 실용적 지침이다. Farad에는 Pretendard, Noto Sans KR, system-ui처럼 한글과 오프라인 환경을 고려한 fallback chain 및 PPTX 글꼴 대체 전략이 필요하다.

    4. 작아도 발동 조건을 구체적으로 적는다

    description에 무엇을 하고 언제 쓰는지를 적어 자동 선택성을 높인다. 표준도 description에 행동과 사용 시점, 키워드를 포함하라고 권한다. Agent Skills specification Farad의 표시명은 한국어여도 내부 farad-artifact description에는 HTML, Confluence, PPTX, 슬라이드, 다이어그램, 보고서, 발표자료 같은 한·영 키워드를 함께 넣는 편이 좋다.

    Farad에 그대로 가져오면 생기는 충돌

    Anthropic 규칙 Farad에 맞지 않는 이유 Farad의 대안
    도형의 orange/blue/green 순환 색이 의미가 아니라 장식이 되어, 한 페이지가 AI 생성물처럼 산만해질 수 있다. 기본은 중립색·hairline·여백. 강조는 한 artifact에서 한 색, 의미 상태가 필요할 때만 추가 색.
    Poppins + Lora 친화적 editorial 인상은 낼 수 있으나 Farad의 제품 UI( Pretendard, 실용적 모던 UI)와 결이 다르고 한글 fallback 품질도 불균일하다. 본문과 제목 모두 Pretendard 우선, Noto Sans KR/system-ui fallback. 코드만 JetBrains Mono.
    24pt 이상만 heading 처리 HTML의 반응형 단위, PPTX의 슬라이드 계층, Confluence의 제한된 HTML에 공통으로 맞지 않는다. display / h1 / h2 / body / caption 역할과 상대적 크기·행간을 매체별 reference에 규정.
    "accent 순환"만으로 흥미 유지 정보 위계보다 장식성을 먼저 유도하며, 데이터 다이어그램에서 색의 의미가 모호해진다. 제목·요약·결론의 논리적 위계, 한 장면당 한 주장, 라벨·선·그룹으로 먼저 구분.
    정적 값만 제공 overflow, 대비, SVG 선명도, Confluence 붙여넣기 호환성, PPTX 편집성은 보장하지 못한다. HTML/PPTX별 생성 후 렌더·검수·수정 루프를 필수 단계로 둔다.

    farad-artifact에 적용할 구조 제안

    brand-guidelines처럼 모든 것을 본문에 넣지 말고 progressive disclosure를 쓴다.

    farad-artifact/
├── SKILL.md                       # 발동 조건, 공통 workflow, 반드시 지킬 톤
├── references/
│   ├── visual-language.md          # Farad 색/타입/여백/다이어그램 언어, anti-pattern
│   ├── html.md                     # standalone HTML + inline SVG, 접근성, 검수
│   ├── confluence.md               # 지원되는 붙여넣기/첨부 fallback과 금지 요소
│   └── pptx.md                     # 슬라이드 밀도, 편집성, 렌더 QA
├── assets/
│   ├── html-shell.html
│   └── pptx-template.pptx          # 실제 승인된 템플릿이 생긴 뒤에만 추가
└── scripts/
    └── verify_artifact.py          # 필요 시 링크/overflow/산출물 존재 여부 점검

    SKILL.md의 공통 workflow는 다음 정도가 적절하다.

    1. 독자·배포처·핵심 주장·편집 가능성을 확인한다.
    2. 매체(HTML / Confluence / PPTX)와 다이어그램 표현(SVG 기본, Mermaid는 구조 초안)을 고른다.
    3. visual-language.md를 읽고, 넓은 여백·명확한 정보 위계·중립 팔레트로 초안을 만든다.
    4. 해당 매체 reference의 렌더 및 overflow 검사를 실행하고, 결과물을 직접 확인해 고친다.
    5. 산출물 경로, 열람 방법, 편집 가능한 원본을 응답에 남긴다.

    특히 Farad의 anti-pattern은 긍정 규칙만큼 명시해야 한다: 네온 그라데이션, glassmorphism, 불필요한 다색 카드, 장식용 아이콘 군집, 과도한 둥근 pill, 의미 없는 3D/그림자, 텍스트를 대체하는 일러스트를 기본값으로 만들지 않는다. 이는 "밋밋함"이 아니라 사용자가 빠르게 읽고 신뢰할 수 있게 하는 절제다.

    최종 권고

    Anthropic 사례에서 브랜드의 단일 권위·의미 토큰·fallback·명확한 activation description은 채택한다. 그러나 색 순환과 고정 폰트 조합은 채택하지 않는다. Farad의 첫 버전은 템플릿부터 무겁게 시작하지 말고, ① 얇은 SKILL.md, ② 매체별 reference, ③ visual-language.md의 구체적 금지/권장 목록, ④ HTML과 PPTX를 실제 렌더해 보는 QA 계약으로 출발하는 것이 좋다.

    출처

    • Anthropic, brand-guidelines/SKILL.md — 팔레트, 글꼴, 적용 규칙, 구현 힌트의 원문.
    • Anthropic, brand-guidelines directory — 패키지 파일 구성 확인.
    • Anthropic, Skills repository README — skill의 역할과 예시 저장소 성격.
