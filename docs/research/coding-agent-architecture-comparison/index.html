    고정된 증거 경계

    • OpenCode: anomalyco/opencode@b3a012cbdde854b0fe14f95b1c48543bf6517c0a, package 1.17.18
    • Claude Code: 조사 당시 공식 문서 + npm latest 2.1.207 표지, local CLI 2.1.206, 2.1.88 sourcemap 내부 관찰은 별도 C급 증거
    • Codex: openai/codex@2b0b37abb7b29ea272fa856d6dff9221a6bd9ba8와 공식 문서
    • Farad: 2026-07-13 현재 worktree source/docs/tests; focused test 1,527개 통과

    핵심 결론

    • 단일 승자는 없다: OpenCode는 provider/API, Claude Code는 terminal workflow, Codex는 ordered runtime와 local command containment, Farad는 provider-neutral native desktop과 HPC/NFS 제품 계약이 강하다.
    • Farad는 재작성보다 계약-구현 gap closing이 맞다. 최우선은 OS execution boundary, scheduler due index, transcript I/O/repair, nonblocking explicit-refresh snapshot, Qt permission snapshot, client lifecycle다.
    • server/app protocol과 깊은 agent team은 실제 두 번째 surface·workflow 요구가 생길 때까지 조건부다.

    검증

    • Farad runtime/transcript/tool/MCP/session/scheduler/settings 관련 focused test: 1,527 passed
    • Mermaid CLI 11.16.0 실제 render: 6개 보고서, 19개 chart 모두 통과
    • 상대 Markdown link 존재 여부와 fenced block 균형: 통과
    • 전체 repository test suite, ruff, mypy는 문서 조사 범위를 넘어 실행하지 않음

    문서만 추가했으며 Farad 제품 소스나 기존 사용자 변경은 수정하지 않았다.
