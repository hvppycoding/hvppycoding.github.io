    Anthropic pptx Skill 벤치마크

    조사일: 2026-07-14
    대상: Anthropic Skills / skills/pptx

    한 줄 평가

    이 스킬의 가장 강한 부분은 PPTX를 코드로 만들었다고 끝내지 않고, 실제 렌더 결과를 사람이 보는 방식으로 반복 검수하는 계약이다. 반면 시각 지침은 "슬라이드는 언제나 강렬하고 시각적으로 풍부해야 한다"에 기울어 있어, Farad의 차분하고 정보 우선인 자료 생성 스킬에는 선별 이식이 필요하다.

    범위와 파일 구조

    SKILL.md는 deck/slides/presentation 또는 .pptx가 입력·출력·편집 대상인 모든 요청에서 발동하도록 범위를 넓게 잡는다. 세 가지 경로를 제공한다.

    상황 핵심 흐름 상세 문서
    기존 파일 읽기 markitdown 텍스트 추출, thumbnail, 필요 시 raw XML SKILL.md
    기존 템플릿 편집 썸네일 분석 → XML unpack → 구조 변경 → 내용 교체 → clean/pack editing.md
    신규 생성 PptxGenJS로 슬라이드 생성 pptxgenjs.md

    보조 스크립트는 thumbnail.py, Office unpack/pack, add_slide.py, clean.py로 구성된다. 템플릿 편집과 신규 생성을 한 방법으로 뭉개지 않고, 원본의 레이아웃·관계를 보존해야 하는 경우에는 OOXML 패키지를 다루며, 처음부터 만들 때만 PptxGenJS를 쓴다.

    작업 방식에서 배울 점

    1. 템플릿을 먼저 읽고, 콘텐츠를 레이아웃에 매핑한다

    템플릿 썸네일과 텍스트를 먼저 읽은 후 콘텐츠 섹션마다 사용할 기존 슬라이드를 선택한다. 슬라이드 구조를 모두 확정한 뒤에야 텍스트를 교체하고, 빈 자리에는 텍스트만 지우지 말고 이미지·shape까지 삭제하도록 요구한다. "템플릿 slot 수와 원본 항목 수는 다를 수 있다"는 경고는 실제 PPTX 생성 실패를 줄이는 좋은 규칙이다.

    Farad에도 그대로 가져갈 수 있다. farad-artifact는 기존 회사 템플릿이 주어지면 템플릿의 타입·여백·폰트·색을 관찰한 뒤, 자료의 정보 유형에 맞는 슬라이드 매핑을 먼저 제시해야 한다.

    2. 소스 변경과 패키지 무결성의 경계를 안다

    슬라이드 복제는 XML 파일을 복사하지 말고 전용 스크립트를 쓰게 한다. 이는 notes, relationship ID, content type처럼 화면에 보이지 않는 패키지 관계를 지키기 위한 것이다. 편집 시에는 각 XML의 모든 placeholder(텍스트·그림·차트·아이콘·caption)를 찾아 교체하고, pack 단계에서 검증·정리를 한다.

    PptxGenJS 가이드도 색상값의 # 금지, 8자리 hex로 opacity를 표현하면 파일이 망가지는 문제, 옵션 객체 재사용에 따른 mutation 문제, proper bullet API 사용 등을 구체적으로 적는다. 결과적으로 디자인 안내서이면서 파일 생성의 실패 사전이다.

    3. 산출물 QA를 필수 단계로 둔다

    가장 채택 가치가 높은 부분이다. 텍스트 QA(markitdown)와 시각 QA를 분리한다. 시각 QA는 LibreOffice로 PDF 변환 후 Poppler로 슬라이드별 JPEG를 만들고, 오버플로·겹침·가장자리 여백·정렬·대비·placeholder 잔존을 체크한다. 첫 렌더를 정답으로 보지 말고 최소 한 번은 문제를 고치고 다시 렌더하기 전에는 성공 선언을 금지한다.

    Farad에서는 이 흐름을 생성 → render → 검토 목록 작성 → 수정 → 영향 슬라이드 재검토로 표준화할 만하다. 다만 "문제가 반드시 있어야 한다"보다 "확인 항목별로 pass/fail 근거를 남긴다"가 더 실무적이다. 다중 에이전트의 fresh-eye 검토 권고는 유용하지만, Farad 스킬 자체가 에이전트 병렬 실행을 전제하면 안 된다. 가능할 때만 독립 시각 검토를 권장하는 수준이 적절하다.

    시각 설계 지침: 채택·수정·배제

    판정 지침 Farad 적용
    채택 제목/본문 크기 대비, 일관된 간격, 최소 여백, 낮은 대비 방지 Farad 토큰과 폰트 기준으로 수치화한다.
    채택 주제와 자료 구조에 맞는 레이아웃 선택, 템플릿의 무의미한 반복 방지 단, 변주는 정보 구조가 달라질 때만 한다.
    수정 한 색의 dominance와 제한된 accent Farad는 neutral/off-white를 기본으로, 강조색은 의미 상태·핵심 경로에만 쓴다.
    수정 차트·아이콘·shape로 시각화 데이터·관계가 있는 때만 SVG 도표·차트를 쓴다. 장식용 아이콘은 기본적으로 생략한다.
    배제 "모든 슬라이드에는 visual element" 제목·결론·결정문은 텍스트와 충분한 여백만으로 더 잘 읽힐 수 있다.
    배제 bold palette, dark/light sandwich, 독특한 motif를 매번 강제 Farad의 지속적인 톤보다 특정 발표의 연출을 우선하는 규칙이다.
    배제 이탤릭 accent, 색 원형 속 아이콘, full-bleed 이미지 등의 기본 권장 업무 문서에서는 장식 과잉과 LLM 생성물 같은 인상을 만들기 쉽다.

    특기할 점은 이 스킬도 제목 아래 accent line은 AI 생성 슬라이드의 표지이므로 금지한다. Farad가 피하려는 "그럴듯한 AI 자료"의 한 유형을 명시적으로 차단한 규칙이라 유지할 가치가 높다.

    farad-artifact에 권장하는 이식안

    1. 두 제작 경로: 템플릿이 있으면 분석·보존 편집, 없으면 Farad 기본 테마로 신규 생성. 두 경로를 한 프롬프트로 섞지 않는다.
    2. 정보 우선 설계 brief: 독자, 결정/행동, 전달할 주장, 자료 형식(발표·HTML·Confluence), 필요한 diagram만 먼저 확정한다. 각 슬라이드/섹션의 visual은 내용 필요성으로 정당화한다.
    3. 재사용 가능한 Farad 토큰: 오프화이트 배경, neutral text, 제한된 blue 계열 강조, 명확한 표·SVG diagram 규칙, 충분한 여백을 별도 references/farad-style.md에 둔다. 포맷별 구현 가이드와 브랜드 계약을 분리한다.
    4. 포맷별 렌더 QA: PPTX는 슬라이드 이미지, HTML은 브라우저 screenshot, Confluence는 지원되는 markup/첨부 방식 검증으로 나눈다. 모든 경로에서 overflow, contrast, reading order, 링크·파일 경로, placeholder 잔존을 점검한다.
    5. 완료 기준: 결과 파일뿐 아니라 원본 소스(예: PptxGenJS, inline SVG 또는 Mermaid 원문), 렌더 검토 흔적, 수정 후 확인 결과를 남긴다.

    결론

    Anthropic pptx는 Farad가 참고할 제작·검증 엔진으로 훌륭하다. 특히 템플릿 보존, OOXML의 구체적 위험 방지, 렌더 기반 fix-and-verify 루프는 거의 그대로 채택할 만하다. 그러나 색·모티프·시각 요소를 강하게 요구하는 미학은 Farad의 목표와 다르다. farad-artifact는 이를 "정보를 더 빨리 이해시키는 경우에만 시각화한다"와 "조용한 기본값, 드문 강조"로 뒤집어야 한다.
