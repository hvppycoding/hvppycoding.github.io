    Pyverilog 서브모듈 구현

    2025-08-19

    You are professional expert of pyverilog and verilog. 아래는 yosys 툴의 submod 기능에 대한 documentation이야. 이와 유사한 기능을 pyverilog로 만들고 싶어. bit width(MSB, LSB)가 있는 포트/넷도 잘 처리해야해. 원하는 입력 커맨드: submod -f instance.list(파일 안에 submodule화 하고자하는 instance 명들 포함) -t netlist1.v netlist2.v submod - moving part of a module to a new submodule yosys> help submod submod [options] [selection] This pass identifies all cells with the 'submod' attribute and moves them to a newly created module. The value of the attribute is used as name for the cell that replaces the group of cells with the same attribute value. This pass can be used to create a design hierarchy in flat design. This can be useful for analyzing or reverse-engineering a design. This pass only operates on completely selected modules with no processes or memories. -name don't use the 'submod' attribute but instead use the selection. only objects from one module might be selected. the value of the -name option is used as the value of the 'submod' attribute instead.

    좋아요—Yosys submod와 유사한 “인스턴스 묶음을 새 서브모듈로 추출” 기능을 Pyverilog로 만들 수 있게 전체 스크립트를 준비했어요. 코드 전체는 옆의 캔버스에 올려두었습니다: pyverilog_submod.py. 아래는 동작 원리와 사용법, 그리고 비트폭(MSB/LSB) 처리 포인트를 단계별로 정리해둘게요.

    구현 개요 (step-by-step)

    1. 입력 파싱

      • -f instance.list: 서브모듈로 옮길 인스턴스 이름 목록(줄당 1개, # 주석 허용).

      • -t <target_module>: 변환 대상 모듈.

      • netlist*.v: Verilog 파일들.
        → Pyverilog parse()로 전체 AST를 구성.

    2. 타깃 모듈/인스턴스 수집

      • 타깃 모듈 안의 InstanceList/Instance를 전부 나열.

      • 이름이 리스트에 포함된 인스턴스만 선택 집합 으로 분류.

    3. 경계(net) 판정용 사용 집합 계산

      • 선택된 인스턴스들이 참조하는 식(expression)에서 식별자 집합(Identifier names)을 수집 → sel_ids.

      • 나머지(선택되지 않은) 인스턴스들이 참조하는 식별자 집합 → other_ids.

      • 타깃 모듈의 탑 포트명 집합도 확보.

      • 외부 식별자 = (sel_ids ∩ other_ids) ∪ {모듈 포트들}
        → 선택 영역과 외부 양쪽에서 모두 쓰이는 신호(혹은 최상위 포트)는 “경계”로 간주.

    4. 셀 포트 방향 추론

      • 인스턴스가 가리키는 셀/모듈 정의에서 각 포트의 input/output/inout 방향을 AST로 조회.

      • 셀 정의를 찾을 수 없으면 보수적으로 inout 처리.

    5. 경계식 → 새 서브모듈 포트로 승격 (표현식 단위)

      • 선택된 인스턴스의 각 포트 연결식에 대해 순회하면서,

        • 식 서브트리 가 “외부 식별자만으로 구성된 순수 외부식”이면 그 서브트리 전체 를 새 포트로 치환.

          • 예: bus[7:4], ext_sig, {a[3:0], b} 등(전부 외부일 때).

        • 내부/외부가 섞인 경우엔 외부 부분만 개별 포트로 치환하고 나머지는 그대로 유지.

      • 동일한 외부식은 문자열로 직렬화해 중복 없이 하나의 새 포트 로 합침.

    6. 새 포트의 방향·폭 결정

      • 방향: 해당 외부식이 연결된 셀 포트들 방향을 모아

        • output만 → output

        • input만 → input

        • 혼합/불명 → inout

      • 폭(width): 아래 규칙으로 정확히 산출

        • Identifier → 선언 폭(원 모듈의 Ioport/Decl에서 Width(msb, lsb) 취득).

        • Pointer(x[i]) → 1비트.

        • Partselect(x[msb:lsb]) → |msb-lsb|+1.

        • Concat({a,b[3:0],...}) → 항목 폭 합.

        • 상수 8'hFF 등 → 앞의 크기(여기선 8). 미사이즈 상수는 32비트 가정.

    7. 새 서브모듈 구성

      • 포트 리스트(Ioport)를 선언(다비트일 경우 [N-1:0], 1비트는 스칼라).

      • 선택된 인스턴스들을 치환된 포트 연결식 으로 그대로 새 모듈 내부에 배치.

      • 선택 영역에서만 사용되는 내부 신호 선언(wire/reg)을 원 모듈의 선언에서 복사하여 새 모듈에 포함.

    8. 원 모듈 수정

      • 선택된 인스턴스들을 원 모듈에서 제거.

      • 경계 포트 맵으로 새 서브모듈 1개 를 인스턴스화하고,

        • 각 포트는 원래의 외부식(예: bus[7:4], {a,b})에 직접 연결 → 슬라이스/컨캣 그대로 유지되므로 폭/비트 매칭 보장.

    9. Verilog 출력

      • AST를 ASTCodeGenerator로 코드 생성 → 표준출력(또는 -o 파일).

    사용법

    python pyverilog_submod.py \
  -f instance.list \
  -t top_module \
  -o out.v \
  netlist1.v netlist2.v

    instance.list 예시:

    nginx

u_alu_0
u_alu_1   # 주석 허용
u_regfile

    옵션:

    • -n my_sub : 새 모듈 이름 지정(미지정시 <target_module>_submod).

    • -o out.v : 결과 Verilog 파일(미지정시 stdout).

    비트폭/슬라이스 처리 포인트

    • bus[MSB:LSB] → 서브모듈 포트명을 bus_MSB_LSB 형태로 생성, **폭 = MSB-LSB +1**.

    • bus[i](포인터) → 1비트 포트 생성.

    • {a, b[3:0]} 같은 순수 외부 컨캣 은 한 포트로 올림(폭은 합계).
      내부·외부 혼합 컨캣은 외부 부분만 포트화 하고 내부 부분은 유지.

    간단 예시 (전/후)

    Before (일부):

    module top(input [7:0] A, input [7:0] B, output [3:0] Y);
  wire [7:0] w0;
  wire [3:0] mid;

  subcell_u u0 (.in(A[7:4]), .out(mid));          // <- 선택
  subcell_v u1 (.a({B[3:0], A[3:0]}), .y(w0));    // <- 선택 아님
  subcell_w u2 (.a(mid), .b(w0), .y(Y));          // <- 선택
endmodule

    After (개념):

    module top_submod(
  input  [3:0] A_7_4,
  input  [7:0] w0,
  output [3:0] mid
);
  subcell_u u0 (.in(A_7_4), .out(mid));
  subcell_w u2 (.a(mid), .b(w0), .y(mid)); // 예시용
endmodule

module top(...);
  ...
  top_submod u_top_submod (
    .A_7_4(A[7:4]),
    .w0(w0),
    .mid(mid)
  );
  subcell_v u1 (.a({B[3:0], A[3:0]}), .y(w0));
endmodule

    포인트: A[7:4]와 w0처럼 외부와 교차되는 식은 그대로 상위에서 연결 되며, 새 모듈 안에선 순수 아이디(포트명)로 치환됩니다.

    제약/가정 (필요 시 확장 가능)

    • 대상은 구조적 netlist(인스턴스/선언 위주). always/process/memory는 Yosys submod와 마찬가지로 범위 밖으로 두었습니다.

    • 외부로 넘어가는 연속 할당(assign)이 경계를 가르는 경우는 현재 기본 처리(경계 판정엔 반영 X). 필요하면 Assign 스캔을 추가해 드릴게요.

    • 인스턴스가 가리키는 셀 정의가 없을 때 포트 방향은 inout으로 보수 처리합니다(대부분의 합성 netlist는 정의가 들어있습니다).

    • 동일 외부식의 포트명 충돌은 자동으로 _1, _2 ...를 붙여 회피.

    다음 단계(원하시면 추가해 드릴 수 있어요)

    • Assign/연산 노드까지 경계 판정 확대.

    • 슬라이스 병합(예: bus[7:4]와 bus[3:0]을 하나의 8비트 포트로 자동 병합).

    • 사용되지 않게 된 원 모듈의 선언(wire/reg) 정리(제거).

    • CLI에 Yosys 스타일 옵션 추가(-name, 선택 범위 기반 등).

    필요하시면 실제 여러분의 netlist 한 조각으로 바로 돌려본 전/후 결과 도 만들어 드릴게요. 캔버스의 pyverilog_submod.py를 그대로 저장해 실행하면 됩니다.
