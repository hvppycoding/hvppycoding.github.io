    커스터마이즈된 크롬 배포 방법

    2025-08-08

    나의 업무 환경에서 모든 사람이 스토리지를 공유할 수 있어. 이 상황에서 크롬 실행 스크립트를 공유해서 모두가 같은 세팅으로 크롬을 사용할 수 있게 하려고 해. 근데 몇몇 사이트에 대해 탬퍼몽키를 작동시키고 싶어. 탬퍼몽키 스크립트를 내장에서 같이 배포를 할 수 있을까?

    가능은 한데, 어떻게 배포·관리하느냐 에 따라 난이도와 안정성이 크게 달라져요. 한 줄 요약부터:

    • 진짜 추천 : 탬퍼몽키 없이 사용자 스크립트를 크롬 확장 프로그램으로 포장 해서 기업 정책(ExtensionInstallForcelist)으로 강제 배포

    • “탬퍼몽키를 꼭 써야 해요”라면: 자동 설치는 사실상 불가(사용자 확인 필요) , 대신 공유 서버에 .user.js 올려 링크 배포 또는 설정 백업파일(.zip) 배포 후 수동 Import 가 현실적

    아래에 단계별로 정리해볼게요. (요청하신 “몇몇 사이트에서만 작동”도 포함)

    1) 베스트 프랙티스: 사용자 스크립트를 크롬 확장 으로 변환해 배포

    탬퍼몽키 의존을 없애고, 모든 사용자가 동일 설정으로 조용히(무인간섭) 쓰게 하려면 이게 가장 깔끔하고 안정적입니다.

    어떻게?

    1. 기존 .user.js 내용을 content script 로 옮깁니다.

    2. 어떤 사이트에서만 돌릴지 matches(또는 exclude_matches)로 지정.

    3. 필요 권한은 host_permissions/permissions에 명시.

    4. 내부 웹 서버(사내 HTTP(S))에 업데이트 피드(update.xml)를 올려 사내 전용 확장 으로 운영하거나, 크롬 웹스토어를 비공개 로 써도 됩니다.

    5. 관리용 정책으로 강제 설치 :

      • 조직 관리(Windows GPO / macOS 프로파일 / Linux 정책 파일)에서 ExtensionInstallForcelist에 확장ID;업데이트URL 추가.

    최소 예시 (Manifest V3)

    manifest.json

    {
  "manifest_version": 3,
  "name": "Corp Userscript Pack",
  "version": "1.0.0",
  "description": "사내 사이트용 사용자 스크립트 모음",
  "permissions": ["storage"],
  "host_permissions": [
    "https://example1.internal/*",
    "https://example2.com/*"
  ],
  "content_scripts": [
    {
      "matches": ["https://example1.internal/*"],
      "js": ["script1.js"],
      "run_at": "document-idle"
    },
    {
      "matches": ["https://example2.com/*"],
      "js": ["script2.js"],
      "run_at": "document-idle"
    }
  ]
}

    script1.js/script2.js에 기존 탬퍼몽키 코드 내용 이식.
    ※ GM_* API를 썼다면, 크롬 확장 API(예: chrome.storage, fetch, 메시징 등)로 대체가 필요할 수 있어요. 대부분 치환 가능합니다.

    장점

    • 전원 동일 버전 강제, 자동 업데이트.

    • 사용자 클릭 없이 조용히 배포 가능.

    • 프로필 공유나 확장 데이터 충돌 이슈 없음.

    2) “탬퍼몽키를 꼭 쓰고 싶다”면: 배포 선택지와 한계

    A. 링크 배포(사내 서버에 .user.js 호스팅)

    • .user.js를 내부 서버에 올리고, 첫 실행 시 탬퍼몽키가 설치 확인 팝업을 띄워 사용자가 “설치”를 눌러야 합니다.

    • 완전 무인 설치는 보안상 막혀 있습니다.

    • 크롬 실행 스크립트에서 처음 띄울 URL로 해당 .user.js 링크를 열게 하여, 최초 1회만 클릭하도록 안내하는 방식이 현실적.

    B. 탬퍼몽키 설정 백업/복원으로 배포

    • 관리자가 탬퍼몽키 대시보드에서 Export(백업) → 사용자에게 .zip 전달 → 각자 Import.

    • 역시 사용자 상호작용이 필요하고, 자동 업데이트·버전 통일을 보장하기 어렵습니다.

    C. 강제 설치(ExtensionInstallForcelist) + 탬퍼몽키만

    • 정책으로 탬퍼몽키 자체를 강제 설치 하는 건 가능합니다.

    • 하지만 개별 사용자 스크립트까지 자동 주입·업데이트 하는 방법은 공식적으로 제공되지 않습니다(사용자 확인 필요).

    • 따라서 “모두 같은 스크립트를, 클릭 없이”가 목표라면 1)번 방식이 낫습니다.

    3) “몇몇 사이트에서만 작동” 설정

    • 확장 방식 : manifest.json의 content_scripts.matches에 사이트 패턴만 넣으면 끝.

    • 탬퍼몽키 방식 : 스크립트 헤더에 @match/@include를 넣어 해당 도메인에서만 동작하도록 설정.

    예)

    js

// ==UserScript==
// @name         Corp Helper
// @match        https://example1.internal/*
// @match        https://example2.com/path/*
// @run-at       document-idle
// ==/UserScript==

    4) 크롬 “실행 스크립트”로 통일하려는 경우의 주의점

    • 프로필 폴더를 공유 스토리지에서 공용으로 쓰는 건 비권장(락/손상/동시쓰기/성능 문제).

    • 대신 각 사용자 로컬 프로필 을 쓰되, 정책으로 확장 강제 설치 와 홈페이지/스타트업 URL 등을 통일하세요.

    • --user-data-dir=로 네트워크 경로를 강제로 쓰는 건 위험합니다.

    5) 권장 아키텍처(요약)

    1. 사용자 스크립트를 확장으로 변환

    2. 사내 웹 서버에 확장 업데이트 피드 구성(또는 웹스토어 비공개)

    3. ExtensionInstallForcelist 정책으로 강제 설치

    4. 사이트 타깃팅은 matches로 관리

    5. 필요 시 버전 업은 업데이트 서버에 새 버전 배포 → 전원 자동 반영

    원하시면

    • 기존 탬퍼몽키 스크립트(코드) 보여주시면 확장용으로 변환 해 드리고,

    • 사내 업데이트 피드(update.xml)와 정책 값도 딱 맞게 만들어 드릴게요.
      환경(Windows AD/GPO, macOS, Linux)도 알려주시면 정책 예시까지 세팅해 드릴 수 있어요.

    무슨 말인지 전혀 모르겠어; content script가 뭔데?

    좋아요, 그럼 아주 기초부터 설명할게요.
    content script 는 크롬 확장 프로그램에서 쓰이는 개념인데, 쉽게 말하면 "특정 웹사이트에 자동으로 주입되어 실행되는 자바스크립트"예요.

    1. 왜 content script가 필요한가?

    탬퍼몽키(UserScript)도 결국은 브라우저가 어떤 웹페이지를 불러올 때 자바스크립트를 페이지 안에 넣어서 실행 하는 구조예요.
    크롬 확장에서 content script가 하는 역할이 탬퍼몽키 스크립트와 동일 합니다.
    차이점은:

    • 탬퍼몽키 : 브라우저에 설치된 확장 프로그램이 여러 개의 .user.js를 관리하고, @match 규칙에 따라 해당 페이지에 주입.

    • content script : 확장 프로그램 자체의 일부로, 미리 manifest.json에 어느 사이트에 넣을지 정의.

    2. 동작 흐름

    1. 사용자가 웹사이트 A(예: https://example.com)에 접속.

    2. 크롬이 manifest.json을 보고 “이 사이트에 myscript.js라는 content script를 넣어야 하네?” 판단.

    3. 해당 자바스크립트를 페이지 안에 삽입해 실행.

    4. 그 코드가 HTML 조작, 버튼 클릭 자동화, 스타일 변경 등 원하는 작업 수행.

    3. 탬퍼몽키와 비교

    구분 탬퍼몽키(UserScript) content script(크롬 확장)
    설치 확장 설치 + 스크립트 개별 설치 확장만 설치
    배포 .user.js 링크나 파일로 배포 → 사용자가 설치 클릭 확장 자체를 배포(정책으로 강제 가능)
    업데이트 스크립트마다 별도 관리 확장 버전 업데이트 시 전부 자동 반영
    사이트 지정 @match/@include manifest.json의 matches

    4. 간단한 예

    manifest.json

    {
  "manifest_version": 3,
  "name": "My Helper",
  "version": "1.0",
  "content_scripts": [
    {
      "matches": ["https://example.com/*"],
      "js": ["myscript.js"],
      "run_at": "document-idle"
    }
  ]
}

    myscript.js

    console.log("이 메시지는 example.com에 접속할 때만 보임!");
document.body.style.backgroundColor = "yellow";

    ➡ 이 확장을 설치하면 example.com을 열 때마다 자동으로 배경이 노란색이 되고 콘솔 메시지가 찍혀요.
    탬퍼몽키라면 .user.js에 넣을 내용을 여기서 myscript.js로 넣는 거죠.

    5. 당신 상황에 적용하면

    • 크롬 실행 스크립트로 모든 직원이 같은 프로필을 쓰게 하는 대신,
      content script를 가진 전용 확장 을 만들어서 정책으로 강제 설치하면
      탬퍼몽키 없이도 “특정 사이트에서만 작동하는 자동화”가 가능합니다.

    • 이렇게 하면 .user.js 파일을 따로 배포하고 설치시키는 번거로움이 사라지고,
      업데이트도 한 번에 됩니다.

    원하시면 제가 기존 탬퍼몽키 스크립트를 content script로 변환 해서 드릴 수 있어요.
    혹시 지금 쓰고 있는 .user.js 코드가 준비되어 있나요? 그러면 그대로 확장 형태로 만들어 드릴게요.

    manifest.json은 어디있는데

    좋은 질문이에요.
    manifest.json은 크롬 확장 프로그램을 구성하는 설정 파일 이고,
    기본적으로 크롬 안에는 없는 파일 이에요.
    우리가 직접 새 확장 프로그램 폴더 를 만들어서 거기에 넣어야 합니다.

    1. manifest.json이 왜 필요한가?

    크롬은 “이 확장이 어떤 이름인지, 어떤 권한을 쓰는지, 어떤 스크립트를 어디에 넣을지”를
    manifest.json에서 읽어옵니다.
    즉, 확장의 설명서 역할을 하는 파일이에요.

    2. 어디서 만들고 두는가?

    1. 컴퓨터 어딘가(예: C:\chrome-extension\ 또는 ~/chrome-extension/)에 폴더 하나 를 만듭니다.

    2. 그 폴더 안에 manifest.json을 새로 만듭니다.
      (메모장, VS Code, nano, vim 등 아무 텍스트 편집기로 작성)

    3. 같은 폴더 안에 content script 파일(예: myscript.js)도 둡니다.

    폴더 구조 예시:

    pgsql

C:\chrome-extension\
 ├─ manifest.json
 ├─ myscript.js

    3. 크롬에서 로드하는 방법

    1. 크롬 주소창에 chrome://extensions/ 입력.

    2. 개발자 모드 켜기 (오른쪽 상단 토글).

    3. 압축해제된 확장 프로그램 로드 버튼 클릭.

    4. 아까 만든 C:\chrome-extension\ 폴더 선택.

    ➡ 이제 그 폴더 안의 manifest.json과 스크립트를 읽어서 확장으로 설치됩니다.

    4. 다음 단계

    • 제가 아까 예시로 보여드린 manifest.json을 그대로 저장하면,

    • myscript.js에 원하는 탬퍼몽키 코드(필요시 수정) 넣고,

    • 위 절차로 로드하면 바로 실행됩니다.

    원하시면 제가

    1. 탬퍼몽키 코드 → content script 변환본

    2. 완성된 manifest.json
      두 개를 만들어서 그대로 폴더에 넣고 로드만 하면 되게 해드릴까요?
      그러면 지금 바로 실행해볼 수 있습니다.

    그럼 내가 직접 커스텀 확장을 만들라는 말이야? 그렇게 이해하면 되는건가

    네, 맞아요.
    제가 말한 content script 방식 은 결국 “탬퍼몽키 대신 내가 직접 만든 커스텀 크롬 확장”을 만드는 걸 의미해요.

    왜 굳이 이렇게 하자고 하는지

    1. 탬퍼몽키 단점

      • 스크립트 배포 시 사용자마다 “설치” 클릭이 필요 (자동 주입 불가)

      • 업데이트나 버전 통일이 어려움

    2. 커스텀 확장 장점

      • 모든 사람에게 정책으로 강제 설치 가능 (아예 클릭 없이)

      • 업데이트 시 한 번에 전원 반영

      • “이 사이트에서만 실행”을 확장 설정으로 깔끔하게 관리 가능

    작업 과정 요약

    1. 폴더 만들기 (확장 전용)

    2. manifest.json 작성 → 확장 정보와 동작 사이트 지정

    3. 기존 탬퍼몽키 .user.js 내용을 myscript.js에 옮기기

      • @match, GM_* 같은 건 확장 API 방식으로 변환

    4. 크롬에서 chrome://extensions → “개발자 모드” → “압축해제된 확장 프로그램 로드”

    5. 잘 동작하면 이걸 사내 정책(ExtensionInstallForcelist) 으로 모든 사람에게 배포

    즉, 제안하는 건:

    “탬퍼몽키 스크립트를 그대로 쓰는 대신, 그걸 content script 형태로 포장해서 우리 회사 전용 확장으로 만드는 것”

    원하시면 제가

    • 지금 쓰고 있는 탬퍼몽키 코드 를 받아서

    • 바로 실행 가능한 커스텀 확장 패키지(폴더 구조 + manifest.json + script)로 변환해서
      테스트까지 가능한 상태로 만들어 드릴 수 있어요.

    혹시 탬퍼몽키 스크립트 원본을 보여줄 수 있나요?
    그러면 제가 확장으로 옮겨드릴게요.

    알았어. 그런데 스크립트를 어떻게 작성해야할지 모르겠어. open web ui 사이트에서 한/영 전환을 google input tools 확장으로 하고 있단 말야? 근데 채팅창에 글자를 치면 첫 글자가 ㅇㅏㄴ녕하세요 이렇게 깨져서 스페이스를 치고 “ 안녕하세요” 이렇게 해야해

    맞아요—이건 IME(한/영 입력기) 조합 중에 사이트 쪽 키 이벤트가 먼저 개입 해서 생기는 전형적인 증상이에요. 해결 포인트는 간단해요:

    “한글 조합 중(composition)일 때는 사이트의 키 핸들러가 못 끼어들게 막는다.”
    즉, isComposing(또는 keyCode === 229)인 동안 keydown/keypress/keyup/input/beforeinput 이벤트의 전파를 차단합니다.

    아래에 바로 쓸 수 있는 content script 를 드릴게요. 이걸 “커스텀 확장”의 myscript.js로 두고, manifest.json에서 해당 사이트에만 주입하면 됩니다.

    0) 뭐가 어떻게 고쳐지는가 (한줄 요약)

    • 한글 조합 중에는 사이트의 “엔터로 전송” 같은 핫키나, 값 덮어쓰기 로직이 동작하지 않도록 막습니다.

    • 그 결과 첫 글자가 ㅇㅏ처럼 깨지지 않고 정상적으로 “안녕하세요”가 바로 입력됩니다.

    1) manifest.json (예시)

    도메인만 당신 환경에 맞게 바꾸세요.
    Open WebUI를 로컬로 쓰면 http://localhost:*/* 또는 사내 도메인으로 바꾸면 됩니다.

    {
  "manifest_version": 3,
  "name": "Open WebUI IME Fix",
  "version": "1.0.0",
  "description": "한글 IME 조합 시 이벤트 충돌을 막아 첫 글자 깨짐 방지",
  "content_scripts": [
    {
      "matches": [
        "https://openwebui.example.com/*",
        "http://localhost:3000/*"
      ],
      "js": ["myscript.js"],
      "run_at": "document_start"
    }
  ]
}
    • run_at: "document_start"로 최대한 빨리 주입해, 사이트가 자체 리스너를 붙이기 전에 캡처링 단계에서 먼저 가로챕니다.

    2) myscript.js (붙여넣기 그대로 사용)

    // Open WebUI IME(한글) 깨짐 방지 패치
// 아이디어: 조합 중(isComposing / keyCode 229)에는 키/입력 이벤트 전파를 막아
// 사이트 단축키(Enter 전송 등)나 값 덮어쓰기가 끼어들지 못하게 함.

(function () {
  const DEBUG = false;

  function log(...args) {
    if (DEBUG) console.log("[IME-FIX]", ...args);
  }

  // IME 조합 중인지 판별: e.isComposing이 표준, 일부 환경은 keyCode 229를 병행
  function isIMEComposingEvent(e) {
    // 일부 브라우저/확장 조합에서 e.isComposing이 undefined일 수 있음
    return e.isComposing === true || e.keyCode === 229;
  }

  // 조합 중 이벤트는 막아버림(캡처링 단계에서)
  function stopIfComposing(e) {
    if (isIMEComposingEvent(e)) {
      // Enter가 조합 중에 눌리면 전송 방지
      if (e.type === "keydown" && e.key === "Enter") {
        e.preventDefault();
      }
      e.stopImmediatePropagation();
      e.stopPropagation();
      log("blocked during composition:", e.type, e.key);
    }
  }

  // 일부 사이트는 beforeinput/input에서 값 조작을 함 → 조합 중에는 이것도 차단
  function stopInputIfComposing(e) {
    // isComposing이 이벤트에 없을 수 있어 activeElement 상태도 참고
    // 다만 표준적으론 e.isComposing 체크가 핵심
    if (e.isComposing === true) {
      e.stopImmediatePropagation();
      e.stopPropagation();
      log("blocked input during composition:", e.type);
    }
  }

  // 문서 전체에 “먼저” 붙여 사이트 리스너보다 우선권 확보
  ["keydown", "keypress", "keyup"].forEach((t) => {
    document.addEventListener(t, stopIfComposing, true); // useCapture = true
  });

  ["beforeinput", "input"].forEach((t) => {
    document.addEventListener(t, stopInputIfComposing, true);
  });

  // 추가 안전장치: 채팅 입력 필드에 직접 패치(중복 부착 방지)
  function patchEditable(el) {
    if (!el || el.dataset.imePatched === "1") return;
    el.dataset.imePatched = "1";
    ["keydown", "keypress", "keyup"].forEach((t) => {
      el.addEventListener(t, stopIfComposing, true);
    });
    ["beforeinput", "input"].forEach((t) => {
      el.addEventListener(t, stopInputIfComposing, true);
    });
    log("patched:", el);
  }

  // Open WebUI는 textarea나 contenteditable을 쓸 수 있으니 둘 다 케어
  function scanAndPatch() {
    const candidates = [
      ...document.querySelectorAll('textarea, input[type="text"], [contenteditable="true"]')
    ];
    candidates.forEach(patchEditable);
  }

  // 초기 스캔
  scanAndPatch();

  // 동적 생성 대응
  const mo = new MutationObserver(() => scanAndPatch());
  mo.observe(document.documentElement, { childList: true, subtree: true });

  log("IME fix initialized");
})();

    왜 이렇게 하는가?

    • 문제 원인 : 사이트가 keydown/input에서 값 조작·전송을 먼저 해버려서, IME가 조합을 끝내기 전에 문자열이 쪼개지거나 깨집니다.

    • 해결 : 조합 중엔(IME가 입력을 “완성”하기 전) 사이트 쪽 리스너가 돌아가지 못하게 캡처 단계에서 막습니다. 조합이 끝나면(compositionend) 브라우저가 완성된 글자 를 정상 전달합니다.

    3) 적용 순서 (진짜 쉬운 버전)

    1. 위 manifest.json/myscript.js 두 파일을 폴더에 넣기

    2. 크롬 주소창 → chrome://extensions/

    3. 오른쪽 상단 개발자 모드 켜기 → 압축해제된 확장 프로그램 로드 → 폴더 선택

    4. Open WebUI 페이지 새로고침 후, 채팅창에 그냥 “안녕하세요” 쳐보기

      • 처음 글자가 ㅇㅏ로 깨지지 않고 한 번에 “안”이 나와야 정상

    4) 자주 묻는 질문 (빠른 체크)

    • Enter가 조합 중에 눌리면 메시지 전송되던데?
      위 스크립트는 조합 중 Enter에 preventDefault()를 걸어서 전송을 막습니다.

    • 사이트 단축키(예: Ctrl+K)는 괜찮을까?
      조합 중일 때만 막습니다. 조합이 끝난 이후엔 단축키 정상 동작.

    • Google Input Tools 말고 다른 IME(윈도우 한글, macOS 한글)도 되나?
      네. 핵심은 isComposing/229 체크라서 IME 종류와 무관 하게 동작합니다.

    • 특정 도메인만 패치하고 싶어
      manifest.json의 matches 배열에서 원하는 도메인만 남기세요.

    필요하면 이걸 탬퍼몽키용 으로도 만들어 드릴 수 있지만, 조직 전체 배포/통일이 목표라면 지금처럼 커스텀 확장 으로 가는 게 훨씬 깔끔합니다.

    원하시면 당신 환경의 정확한 도메인 을 알려주면, manifest.json을 그에 맞춰 딱 맞게 수정해 드릴게요.
