    2026-06-21

    hrag(hyperrag) 사용법 — Git처럼 쓰는 로컬 문서 검색(RAG) CLI

    hrag(hyperrag)는 Git처럼 동작하는 로컬 RAG(검색 증강) CLI입니다. 워크스페이스마다 .hrag/ 아래에 인덱스를 저장하고, 커밋한 모든 문서의 정규화된 Markdown 스냅샷을 보관하며, 검색 결과로는 "내용"이 아니라 원본/Markdown 위치(locator) 를 돌려줍니다. 그래서 에이전트(LLM)는 검색 → read로 실제 내용을 확인 → 답변, 이라는 깔끔한 흐름을 가집니다.

    핵심 철학은 명시성입니다. 자동 색인이 없습니다. add로 명시적으로 올린 파일만 commit 시점에 변환·청킹·임베딩·색인됩니다.

    1. 설치

    # 기본 설치 (검색/색인 코어)
pip install -e .

# PDF / DOCX 변환 + PDF 시각 자산까지 쓰려면
pip install -e '.[convert]'
    • PDF Markdown 추출: PyMuPDF4LLM
    • DOCX 변환: MarkItDown
    • Python 3.11+ 필요

    2. 환경 변수와 설정

    임베딩/리랭커 엔드포인트는 .hrag/config.toml에서 읽고, $VAR 또는 ${VAR} 형태의 문자열은 환경 변수로 치환됩니다.

    export HYPERRAG_EMBEDDING_ENDPOINT="https://your-embedding-endpoint/v1/embeddings"
export HYPERRAG_RERANKER_ENDPOINT="https://your-reranker-endpoint/v1/rerank"
export HYPERRAG_API_KEY="sk-..."   # 인증이 필요 없는 엔드포인트면 생략 가능

    hrag init이 생성하는 기본 config.toml:

    version = 1

[embedding]
endpoint = "$HYPERRAG_EMBEDDING_ENDPOINT"
api_key = "$HYPERRAG_API_KEY"
model = "BAAI/bge-m3"
dim = 1024
batch_size = 64

[reranker]
endpoint = "$HYPERRAG_RERANKER_ENDPOINT"
api_key = "$HYPERRAG_API_KEY"
model = "BAAI/bge-reranker-v2-m3"

[chunking]
max_tokens = 800
overlap_tokens = 120

[search]
bm25_top_k = 80
vector_top_k = 80
rerank_top_k = 50
return_top_k = 10
exclude_stale = false

[visual]
enabled = true
page_renders = "lazy"      # off | lazy | eager
page_render_dpi = 150
page_render_format = "png"
extract_images = true      # PDF 내부 이미지 추출
image_min_pixels = 0       # width*height 가 이 값 미만이면 건너뜀 (0=전부)

    규칙: "$NAME" / "${NAME}" 처럼 정확히 환경 변수 한 개만 치환됩니다. "https://$HOST/v1" 같은 부분 보간은 지원하지 않습니다. 엔드포인트가 비어 있으면 해당 명령에서 곧바로 실패합니다.

    3. 5분 워크플로우

    hrag init                          # .hrag/ 와 SQLite 인덱스 생성
hrag add README.md docs/           # 색인할 파일/디렉터리를 "스테이징"만 함
hrag status                        # 스테이징/변경/삭제 상태 확인
hrag commit -m "add docs"          # 변환→청킹→임베딩→색인 (여기서 실제 작업)
hrag ls                            # 색인된 문서 목록 + 라이브 상태
hrag search "rate limit policy"    # 검색 (locator 반환)
hrag read doc_xxx --chunk 3        # 검색이 가리킨 청크 주변을 실제로 읽기

    색인은 워크스페이스 루트(.hrag/가 있는 디렉터리)를 자동으로 찾아 동작합니다. 하위 디렉터리에서 명령을 실행해도 상위의 워크스페이스를 사용합니다.

    4. 상태 모델 (Git처럼)

    상태 의미
    untracked 파일은 있지만 한 번도 스테이징/색인되지 않음
    staged hrag add로 스테이징 테이블에 기록됨
    indexed hrag commit으로 변환/청킹/임베딩/색인 완료
    modified 색인 당시 해시와 현재 파일 해시가 다름
    deleted 색인된 원본 경로가 더 이상 존재하지 않음
    stale modified 또는 deleted

    기본적으로 검색은 stale 문서도 포함하고 결과에 stale=true로 표시합니다. 제외하려면 [search] exclude_stale = true.

    5. 명령어 레퍼런스

    hrag init [path] [--force]

    .hrag/와 인덱스 DB를 생성합니다. path를 생략하면 현재 디렉터리. 이미 있으면 그대로 두며, --force로 config.toml을 덮어씁니다.

    hrag add <path>... [--include-code] [--all-supported] [--force-secret]

    파일/디렉터리를 스테이징만 합니다(변환·색인하지 않음).

    • 기본 대상: .md .mdx .txt .rst .pdf .docx 및 README*, CHANGELOG* 등
    • --include-code: 디렉터리 추가 시 소스/설정 확장자(.py .ts .go .json 등)도 포함
    • --all-supported: 지원하는 문서/코드 타입 전부 스테이징
    • --force-secret: .env, *.pem 같은 비밀 파일도 강제 포함(위험)

    hrag status [--json]

    스테이징된 파일, modified/deleted 문서, 색인된 문서·청크 수를 보여줍니다.

    hrag ls [--json]

    색인된 문서 목록을 라이브 상태(indexed/modified/deleted)와 함께 표로 출력합니다.

    hrag commit [-m MESSAGE]

    스테이징된 파일을 정규 Markdown으로 변환하고 청킹·임베딩한 뒤 SQLite 인덱스를 갱신합니다. 실제 변환·임베딩이 일어나는 유일한 지점입니다.

    hrag search <query> [--json] [--include-assets] [-W <root> ...]

    커밋된 청크를 검색합니다. (검색 파이프라인은 §7 참고)

    • --json: 안정적인 기계 판독용 출력(에이전트 계약)
    • --include-assets: 결과 청크에 연결된 시각 자산(페이지 렌더/추출 이미지) locator 포함
    • --workspace/-W: 다른 워크스페이스 루트를 추가로 검색(반복 가능, 멀티 워크스페이스)

    hrag read <doc_id> --chunk <n> [--around <n>] [--with-assets]

    검색이 가리킨 청크 주변의 Markdown 발췌를 읽습니다.

    • --around: 앞뒤 몇 개의 청크까지 포함할지(기본 2)
    • --with-assets: 연결된 시각 자산을 materialize(필요 시 렌더)하여 경로와 함께 반환

    hrag cat <doc_id>

    해당 문서의 정규 Markdown 스냅샷 전체를 출력합니다.

    hrag path <doc_id> [--json]

    원본 경로와 정규 Markdown 경로(상대/절대)를 보여줍니다.

    hrag asset <asset_id> [--json] [--materialize/--no-materialize]

    시각 자산의 경로를 보여줍니다. 기본적으로 lazy 페이지 렌더는 즉시 렌더합니다. --no-materialize면 메타데이터만 조회합니다.

    hrag log

    최근 커밋 기록(문서/청크 수, 메시지)을 보여줍니다.

    6. PDF와 시각 자산

    PDF는 두 종류의 시각 자산을 다룹니다.

    (1) 페이지 렌더(page render) — PDF의 각 페이지를 통째로 PNG로 렌더합니다.

    • [visual] page_renders 모드: lazy(기본, 요청 시 렌더) / eager(커밋 때 전부 렌더) / off
    • page_render_dpi로 해상도 조절
    • asset id 예: page:doc_xxx:p000012:render:150dpi:png

    (2) 임베디드 이미지 추출 — PDF 내부에 박혀 있는 그림/도표를 꺼냅니다.

    • hrag commit 시 PDF 객체(xref) 단위로 중복 제거하여 .hrag/assets/by-doc/<doc_id>/images/에 저장
    • 정규 Markdown 스냅샷에는 상대 경로 이미지 링크로 삽입됩니다: ![embedded image x7 (60x40)](../../../assets/by-doc/doc_xxx/images/x000007.png)
    • 임베딩/검색용 텍스트에서는 이미지 마크업을 제거하므로 검색 품질에 영향이 없고, 스냅샷에는 그대로 남아 cat/read로 노출되어 LLM이 경로로 열어볼 수 있습니다.
    • [visual] extract_images = false로 끄거나, image_min_pixels로 작은 아이콘을 거를 수 있습니다.

    사용 예:

    hrag search "revenue chart" --include-assets --json
hrag read doc_xxx --chunk 3 --with-assets
hrag asset page:doc_xxx:p000012:render:150dpi:png --json
hrag asset image:doc_xxx:x000007:png --json

    참고: 벡터로 그려진(임베디드 래스터가 아닌) 도표는 이미지 추출 대상이 아니며, 페이지 렌더로 커버됩니다. 비전 캡션 생성은 하지 않으므로 이미지 "내용"으로 직접 검색되지는 않고, 검색된 청크에 자산 경로가 따라옵니다.

    7. 검색 파이프라인

    1. 커밋된 청크에 대해 FTS5/BM25 키워드 검색
    2. 쿼리를 OpenAI 호환 임베딩 엔드포인트로 임베딩
    3. 청크 임베딩과 코사인 유사도(인프로세스 브루트포스)
    4. BM25 + 벡터 후보를 RRF(상호 순위 융합) 로 병합
    5. 상위 rerank_top_k개를 Cohere 스타일 리랭커로 재정렬
    6. 상위 return_top_k개 반환 (stale 문서 기본 포함)

    리랭커 호출이 실패하면 융합 점수 기반으로 폴백합니다(reranker_fallback=true).

    8. 멀티 워크스페이스 검색

    여러 워크스페이스를 한 번에 검색할 수 있습니다.

    hrag search "deployment" -W ~/proj/a -W ~/proj/b --json

    이때 각 결과의 read_command에는 해당 워크스페이스로 이동하는 cd가 포함되어 바로 복사·실행할 수 있습니다.

    9. 에이전트(LLM) 연동

    hrag search --json은 안정적인 기계 판독 계약입니다. 결과는 내용이 아니라 locator이므로, 에이전트는 반드시 read/cat 또는 반환된 Markdown 경로+라인 범위로 실제 내용을 확인한 뒤 답해야 합니다.

    검색 JSON 결과(요약):

    {
  "doc_id": "doc_xxx",
  "chunk_id": 3,
  "title": "API Policy",
  "snippet": "...",
  "source_path": "docs/api.pdf",
  "source_page": 12,
  "source_locator": "docs/api.pdf:page 12",
  "markdown_locator": ".hrag/markdown/xx/yy/doc_xxx__api.md:120-167",
  "read_target": { "kind": "markdown", "path": "...", "start_line": 120, "end_line": 167 },
  "related_assets": [],
  "stale": false,
  "read_command": "hrag read doc_xxx --chunk 3 --around 2",
  "cat_command": "hrag cat doc_xxx",
  "path_command": "hrag path doc_xxx --json"
}

    에이전트 정책

    • 호출해도 되는 명령: hrag search, hrag read, hrag cat, hrag path
    • 사람이 명시적으로 요청할 때만: hrag add, hrag commit, hrag init, hrag reset

    10. 저장 구조 (고정)

    workspace-root/
  .hrag/
    config.toml          # 설정 ( 프로젝트 루트가 아니라 .hrag 안에 위치 )
    index.sqlite         # 인덱스 DB
    markdown/            # 정규 Markdown 스냅샷 (doc_id 기준)
    assets/              # 페이지 렌더 / 추출 이미지
    cache/  tmp/  logs/
    • Markdown 스냅샷 경로: .hrag/markdown/<doc-id-prefix>/<...>/doc_<hash>__<slug>.md
    • doc_id = "doc_" + base32(sha256("file://" + 절대경로))[0:20] → 같은 파일은 수정해도 같은 doc_id, 이름을 바꾸면 새 doc_id.
    • 저장 레이아웃은 사용자 설정 대상이 아닙니다(고정).

    요약

    hrag는 "검색은 위치만, 내용은 read로"라는 원칙과 Git식 명시적 워크플로우 (add → commit → search → read)를 결합한 로컬 RAG CLI입니다. PDF의 페이지 렌더와 내부 이미지 추출까지 지원해, 문서의 텍스트뿐 아니라 시각 자료까지 에이전트가 경로로 접근할 수 있습니다.
